    命令注册与 路由（深潜审计版）

    核心论点

    03 的核心是：slash 不是一套独立系统，而是 command registry 的一个消费者投影。

    具体体现为：

    1. 所有命令源先在 getCommands 并轨成统一 Command[]；
    2. availability/enabled/remote-safe/bridge-safe 都在执行前过滤；
    3. slash 入口只做解析与分发，不重建命令事实；
    4. unknown/malformed/path-like 输入走恢复路径，避免把普通输入误判为命令错误。

    运行时状态所有权

    状态类别 所有者 关键函数 职责
    多来源命令合流态 commands.ts getSkills, loadAllCommands skills/plugin/workflow/builtin 聚合
    运行期命令可见态 commands.ts getCommands availability + isEnabled + dynamic skills 过滤
    consumer 投影态 commands.ts getSkillToolCommands, getSlashCommandToolSkills model 与 slash 不同命令面
    远端安全投影态 commands.ts filterCommandsForRemoteMode, isBridgeSafeCommand remote/bridge 场景前置限制
    slash 语法解析态 slashCommandParsing.ts parseSlashCommand /name args 与 MCP 标记解析
    输入入口分发态 processUserInput.ts processUserInputBase skipSlash/bridge override/attachment/slash gate
    slash 执行分支态 processSlashCommand.tsx processSlashCommand, getMessagesForSlashCommand unknown 恢复、type 分派、fork/background

    守卫与决策矩阵

    Guard 条件 动作 结果
    source merge guard 多来源命令并存 getSkills + loadAllCommands 合流 单一命令事实源
    availability guard cmd.availability 不满足 meetsAvailabilityRequirement 过滤 订阅/提供方约束前置
    enabled guard isCommandEnabled=false getCommands 过滤 禁用命令不暴露
    dynamic skill dedupe guard dynamic 与 base 重名 名称去重后注入 防重复命令
    mcp skill filter guard SkillTool 需要 MCP 技能 getMcpSkillCommands 类型+来源+模型可调用过滤 防杂项 MCP 命令混入
    remote mode guard remote 初始化 filterCommandsForRemoteMode 远端仅保留安全本地命令
    bridge safe guard bridge 输入 slash isBridgeSafeCommand 判定 local-jsx 默认阻断

    Guard 条件 动作 结果
    parse guard 非 /... 或空命令 parseSlashCommand -> null 进入普通 prompt 流
    malformed guard slash 结构无效 返回格式提示 用户可恢复
    unknown guard hasCommand miss looksLike + path probe unknown 命令与普通输入分离
    path-like guard 实际文件路径 不报 unknown，降级普通输入 降低误伤
    userInvocable guard userInvocable=false 直接拒绝用户 slash 调用 模型入口与用户入口分层
    type dispatch guard local/local-jsx/prompt switch 分发 执行语义稳定
    fork context guard prompt + context='fork' executeForkedSlashCommand 子代理隔离执行

    失败、恢复与降级

    命令源加载失败局部化

    getSkills 对 skillDir/pluginSkills 各自 catch 并回空数组，保证核心命令系统可继续运行。

    投影失败局部化

    getSlashCommandToolSkills catch 后返回 []，避免技能索引失败拖垮命令主链。

    不安全 显式反馈

    bridge 输入下，命令已知但不安全时直接返回 /<cmd> isn't available over Remote Control.，而不是把原始 slash 文本送给模型。

    的可恢复降级

    unknown 且看起来不像命令（或是路径）时，回到普通 prompt 流；看起来像命令时给出明确 unknown skill 提示并保留参数语义。

    -异常防死锁

    getMessagesForSlashCommand 的 local-jsx 分支在 load/call 抛错且未 onDone 时会 resolve 空消息并清理 UI 状态，避免 Promise 悬挂卡死队列。

    不变量

    1. getCommands 是 slash 与 SkillTool 的共同命令事实源。
    2. meetsAvailabilityRequirement 与 isCommandEnabled 必须在执行前过滤。
    3. bridge 输入默认 skipSlashCommands，仅白名单命令可例外放行。
    4. userInvocable=false 的命令必须拒绝直接 slash 调用。
    5. command.type + context 必须唯一决定执行分支（local/local-jsx/prompt/fork）。
    6. unknown/malformed/path-like 输入必须保留用户恢复路径。

    跨模块契约

    • 对 02：02 保证启动完成与上下文就绪，03 在其上做命令解析和路由。
    • 对 04：03 输出的是执行意图与消息序列，不负责最终呈现协议。
    • 对 08：03 与 SkillTool 共享 commands.ts 事实源，禁止“双注册表”分叉。
    • 对 05：03 只负责 bridge-origin slash 入口 gating，不管理 bridge 会话生命周期。

    工程约束与演进指引

    扩展命令系统或 slash 路由时，优先检查：

    1. 新来源是否通过 loadAllCommands/getCommands 接入，而非旁路；
    2. 新命令是否定义 availability/enabled/bridge-safe/remote-safe 语义；
    3. 是否破坏 skipSlashCommands + bridgeOrigin 的防护顺序；
    4. 是否引入“已知但不可执行”时的静默失败；
    5. findCommand 对 name/alias/getCommandName 的等价性是否保持。

    建议回归：

    • source merge + dynamic dedupe；
    • availability/enabled 过滤；
    • remote/bridge 安全过滤；
    • malformed/unknown/path-like 三类 slash 输入；
    • userInvocable=false 与 fork context 分支。
