    持久助手运行链（深潜审计版）

    核心论点

    KAIROS 的核心不是“后台常驻”本身，而是把一次性会话升级为可持续、可调度、可收敛的助手运行面：

    1. 激活必须经过 gate；
    2. 状态必须全局可见；
    3. 后台任务必须可中断、可追踪、可恢复；
    4. Dream/Proactive 不能破坏主会话语义。

    运行时状态所有权

    状态类别 所有者 关键函数 职责
    KAIROS 激活态 main.tsx + bootstrap/state.ts setKairosActive / getKairosActive feature+配置通过后激活 assistant 模式
    Dream 调度态 autoDream.ts initAutoDream / executeAutoDream 自动触发整合任务与执行治理
    Dream 锁态 consolidationLock.ts tryAcquireConsolidationLock 防并发重复整合
    Dream 任务态 DreamTask.ts registerDreamTask / completeDreamTask 任务生命周期与 UI 可见状态
    cron 持久任务态 cronScheduler.ts + cronTasks.ts createCronScheduler / addCronTask durable/permanent 任务调度
    proactive tick 态 proactive/index.ts （模块状态机） 无用户输入时主动推进与 sleep 节流

    端到端流程

    1. main.tsx 在 assistant 条件满足时设置 setKairosActive(true)；
    2. bootstrap/state.ts 将该状态暴露给工具/UI/分析链；
    3. initAutoDream 周期检查时间门槛 + 会话门槛 + 锁门槛；
    4. 命中后注册 DreamTask，执行整合 prompt，写回 memory 目录；
    5. cronScheduler 负责 durable/permanent 任务触发与 jitter；
    6. proactive 在无输入时通过 tick + Sleep 维持低干扰运行。

    守卫与决策矩阵

    Guard 条件 行为 结果
    activation gate feature / settings / trust / remote gate 未满足 不激活 KAIROS 回落普通会话模式
    dream time gate 未到最小间隔 跳过 dream 降低无效整合
    dream session gate 新会话数不足 跳过 dream 降低噪音
    lock gate 存在活跃锁 不重复执行 防并发冲突
    task lifecycle guard Dream 执行中断/失败 fail task + rollback lock 保持状态收敛
    cron jitter guard 高频整点任务 加抖动后触发 防群体同刻触发
    proactive block guard context blocked / paused 暂停 tick 防死循环骚扰

    失败、恢复与降级

    激活失败

    assistant gate 不满足时直接降级为普通模式，不进入半激活状态。

    执行失败

    executeAutoDream 失败后通过 failDreamTask 标记失败，并配合 lock 回滚，避免锁泄漏。

    多实例竞争

    tryAcquireConsolidationLock + PID/mtime 检测避免并发重复整合；异常时下次周期重试。

    调度异常

    cron 任务读取/写入失败时保留主会话可用性，调度器后续 tick 再尝试恢复。

    不变量

    1. KAIROS 激活必须由显式 gate 决定。
    2. kairosActive 必须由全局状态读写，不得局部影子化。
    3. Dream 同时刻最多一个整合执行体。
    4. Dream 任务必须有终态（completed/failed/aborted）。
    5. durable/permanent 调度任务必须可追踪且可删除。
    6. proactive 不能无限自激活导致事件风暴。

    跨模块契约

    • 对 01：KAIROS 不能改变 tool-use/result 对偶语义。
    • 对 02：Dream 消费 memory 体系，但不替代 memory gate。
    • 对 07：后台状态可被投影，不应改变 stream 协议语义。
    • 对 09：assistant/CLI 只是入口，持久运行由本模块状态机负责。

    工程约束与演进指引

    扩展 KAIROS 时优先检查：

    1. 新触发器是否有明确门槛与可观测字段；
    2. 是否会打破锁语义与任务终态收敛；
    3. 是否会在 headless/interactive 下产生不同安全行为；
    4. 是否需要追加 jitter、防抖、节流策略。

    建议回归：

    • KAIROS on/off gate；
    • Dream 时间门槛 + 会话门槛 + 锁门槛；
    • kill/retry/failed task 路径；
    • cron durable 与 permanent 任务；
    • proactive blocked/paused 恢复。
