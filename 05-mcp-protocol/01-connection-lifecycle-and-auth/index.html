    协议集成层：连接生命周期与鉴权（深潜审计版）

    核心论点

    连接层的价值不在“是否连上”，而在把多 transport 与 auth 波动压成可判别状态机：

    1. 连接失败局部化，不拖垮全局；
    2. 会话过期可清缓存并重建；
    3. SDK 与非 SDK 连接路径语义分离；
    4. pending server 通过审批 gate 后再进入 runtime。

    运行时状态所有权

    状态类别 所有者 关键函数 说明
    建连态 client.ts connectToServer transport 分支建连与初始回调绑定
    连接可用态 client.ts ensureConnectedClient 调用前最后连接守卫
    缓存失效态 client.ts clearServerCache / onclose 回调 连接与发现缓存级联清理
    配置差异态 client.ts areMcpConfigsEqual 判定是否需重建连接
    显式重连态 client.ts reconnectMcpServerImpl 管理面触发的重连入口
    SDK 同步态 client.ts + print.ts setupSdkMcpClients / updateSdkMcp SDK client 集合更新
    审批前置态 mcpServerApproval.tsx handleMcpjsonServerApprovals pending servers 的启用门

    端到端流程

    1. 聚合 server 配置后调用 connectToServer 建立连接；
    2. 连接对象挂载 onclose/onerror 处理，维护缓存一致性；
    3. 下游调用前通过 ensureConnectedClient 校验可用态；
    4. 配置变化或 session-expired 时走 clearServerCache/reconnectMcpServerImpl；
    5. SDK 场景用 setupSdkMcpClients 与 updateSdkMcp 更新 client 集合；
    6. project 级 pending server 需经 handleMcpjsonServerApprovals 才进入连接候选。

    守卫与决策矩阵

    Guard 条件 动作 结果
    transport guard serverRef.type 分支 选用对应 transport+auth 多协议统一接入
    sdk guard client.config.type='sdk' ensureConnectedClient 直接复用 避免错误重连路径
    disconnected guard 非 connected 抛连接错误/触发重建 防悬空调用
    close/error guard transport onclose/onerror 清连接+发现缓存 防僵尸缓存
    config-change guard config 不等价 重建连接 防旧配置幻读
    approval gate pending project servers 阻塞启用直至审批 防未授权 server
    reconnect guard 手动重连请求 走 reconnectMcpServerImpl 显式恢复路径

    失败、恢复与降级

    建连失败

    • 单 server 标记失败；
    • 其它 server 继续可用（partial availability）。

    认证失败

    • unauthorized 分支进入 needs-auth/失败语义；
    • 后续经授权与重连恢复。

    • 调用路径检测到过期后清缓存；
    • 下次 ensureConnectedClient 触发重建并恢复。

    变更

    • new/removed/failed/pending 检测后 updateSdkMcp 重建 SDK client 集合；
    • 防长期持有失效 client。

    不变量

    1. 非 connected 客户端不得进入发现/调用链。
    2. 连接失效必须联动清理发现缓存。
    3. SDK 与非 SDK 必须走可解释的不同连接语义。
    4. 配置变化应触发连接重建而非复用旧实例。
    5. pending project server 必须审批后启用。
    6. 连接错误必须局部化，不得全局 fail-stop。

    跨模块契约

    • 对 02：01 只保证“可用连接”，02 负责 capability 发现语义。
    • 对 03：01 提供稳定连接守卫，03 承担调用与协商策略。
    • 对 04：CLI/UI 的 add/remove/reconnect 必须回流到 01 的连接状态机。
    • 对主链：01 输出可判别连接态，不输出 transport 细节噪声。
