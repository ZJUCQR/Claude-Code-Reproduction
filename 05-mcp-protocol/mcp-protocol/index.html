    MCP 协议集成层：连接、发现、调用与管理面收敛（深潜审计版）

    1) Scope 与 Evidence Boundary

    本页覆盖 05 模块“MCP 协议收敛层”的全链行为：连接生命周期、能力发现、工具调用与 elicitation 重试、结果规范化与大输出治理、CLI/UI 管理面与审批协同。

    证据范围：

    • src/services/mcp/client.ts
    • src/utils/mcpValidation.ts
    • src/utils/mcpOutputStorage.ts
    • src/services/mcp/mcpStringUtils.ts
    • src/services/mcpServerApproval.tsx
    • src/cli/print.ts
    • src/cli/handlers/mcp.tsx

    不覆盖：

    • query-loop 主状态机本体（仅引用其消费契约）；
    • 通用权限策略引擎本体（仅引用 MCP 接入点）；
    • 非 MCP tool 执行协议。

    2) Core Thesis

    05 模块要解决的不是“把 server 连上”，而是把不稳定外部协议压成主链可承受的稳定语义：

    1. transport/auth 波动被收敛到可判别连接状态；
    2. discovery 失败被局部化为部分可用，而非全局崩溃；
    3. tool call 的异步协商（elicitation）有拒绝路径与重试上界；
    4. 异构返回先规范化再入模；
    5. 管理面（CLI/UI/approval）与 runtime 协议一致。

    3) Runtime State Ownership

    状态类别 所有者 关键函数/字段 说明
    连接态 client.ts connectToServer / ensureConnectedClient / clearServerCache 连接建立、缓存失效与重连入口
    发现缓存态 client.ts fetchToolsForClient / fetchResourcesForClient / fetchCommandsForClient tools/resources/commands 的 LRU 视图
    调用协商态 client.ts callMCPTool / callMCPToolWithUrlElicitationRetry 调用执行、URL 协商、有限重试
    结果收敛态 client.ts + mcpValidation.ts + mcpOutputStorage.ts transformMCPResult / processMCPResult / truncation/persist 结果归一与超大输出治理
    名称/权限映射态 mcpStringUtils.ts + client.ts buildMcpToolName / getToolNameForPermissionCheck / mcpToolInputToAutoClassifierInput 命名空间隔离与权限输入编码
    管理面协同态 mcpServerApproval.tsx + print.ts + handlers/mcp.tsx 审批、刷新、增删改查 配置管理与 runtime 一致

    4) End-to-end Flow

    1. getMcpToolsCommandsAndResources 聚合配置并建立/复用连接；
    2. fetchToolsForClient / fetchResourcesForClient / fetchCommandsForClient 拉取能力并映射内部对象；
    3. tool 调用经 ensureConnectedClient + callMCPToolWithUrlElicitationRetry 执行；
    4. 返回值经 transformMCPResult + processMCPResult 收敛为模型可消费内容；
    5. 管理面通过审批、刷新、CLI 命令维护 server 生命周期；
    6. 连接失效触发缓存联动清理，后续请求自动走重连路径。
    // src/services/mcp/client.ts
export async function ensureConnectedClient(client: MCPServerConnection): Promise<ConnectedMcpServerConnection> {
  if (client.config.type === 'sdk') {
    return client as ConnectedMcpServerConnection
  }
  const connectedClient = await connectToServer(client.name, client.config)
  if (connectedClient.type !== 'connected') {
    throw new Error(`MCP Server '${client.name}' disconnected`)
  }
  return connectedClient
}

    5) Guard / Decision Matrix

    Guard 条件 动作 结果
    transport branch guard server type 分支（sse/http/stdio/proxy/ws/...） 选择对应 transport+auth 路径 连接行为可解释
    connected capability guard client.type !== connected 或缺 capability 返回空集合/拒绝调用 局部退化
    cache invalidation guard onclose/onerror/session-expired 清连接+发现缓存 防僵尸能力
    elicitation trigger guard McpError code UrlElicitationRequired 进入协商/重试 协议级交互闭环
    retry bound guard attempt >= MAX_URL_ELICITATION_RETRIES 停止重试并失败 防无限循环
    user-decline guard accept 之外动作（decline/cancel） 返回解释性结果 保留用户否决权
    large-output guard content 超阈值 truncate 或 persist 指引 防上下文爆炸
    approval guard project pending servers 审批流程（单个/多选） 防未授权接入

    6) Failure / Recovery / Degradation

    6.1 连接失败恢复

    • 单 server 失败标记为 failed/needs-auth；
    • 其它 server 继续提供能力（partial availability）。

    6.2 会话过期恢复

    • callMCPTool 检测 session-expired 分支后清缓存并抛特定错误；
    • 上层 wrapper 使用 ensureConnectedClient 触发重连后重试一次。

    6.3 Discovery 退化

    • tools/resources/commands 任一路径失败均降级为 []；
    • 不阻断其余 server 与其余 capability。

    6.4 Elicitation 恢复链

    • hook 可提前 accept/decline/cancel；
    • 无 hook 时走 structuredIO 或 queue；
    • accept 才重试调用，decline/cancel 返回可解释结果。

    6.5 大输出退化链

    • 超阈值先判断截断或落盘策略；
    • 二进制内容持久化后返回引用说明，避免把 raw binary 推给模型。

    7) Invariants

    1. 非 connected client 不得进入发现/调用主路径。
    2. 连接缓存与发现缓存失效必须联动。
    3. UrlElicitationRequired 必须有用户拒绝分支与重试上界。
    4. MCP 原始返回必须先规范化再进入主链。
    5. tool 命名空间需稳定隔离（mcp__...），避免跨 server 冲突。
    6. 大输出治理必须默认保护上下文预算。
    7. pending project servers 必须经审批才能进入可用集合。

    8) Cross-module Contracts

    • 对 query/tool 主链：05 输出标准化 tool result，不输出 MCP 私有异常形态。
    • 对 hooks：elicitation hooks 可参与决策，但不得破坏重试边界与终态收敛。
    • 对 CLI/UI：管理面改动必须回流 runtime 配置事实源。
    • 对安全策略：权限提示和工具元信息只提供信号，不替代策略层裁决。

    9) Engineering Constraints / Evolution Guidance

    扩展 MCP 能力时必须验证：

    1. 新 transport 是否接入统一连接状态与缓存清理；
    2. discovery 新对象是否遵循 capability gate + fail-open 降级；
    3. 新 elicitation 类型是否具备 decline/cancel 与重试上界；
    4. 新结果类型是否先规范化再上送；
    5. 管理面改动是否与审批/刷新流程一致。

    建议回归：

    • transport/auth 分支（sse/http/stdio/proxy/ws）；
    • session-expired 后自动恢复；
    • discovery 局部失败下部分可用；
    • elicitation accept/decline/cancel 全分支；
    • 大输出 truncate/persist 双路径；
    • pending 审批单个/多个分支。
