    Prompt 与压缩：Microcompact 与 SessionMemory Compact（深潜审计版）

    1) Scope 与 Evidence Boundary

    本页覆盖“如何压缩”中的轻量路径与 SM fallback，证据范围：

    • src/services/compact/microCompact.ts
    • src/services/compact/sessionMemoryCompact.ts
    • src/services/compact/timeBasedMCConfig.ts
    • src/services/compact/compactWarningState.ts
    • src/services/SessionMemory/sessionMemoryUtils.ts

    不覆盖：

    • auto-compact 触发决策（见 02）；
    • full compact 与 cleanup（见 04）。

    2) Core Thesis

    03 页解决的是“在不立即 full compact 的前提下，先做低侵入降压”：

    1. time-based microcompact：冷缓存场景直接清旧 tool_result content；
    2. cached microcompact：热缓存场景走 cache_edits，尽量不改本地消息；
    3. session-memory compact：利用 session memory 快速重建 summary 并保留后段消息；
    4. 三路径都以 API 不变量为底线。

    3) Runtime State Ownership

    状态类别 所有者 关键字段/函数 说明
    microcompact 入口态 microCompact.ts microcompactMessages time-based 与 cached path 分流
    time-based 配置态 timeBasedMCConfig.ts getTimeBasedMCConfig enabled/gapThreshold/keepRecent
    cachedMC 执行态 microCompact.ts pendingCacheEdits + cachedMC module state 追踪可删 tool_result
    warning 抑制态 compactWarningState.ts suppress/clearCompactWarning 避免压后误报
    SM compact 配置态 sessionMemoryCompact.ts smCompactConfig min/max token 与 min text 消息数
    SM compact 游标态 sessionMemoryUtils.ts lastSummarizedMessageId 决定保留区间起点

    4) End-to-end Flow

    4.1 microcompact 主入口

    // src/services/compact/microCompact.ts
export async function microcompactMessages(messages, toolUseContext?, querySource?) {
  clearCompactWarningSuppression()

  const timeBasedResult = maybeTimeBasedMicrocompact(messages, querySource)
  if (timeBasedResult) return timeBasedResult

  if (feature('CACHED_MICROCOMPACT')) {
    if (mod.isCachedMicrocompactEnabled() && mod.isModelSupportedForCacheEditing(model) && isMainThreadSource(querySource)) {
      return await cachedMicrocompactPath(messages, querySource)
    }
  }

  return { messages }
}

    4.2 time-based trigger

    evaluateTimeBasedTrigger 要求：

    • config enabled；
    • querySource 显式且 main-thread；
    • last assistant 存在且 gap 超阈值。

    命中后仅清除旧 tool_result content，至少保留最近 1 个，避免“全清空”。

    4.3 session-memory compact

    trySessionMemoryCompaction 流程：

    1. gate 检查 + 配置初始化；
    2. 等待 in-progress session memory extraction；
    3. 读取 session memory（空/模板态则返回 null）；
    4. 计算 messagesToKeep 起点并做 API 不变量修正；
    5. 构造 compaction result；
    6. 若 post-compact token 仍超阈值则返回 null（让上层 fallback legacy）。

    5) Guard / Decision Matrix

    Guard 条件 动作 结果
    time-based 总开关 config.enabled=false 不触发 time-based 继续后续路径
    main-thread 限制 !querySource || !isMainThreadSource 不触发 time-based 避免分析/子流程误触发
    gap 未达阈值 gap < gapThreshold 不触发 time-based 保持原消息
    cachedMC 可用 gate+model+main-thread 走 cachedMicrocompactPath 生成 cache edits
    cachedMC 不可用 任一条件不满足 no-op 交由 autocompact
    SM compact gate shouldUseSessionMemoryCompaction=false 返回 null fallback legacy
    session memory 空模板 isSessionMemoryEmpty=true 返回 null fallback legacy
    summarized id 缺失 index=-1 返回 null fallback legacy
    post size 超阈值 postCompactTokenCount >= autoCompactThreshold 返回 null fallback legacy

    6) Failure / Recovery / Degradation

    6.1 microcompact 降级

    time-based/cached 任一路径不命中都安全 no-op，不会阻断 query。

    6.2 cachedMC 状态恢复

    time-based 触发后会 resetMicrocompactState()，防止 cachedMC 继续引用已失效工具 ID。

    6.3 SM compact 失败恢复

    trySessionMemoryCompaction 对“无 memory、空模板、ID 不存在、超阈值、异常”统一返回 null，由上层继续 legacy compact。

    6.4 API 不变量恢复

    adjustIndexToPreserveAPIInvariants 回溯补齐：

    • tool_use/tool_result 配对；
    • 同 message.id streaming 片段（含 thinking）。

    6.5 extraction 等待降级

    SM compact 在读取 session memory 前等待 extraction，但等待具 timeout/stale 保护，避免卡死。

    7) Invariants

    1. microcompact 不得生成 orphan tool_result。
    2. time-based 至少保留 1 个最近 compactable 结果。
    3. cached microcompact 仅允许 main-thread 进入。
    4. SM compact 若无法保证阈值与一致性，必须返回 null 而非硬上。
    5. adjustIndexToPreserveAPIInvariants 必须在最终切片前执行。
    6. warning suppression 必须在成功 compact 后设置，并在新尝试前清除。
    7. SM compact 不应绕过 session memory extraction 的在途同步。

    8) Cross-module Contracts

    • 对 02（决策层）：本页不决定是否触发，只定义触发后执行语义与回退语义。
    • 对 04（full compact）：本页返回 {messages} 或 null 以便上层进入 full compact。
    • 对 02-memory-system：SM compact 依赖 session memory 内容，但对其可用性保持 fail-open fallback。
    • 对 query：microcompact 返回消息必须可直接进入后续 query 调用，不改变 query 状态机拓扑。

    9) Engineering Constraints / Evolution Guidance

    新增 microcompact 策略时必须验证：

    1. 是否会污染 cachedMC 全局状态；
    2. 是否维持 tool pair 与 message.id 合并不变量；
    3. 是否在不可用场景可靠 no-op；
    4. 是否保留上层 fallback full compact 的机会。

    建议回归：

    • time-based 触发/不触发；
    • cachedMC 可用/不可用；
    • SM compact 的 no-memory / empty-template / id-missing / threshold-exceeded；
    • adjustIndexToPreserveAPIInvariants 对 tool pair 与 thinking 片段补齐。
