    、背压与错误传播（深潜审计版）

    核心论点

    StreamingToolExecutor 的核心目标不是“并发多跑几个工具”，而是让 streamed tool use 在实时输出下仍保持有序和可终止：

    1. concurrency-safe 与 exclusive 工具必须在统一 admission 规则下执行；
    2. 进度可立即 yield，但最终结果必须保持顺序；
    3. sibling abort、interrupt、fallback discard 都要有 synthetic terminal state；
    4. 任何工具都不能永久停留在不确定中间态。

    运行时状态所有权

    状态类别 所有者 关键函数/字段 说明
    队列态 StreamingToolExecutor.ts tools / status (queued/executing/completed/...) 全部 streamed tools 的生命周期列表
    admission 态 StreamingToolExecutor.ts addTool / canExecuteTool / processQueue 并发安全与独占调度
    执行态 StreamingToolExecutor.ts executeTool 实际运行与状态回收
    synthetic error 态 StreamingToolExecutor.ts createSyntheticErrorMessage fallback discard / sibling abort / missing tool
    主循环消费态 query.ts streamed tool result drain 将 executor 结果接回 query 主链
    具体 tool 调用态 toolExecution.ts runToolUse 工具执行与 message 生成

    端到端流程

    1. 模型流产生 tool_use block，addTool 入队；
    2. processQueue 检查可执行性：并发安全工具可并行，独占工具形成栅栏；
    3. executeTool 运行工具并立即 yield progress；
    4. 成功、失败、interrupt、fallback discard 都被收敛为最终结果或 synthetic error；
    5. query.ts drain executor 输出并把结果并回 assistant/user message 流；
    6. 队列推进直到所有 tools 终结。
    // src/services/tools/StreamingToolExecutor.ts
private canExecuteTool(isConcurrencySafe: boolean): boolean {
  const executingTools = this.tools.filter(t => t.status === 'executing')
  return executingTools.length === 0 || (isConcurrencySafe && executingTools.every(t => t.isConcurrencySafe))
}

    守卫与决策矩阵

    Guard 条件 动作 结果
    admission guard concurrency-safe vs exclusive 并行或栅栏阻塞 背压稳定
    missing tool guard tool 不存在 synthetic error 保证终态
    sibling error guard sibling 失败 abort 相关 siblings / synthetic cancel 防队列悬挂
    interrupt guard user interrupt / cancel reason 按 interruptBehavior 取消 用户中断可收敛
    fallback discard guard streaming fallback 发生 丢弃未完成执行并合成错误 防重复执行
    progress/final guard in-flight progress vs final result 立即 yield progress，结果有序输出 UX 与语义兼得
    reentry guard processQueue 已在推进 避免重复执行同一工具 防双执行

    失败、恢复与降级

    工具不存在

    • 直接生成 “No such tool available” synthetic error；
    • 队列继续向前推进。

    • 某工具失败后，通过 sibling abort controller 传播取消；
    • 被取消的兄弟工具收敛为 synthetic terminal state。

    用户中断

    • interrupt 根据工具 interruptBehavior 分流；
    • 可取消的工具终止，不应取消的保持收尾语义。

    • fallback 发生后，未决工具执行被标记 discard；
    • 后续产出 synthetic error，避免真实执行结果与 fallback 响应混杂。

    结果排空恢复

    • 即使 progress 已提前发出，最终结果仍要 drain 完整并保持顺序；
    • 防止“看到进度但永远没有终态”。

    不变量

    1. 每个 queued tool 最终必须 completed 或 synthetic terminal。
    2. 非 concurrency-safe 工具不得被后续 exclusive tool 穿透。
    3. sibling 错误传播不得污染已完成结果。
    4. progress 与 final result 必须共享同一 tool identity。
    5. fallback discard 后不得继续提交真实执行结果。
    6. processQueue 不得并发重入导致双执行。

    跨模块契约

    • 对 02：04 消费已去重、已关联的 streamed tool 语义。
    • 对 03：transport retry 不应让 04 重复执行已入队工具。
    • 对 01：04 输出 progress/final result，01 再将其投影到 UI。
    • 对 toolExecution：04 只做调度与收敛，不重写具体工具业务语义。
