    流式处理：事件语义、请求关联、传输重放与工具背压（深潜审计版）

    1) Scope 与 Evidence Boundary

    本页覆盖 07 模块“流式语义收敛层”：模型流事件解析、StructuredIO 请求关联、transport buffering/replay、streaming tool executor、CLI/REPL/UI 渲染与 completion/error/abort/fallback 语义。

    证据范围：

    • src/services/api/claude.ts
    • src/utils/messages.ts
    • src/services/api/errors.ts
    • src/cli/structuredIO.ts
    • src/cli/transports/ccrClient.ts
    • src/cli/transports/HybridTransport.ts

    不覆盖：

    • 模型决策本体与 tool 业务语义；
    • slash 命令注册语义；
    • 非 streaming 模式下的普通一次性响应路径。

    2) Core Thesis

    07 模块的第一职责不是“快显示”，而是语义可关联、可恢复、可去重：

    1. stream event 必须被稳定装配成最终消息语义；
    2. request/response 关联必须在取消、重复、迟到响应下保持幂等；
    3. transport 重连/重放不能引入语义重复；
    4. tool 流式执行必须在背压、并发和错误传播下可收敛；
    5. UI 看到的是投影视图，不能反向篡改事件语义。

    3) Runtime State Ownership

    状态类别 所有者 关键函数/字段 说明
    流事件装配态 claude.ts + messages.ts stream event parsing / handleMessageFromStream content_block_*、message_delta 到消息状态
    内容规范化态 messages.ts normalizeContentFromAPI / normalizeMessagesForAPI 最终 API-safe/REPL-safe 消息形态

    渲染投影态 REPL.tsx + Messages.tsx streamingText / streamingThinking / streamingToolUses live overlay 与静态渲染

    4) End-to-end Flow

    1. 模型流在 claude.ts 被解析为增量 stream events；
    2. handleMessageFromStream 将增量装配为 REPL/消息状态更新；
    3. StructuredIO 将语义事件写入 outbound 并跟踪控制请求关联；
    4. transport 层负责缓冲、flush、replay、reconnect；
    5. streamed tool use 进入 StreamingToolExecutor，按并发规则执行并产出进度/结果；
    6. Messages.tsx / REPL.tsx 将 streamingText/thinking/toolUses 投影到用户界面；
    7. 完成、refusal、abort、fallback 走统一 completion/error/recovery 分支。

    5) Guard / Decision Matrix

    Guard 条件 动作 结果
    stream event type guard content_block_start/delta/stop、message_delta、message_stop 进入对应装配分支 事件语义稳定
    refusal guard stop_reason='refusal' 生成 refusal user-facing error 防静默拒绝
    fallback guard stream 不完整/无有效 assistant output 进入 non-streaming fallback 保持可用性
    request correlation guard duplicate/orphan/late response 去重/忽略/局部清理 协议幂等
    transport replay guard buffered events 未 flush 先 flush 再写非 stream 消息 保持顺序
    concurrency guard tool concurrency-safe vs exclusive 允许并行或形成栅栏 背压稳定
    sibling abort guard sibling error / interrupt / fallback discard 传播 synthetic error/cancel 工具收尾一致
    render mode guard live vs transcript/static overlay 或静态渲染 UX 稳定

    6) Failure / Recovery / Degradation

    6.1 不完整 stream 恢复

    • 若 stream 启动后没有形成有效 assistant 输出或 stop_reason；
    • 进入 non-streaming fallback，而不是误判成功。

    6.2 session/abort 恢复

    • APIUserAbortError + aborted signal 视为真实用户中断；
    • 非用户中断则按 timeout/connection 路径分类并决定是否 fallback。

    6.3 duplicate/orphan 响应吸收

    • resolvedToolUseIds 吞掉已完成 tool_use 的重复响应；
    • orphan response 走忽略或 unexpected callback，不重新写业务状态。

    6.4 tool 执行恢复

    • sibling error、user interrupt、streaming fallback discard 都通过 synthetic error 收敛；
    • 保证每个工具都有终态。

    6.5 transport 退化

    • delayed/buffered events 会在 close/flush 边界集中输出；
    • 重连与 replay 失败时显式关闭，而不是静默乱序。

    7) Invariants

    1. 语义 ID 稳定性高于传输成功率。
    2. control 与 content 消息必须共享顺序保证。
    3. duplicate control/tool responses 不得重新进入业务处理。
    4. 任何 streamed tool 最终都必须收敛为 completed 或 synthetic terminal state。
    5. fallback/reconnect 不能引入重复 assistant/tool 语义。
    6. render overlay 只能投影状态，不能改变底层消息语义。
    7. refusal/max_output/context-window stop 必须有可解释终态。

    8) Cross-module Contracts

    • 对 query/tool 主链：07 只投影与关联语义事件，不重写业务语义。
    • 对 05（MCP）与 06（Hooks）：控制消息与内容消息共享顺序与 request correlation。
    • 对 CLI/UI：输出模式可不同，但事件语义必须一致。
    • 对 transport：delivery retry 不等于 semantic replay，二者必须分层处理。

    9) Engineering Constraints / Evolution Guidance

    扩展 streaming 机制时必须验证：

    1. 新 stream event 是否进入统一装配器；
    2. 新 control request 是否有 pending/resolve/cancel/duplicate 语义；
    3. 新 transport 是否保证缓冲 flush 顺序与 replay 幂等；
    4. 新 tool progress 事件是否能在 UI 中稳定投影；
    5. fallback 路径是否会重复写入 assistant/tool 状态。

    建议回归：

    • content_block_start/delta/stop + message_delta/message_stop 全链；
    • refusal/max_tokens/model_context_window_exceeded；
    • duplicate/orphan/late response；
    • Hybrid/CCR delayed flush；
    • sibling abort / interrupt / fallback discard；
    • transcript/live/static render 差异。
