命令注册与 Slash 路由（深潜审计版）

1) Scope 与 Evidence Boundary

本页只讨论 09 模块的“命令事实源 -> 输入路由”主链：

  • src/commands.ts 如何把多来源命令并轨并做执行前过滤；
  • src/utils/processUserInput/processUserInput.ts 如何决定 slash/非 slash 分流；
  • src/utils/processUserInput/processSlashCommand.tsx 如何把 /cmd args 路由到 local/local-jsx/prompt/fork。

证据范围：

  • src/commands.ts:getSkills
  • src/commands.ts:loadAllCommands
  • src/commands.ts:getCommands
  • src/commands.ts:getSkillToolCommands
  • src/commands.ts:getSlashCommandToolSkills
  • src/commands.ts:isBridgeSafeCommand
  • src/commands.ts:filterCommandsForRemoteMode
  • src/utils/slashCommandParsing.ts:parseSlashCommand
  • src/utils/processUserInput/processUserInput.ts:processUserInput
  • src/utils/processUserInput/processSlashCommand.tsx:processSlashCommand

不覆盖：

  • CLI 顶层 fast-path（见 01）；
  • Commander/preAction 初始化屏障（见 02）；
  • structured output / bridge 生命周期（见 04/05）。

2) Core Thesis

03 的核心是：slash 不是一套独立系统，而是 command registry 的一个消费者投影。

具体体现为：

  1. 所有命令源先在 getCommands 并轨成统一 Command[]；
  2. availability/enabled/remote-safe/bridge-safe 都在执行前过滤；
  3. slash 入口只做解析与分发，不重建命令事实；
  4. unknown/malformed/path-like 输入走恢复路径，避免把普通输入误判为命令错误。

3) Runtime State Ownership

状态类别 所有者 关键函数 职责

4) End-to-end Flow（事实源到执行）

4.1 commands.ts 先合流再过滤

getSkills 把 skillDir/pluginSkills/bundled/builtinPluginSkills 收敛：

const [skillDirCommands, pluginSkills] = await Promise.all([
  getSkillDirCommands(cwd).catch(() => []),
  getPluginSkills().catch(() => []),
])
const bundledSkills = getBundledSkills()
const builtinPluginSkills = getBuiltinPluginSkillCommands()

loadAllCommands 再合并 workflow/pluginCommands/builtin：

return [
  ...bundledSkills,
  ...builtinPluginSkills,
  ...skillDirCommands,
  ...workflowCommands,
  ...pluginCommands,
  ...pluginSkills,
  ...COMMANDS(),
]

4.2 getCommands 应用运行期 gating + dynamic skills 注入

const allCommands = await loadAllCommands(cwd)
const dynamicSkills = getDynamicSkills()
const baseCommands = allCommands.filter(
  _ => meetsAvailabilityRequirement(_) && isCommandEnabled(_),
)

若 dynamic skills 存在，会去重并插入 builtin 之前，保持 registry 顺序语义。

4.3 model/slash 两个 consumer 的投影过滤

SkillTool 视角（更宽，含 legacy command 风格 prompt 命令）：

return allCommands.filter(
  cmd =>
    cmd.type === 'prompt' &&
    !cmd.disableModelInvocation &&
    cmd.source !== 'builtin' &&
    (cmd.loadedFrom === 'bundled' ||
      cmd.loadedFrom === 'skills' ||
      cmd.loadedFrom === 'commands_DEPRECATED' ||
      cmd.hasUserSpecifiedDescription ||
      cmd.whenToUse),
)

slash 技能视角（更窄，强调 skills/plugin/bundled + description）：

return allCommands.filter(
  cmd =>
    cmd.type === 'prompt' &&
    cmd.source !== 'builtin' &&
    (cmd.hasUserSpecifiedDescription || cmd.whenToUse) &&
    (cmd.loadedFrom === 'skills' ||
      cmd.loadedFrom === 'plugin' ||
      cmd.loadedFrom === 'bundled' ||
      cmd.disableModelInvocation),
)

4.4 processUserInput 决定 slash gate，bridge 有例外白名单

let effectiveSkipSlash = skipSlashCommands
if (bridgeOrigin && inputString?.startsWith('/')) {
  const parsed = parseSlashCommand(inputString)
  const cmd = parsed ? findCommand(parsed.commandName, context.options.commands) : undefined
  if (cmd) {
    if (isBridgeSafeCommand(cmd)) {
      effectiveSkipSlash = false
    } else {
      return { ... shouldQuery: false, resultText: `/${getCommandName(cmd)} isn't available over Remote Control.` }
    }
  }
}

然后统一 slash 入口：

if (inputString !== null && !effectiveSkipSlash && inputString.startsWith('/')) {
  const { processSlashCommand } = await import('./processSlashCommand.js')
  return await processSlashCommand(...)
}

4.6 processSlashCommand 的 unknown 恢复策略

if (!hasCommand(commandName, context.options.commands)) {
  let isFilePath = false
  try { await getFsImplementation().stat(`/${commandName}`); isFilePath = true } catch {}

  if (looksLikeCommand(commandName) && !isFilePath) {
    return { ... shouldQuery: false, resultText: `Unknown skill: ${commandName}` }
  }

  return { ... shouldQuery: true } // 降级为普通 prompt
}

5) Guard / Decision Matrix

5.1 Registry guards

Guard 条件 动作 结果
source merge guard 多来源命令并存 getSkills + loadAllCommands 合流 单一命令事实源
availability guard cmd.availability 不满足 meetsAvailabilityRequirement 过滤 订阅/提供方约束前置
enabled guard isCommandEnabled=false getCommands 过滤 禁用命令不暴露
dynamic skill dedupe guard dynamic 与 base 重名 名称去重后注入 防重复命令
mcp skill filter guard SkillTool 需要 MCP 技能 getMcpSkillCommands 类型+来源+模型可调用过滤 防杂项 MCP 命令混入
remote mode guard remote 初始化 filterCommandsForRemoteMode 远端仅保留安全本地命令
bridge safe guard bridge 输入 slash isBridgeSafeCommand 判定 local-jsx 默认阻断

5.2 Slash routing guards

Guard 条件 动作 结果
parse guard 非 /... 或空命令 parseSlashCommand -> null 进入普通 prompt 流
malformed guard slash 结构无效 返回格式提示 用户可恢复
unknown guard hasCommand miss looksLike + path probe unknown 命令与普通输入分离
path-like guard 实际文件路径 不报 unknown，降级普通输入 降低误伤
userInvocable guard userInvocable=false 直接拒绝用户 slash 调用 模型入口与用户入口分层
type dispatch guard local/local-jsx/prompt switch 分发 执行语义稳定
fork context guard prompt + context='fork' executeForkedSlashCommand 子代理隔离执行

6) Failure / Recovery / Degradation

6.1 命令源加载失败局部化

getSkills 对 skillDir/pluginSkills 各自 catch 并回空数组，保证核心命令系统可继续运行。

6.2 skills 投影失败局部化

getSlashCommandToolSkills catch 后返回 []，避免技能索引失败拖垮命令主链。

6.3 bridge 不安全 slash 显式反馈

bridge 输入下，命令已知但不安全时直接返回 /<cmd> isn't available over Remote Control.，而不是把原始 slash 文本送给模型。

6.4 unknown slash 的可恢复降级

unknown 且看起来不像命令（或是路径）时，回到普通 prompt 流；看起来像命令时给出明确 unknown skill 提示并保留参数语义。

6.5 local-jsx 异常防死锁

getMessagesForSlashCommand 的 local-jsx 分支在 load/call 抛错且未 onDone 时会 resolve 空消息并清理 UI 状态，避免 Promise 悬挂卡死队列。

7) Invariants

  1. getCommands 是 slash 与 SkillTool 的共同命令事实源。
  2. meetsAvailabilityRequirement 与 isCommandEnabled 必须在执行前过滤。
  3. bridge 输入默认 skipSlashCommands，仅白名单命令可例外放行。
  4. userInvocable=false 的命令必须拒绝直接 slash 调用。
  5. command.type + context 必须唯一决定执行分支（local/local-jsx/prompt/fork）。
  6. unknown/malformed/path-like 输入必须保留用户恢复路径。

8) Cross-module Contracts

  • 对 02：02 保证启动完成与上下文就绪，03 在其上做命令解析和路由。
  • 对 04：03 输出的是执行意图与消息序列，不负责最终呈现协议。
  • 对 08：03 与 SkillTool 共享 commands.ts 事实源，禁止“双注册表”分叉。
  • 对 05：03 只负责 bridge-origin slash 入口 gating，不管理 bridge 会话生命周期。

9) Engineering Constraints / Evolution Guidance

扩展命令系统或 slash 路由时，优先检查：

  1. 新来源是否通过 loadAllCommands/getCommands 接入，而非旁路；
  2. 新命令是否定义 availability/enabled/bridge-safe/remote-safe 语义；
  3. 是否破坏 skipSlashCommands + bridgeOrigin 的防护顺序；
  4. 是否引入“已知但不可执行”时的静默失败；
  5. findCommand 对 name/alias/getCommandName 的等价性是否保持。

建议回归：

  • source merge + dynamic dedupe；
  • availability/enabled 过滤；
  • remote/bridge 安全过滤；
  • malformed/unknown/path-like 三类 slash 输入；
  • userInvocable=false 与 fork context 分支。
