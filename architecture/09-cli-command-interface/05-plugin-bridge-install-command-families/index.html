Plugin / Bridge / Install 命令族（深潜审计版）

1) Scope 与 Evidence Boundary

本页只覆盖 09 模块里的管理平面命令族，以及它们与 bridge 运行面的契约边界：

  • plugin 命令族（含 marketplace/install/enable/disable/update）；
  • install [target] 本地安装命令；
  • remote-control / assistant 等 bridge 入口命令（Commander 注册层）；
  • bridge 运行时入口 bridgeMain 与 daemon worker 入口 runBridgeHeadless 的 guard 链。

证据范围：

  • src/main.tsx:run（命令族注册与 help 面）
  • src/bridge/bridgeMain.ts:bridgeMain
  • src/bridge/bridgeMain.ts:runBridgeHeadless

不覆盖：

  • argv 顶层 fast-path 命中规则（见 01）；
  • registry/slash 主路由（见 03）；
  • print/structured output 协议投影（见 04）；
  • replBridge/useReplBridge 的长生命周期状态机（见 07）。

2) Core Thesis

05 的核心不是“多几个管理命令”，而是：把高风险/高副作用能力压缩到可审计的管理平面，并用双层 guard 保证 remote-control 启动安全。

具体体现：

  1. plugin/install/remote-control 是控制面命令，不应混入普通对话语义；
  2. remote-control 在 Commander 层只是可见性投影，真实执行由 entry fast-path + bridgeMain 负责；
  3. bridgeMain 与 runBridgeHeadless 都采用“先校验再运行”的 fail-stop 链；
  4. trust/auth/baseUrl/policy 失败必须显式终止，不能静默降级到不安全状态。

3) Runtime State Ownership

状态类别 所有者 关键函数 职责
管理命令声明态 main.tsx run 声明 plugin/install/remote-control/assistant 命令面
plugin 生态治理态 plugin handlers run 中 plugin 子命令 marketplace、安装、启停、升级入口
bridge 交互入口态 main.tsx + entrypoint run + fast-path handoff Commander help 投影与 bridge 实际执行分离
bridge 交互运行态 bridgeMain.ts bridgeMain permission/trust/auth/baseUrl/session gate + 启动
bridge worker 运行态 bridgeMain.ts runBridgeHeadless 无 TUI 场景下的同等安全约束

4) End-to-end Flow（management family → bridge runtime）

4.1 run 注册管理命令族，不在此处承载核心执行语义

src/main.tsx:run 中，plugin 命令族集中声明：

const pluginCmd = program.command('plugin').alias('plugins')
pluginCmd.command('validate <path>')...
pluginCmd.command('list')...
const marketplaceCmd = pluginCmd.command('marketplace')...
pluginCmd.command('install <plugin>').alias('i')...
pluginCmd.command('uninstall <plugin>').alias('remove').alias('rm')...
pluginCmd.command('enable <plugin>')...
pluginCmd.command('disable [plugin]')...
pluginCmd.command('update <plugin>')...

install 为独立命令族：

program.command('install [target]')
  .option('--force', ...)
  .action(async (...) => { ... })

4.2 remote-control 在 Commander 层是 help 可见性的投影

src/main.tsx:run：

program.command('remote-control', { hidden: true })
  .alias('rc')
  .action(async () => {
    const { bridgeMain } = await import('./bridge/bridgeMain.js')
    await bridgeMain(process.argv.slice(3))
  })

注释明确该 action 在正常路径“不可达”：真实入口由 cli.tsx fast-path 先拦截；这里主要用于命令面与帮助系统保持一致。

4.3 bridgeMain 的启动 guard 顺序是安全边界本体

src/bridge/bridgeMain.ts:bridgeMain 关键顺序：

  1. 解析参数并验证 permissionMode；
  2. enableConfigs() + initSinks()（bridge 快路径绕过 main init，需手动补齐）；
  3. 校验 multi-session feature gate；
  4. 设置 cwd/bootstrap state；
  5. trust dialog gate（未信任直接退出）；
  6. OAuth token gate（未登录直接退出）；
  7. baseUrl HTTPS gate（非 localhost 的 HTTP 直接退出）；
  8. 构建 session ingress / git 元信息并进入后续 bridge loop。

示例片段：

if (permissionMode !== undefined) {
  const { PERMISSION_MODES } = await import('../types/permissions.js')
  if (!PERMISSION_MODES.includes(permissionMode)) process.exit(1)
}

enableConfigs()
initSinks()

if (!checkHasTrustDialogAccepted()) process.exit(1)
if (!bridgeToken) process.exit(1)

if (baseUrl.startsWith('http://') && !baseUrl.includes('localhost') && !baseUrl.includes('127.0.0.1')) {
  process.exit(1)
}

4.4 runBridgeHeadless 复用同样的安全链，但不依赖交互 TUI

src/bridge/bridgeMain.ts:runBridgeHeadless：

  • worker 先 chdir(dir) 并设置 bootstrap cwd；
  • 再 enableConfigs() / initSinks()；
  • trust / auth / HTTPS 与交互态一致；
  • 失败通过抛错区分 permanent/transient，由 supervisor 决策重试。

这保证 daemon worker 与交互 bridge 在安全语义上不分叉。

5) Guard / Decision Matrix

Guard 条件 行为 结果
command-family guard 命中 plugin/install/remote-control/assistant 进入管理命令处理链 控制面能力集中
remote-control visibility guard Commander remote-control 注册 hidden + alias，仅作命令面投影 help 与 fast-path 保持一致
permission mode guard --permission-mode 指定非法值 stderr + exit(1) 权限模式不漂移
config/sink bootstrap guard bridge 快路径绕过 main init 手动 enableConfigs + initSinks 启动副作用一致
multi-session gate 使用 spawn/capacity/create-session-in-dir 且 gate 未开 拒绝并退出 试验特性有门闩
trust gate 未接受 workspace trust 拒绝 bridge 启动 防未授权目录远程接入
auth token guard 无 bridge token 拒绝启动 不进入匿名 remote-control
baseUrl HTTPS guard 非 localhost 且 HTTP 拒绝启动 凭证传输安全
headless parity guard daemon worker 路径 复用同等 trust/auth/HTTPS 校验 交互与非交互语义一致

6) Failure / Recovery / Degradation

6.1 管理命令失败局部化

plugin/install 子命令失败只影响对应命令调用，不应污染主 REPL 会话。

6.2 bridge 启动失败显式化

bridgeMain 对 permission/trust/auth/baseUrl 等失败均直接退出，避免“半连接”状态。

6.3 gate 拒绝是 fail-stop，不是静默回退

multi-session gate 未开启时直接拒绝相关参数，不偷偷降级为另一模式。

6.4 headless 失败分级

runBridgeHeadless 区分 permanent 与 transient，交由 supervisor 决定重试/终止；不在 worker 内部静默吞错。

7) Invariants

  1. 管理命令族属于控制面，不得改变普通消息执行语义。
  2. remote-control 的真实执行路径必须经过 bridge 专用 guard 链。
  3. bridge 快路径必须补齐 enableConfigs 与 initSinks。
  4. trust/auth/baseUrl 任一失败都必须显式终止。
  5. headless bridge 与交互 bridge 必须保持同等安全门槛。
  6. 非 localhost HTTP baseUrl 在 bridge 场景必须被拒绝。

8) Cross-module Contracts

  • 对 01：01 负责 fast-path 命中与桥接入口分流；05 负责 bridge 运行面 guard。
  • 对 02：02 提供通用 preAction 初始化；05 描述其旁路路径（bridge 快路径）如何补齐必要初始化。
  • 对 03：03 定义命令事实与路由；05 只定义管理命令族的执行边界，不重建 registry。
  • 对 04：05 不定义输出协议，仅提供可被输出层消费的终态。
  • 对 07：05 不承载 bridge 长生命周期恢复细节，仅覆盖入口与启动门槛。

9) Engineering Constraints / Evolution Guidance

新增管理命令或 bridge 参数时，必须先检查：

  1. 是否确属管理平面（而非应放普通 slash/对话流）；
  2. 是否会绕过现有 trust/auth/baseUrl/policy guard；
  3. 是否会导致交互态与 headless 态安全语义分叉；
  4. 是否会让 Commander 展示面与真实入口行为不一致；
  5. 失败语义是 fail-stop 还是 fail-open，是否与现有链条一致。

建议回归：

  • plugin marketplace/add/remove/update/install/uninstall/enable/disable；
  • install [target] + --force；
  • remote-control 在 fast-path 与 help 面一致性；
  • bridge permissionMode/trust/auth/baseUrl 各类失败路径；
  • headless bridge 的 permanent/transient 失败分流。
