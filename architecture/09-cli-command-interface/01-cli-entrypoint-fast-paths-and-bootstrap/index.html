CLI 入口 fast-path 与启动（深潜审计版）

1) Scope 与 Evidence Boundary

本页只覆盖 entrypoint 层 argv 分流与 full CLI 启动前 bootstrap，即：

  • 哪些路径在 src/entrypoints/cli.tsx:main 里被短路（fast-path）；
  • 哪些路径必须先做 config/auth/policy gate 才能继续；
  • 何时才允许落入 ../main.js 的完整 Commander 生命周期；
  • --worktree --tmux 的早期分流如何与主路径解耦。

证据边界（仅本页使用）：

  • src/entrypoints/cli.tsx:main
  • src/bridge/bridgeMain.ts:bridgeMain
  • src/utils/worktree.ts:execIntoTmuxWorktree

不覆盖：

  • Commander 组装与 preAction 初始化屏障（见 02）；
  • registry/slash/help/output 投影（见 03/04）；
  • bridge 内部状态机与 recovery 细节（见 05）。

2) Core Thesis

09-01 的核心不是“入口调用 main()”，而是三条硬约束：

  1. 高频命令必须在入口短路，避免不必要的模块求值与初始化副作用；
  2. 需要安全/配置上下文的快路径必须先 gate 再执行，不能先跑业务再补鉴权；
  3. 未命中快路径才允许 delayed import main.js，保证 full CLI 是明确 fallback，而非默认路径被旁路污染。

一句话：entrypoint 是启动成本与副作用边界的第一道闸门。

3) Runtime State Ownership

状态类别 所有者 关键入口 职责
argv 顶层分流态 cli.tsx main 分类 process.argv.slice(2) 并选择 fast/full path
early env gate 态 cli.tsx main 顶层与尾部 gate 设置 COREPACK_ENABLE_AUTO_PIN、remote 内存限制、--bare 环境位
feature fast-path 态 cli.tsx main 多分支 bridge/daemon/bg/template/runner/worktree 分流
bridge 启动态 bridgeMain.ts bridgeMain remote-control 解析、permission mode 校验、config+sinks 早启
tmux worktree 快路径态 worktree.ts execIntoTmuxWorktree 平台检查、tmux 可用性检查、worktree 名解析与执行
full CLI 回退态 cli.tsx delayed import ../main.js 启动 early input 捕获并进入 Commander 主链

4) End-to-end Flow（入口真实执行序）

4.1 顶层环境副作用先于 argv 分流

cli.tsx 顶层先执行环境修正：

process.env.COREPACK_ENABLE_AUTO_PIN = '0'

if (process.env.CLAUDE_CODE_REMOTE === 'true') {
  const existing = process.env.NODE_OPTIONS || ''
  process.env.NODE_OPTIONS = existing
    ? `${existing} --max-old-space-size=8192`
    : '--max-old-space-size=8192'
}

这意味着：entrypoint 在 main() 前就已经决定了部分运行边界（corepack auto-pin 与 remote 进程内存上限）。

4.2 --version 是零额外模块加载路径

if (args.length === 1 && (args[0] === '--version' || args[0] === '-v' || args[0] === '-V')) {
  console.log(`${SNAPSHOT_VERSION} (Claude Code)`)
  return
}

该分支在 startupProfiler 导入之前返回，属于严格快路径。

4.3 其余路径先进入 profiler，再继续分流

const { profileCheckpoint } = await import('../utils/startupProfiler.js')
profileCheckpoint('cli_entry')

后续每个快路径都打 checkpoint，形成可观测启动切面。

4.4 需要配置能力的快路径显式 enableConfigs()

例如 dump-system-prompt、bridge、daemon、bg、tmux-worktree 分支都在业务逻辑前显式启用配置系统。

4.5 bridge 快路径的 gate 顺序是“先 auth，再 GB/policy，再 main”

cli.tsx 中：

if (feature('BRIDGE_MODE') && (...)) {
  const { getBridgeDisabledReason, checkBridgeMinVersion } = await import('../bridge/bridgeEnabled.js')
  const { BRIDGE_LOGIN_ERROR } = await import('../bridge/types.js')
  const { bridgeMain } = await import('../bridge/bridgeMain.js')

  const { getClaudeAIOAuthTokens } = await import('../utils/auth.js')
  if (!getClaudeAIOAuthTokens()?.accessToken) {
    exitWithError(BRIDGE_LOGIN_ERROR)
  }

  const disabledReason = await getBridgeDisabledReason()
  if (disabledReason) exitWithError(`Error: ${disabledReason}`)

  const versionError = checkBridgeMinVersion()
  if (versionError) exitWithError(versionError)

  await waitForPolicyLimitsToLoad()
  if (!isPolicyAllowed('allow_remote_control')) {
    exitWithError("Error: Remote Control is disabled by your organization's policy.")
  }

  await bridgeMain(args.slice(1))
  return
}

并且 src/bridge/bridgeMain.ts:bridgeMain 内部再次做输入校验与早期初始化：

if (permissionMode !== undefined) {
  const { PERMISSION_MODES } = await import('../types/permissions.js')
  if (!PERMISSION_MODES.includes(permissionMode)) {
    console.error(`Error: Invalid permission mode ...`)
    process.exit(1)
  }
}

const { enableConfigs } = await import('../utils/config.js')
enableConfigs()
const { initSinks } = await import('../utils/sinks.js')
initSinks()

即：入口层与 bridge 运行层形成双层 gate，而不是单点校验。

4.6 --worktree --tmux 早期分流可失败回退

cli.tsx：

const hasTmuxFlag = args.includes('--tmux') || args.includes('--tmux=classic')
if (hasTmuxFlag && (args.includes('-w') || args.includes('--worktree') || args.some(a => a.startsWith('--worktree=')))) {
  const { execIntoTmuxWorktree } = await import('../utils/worktree.js')
  const result = await execIntoTmuxWorktree(args)
  if (result.handled) return
  if (result.error) exitWithError(result.error)
}

src/utils/worktree.ts:execIntoTmuxWorktree 的前置 guard：

if (process.platform === 'win32') {
  return { handled: false, error: 'Error: --tmux is not supported on Windows' }
}

const tmuxCheck = spawnSync('tmux', ['-V'], { encoding: 'utf-8' })
if (tmuxCheck.status !== 0) {
  return { handled: false, error: `Error: tmux is not installed. ...` }
}

它返回 { handled, error? } 三态语义，由 entrypoint 决定“终止/回退”。

4.7 argv rewrite 与 bare gate 在 full CLI 前完成

if (args.length === 1 && (args[0] === '--update' || args[0] === '--upgrade')) {
  process.argv = [process.argv[0]!, process.argv[1]!, 'update']
}

if (args.includes('--bare')) {
  process.env.CLAUDE_CODE_SIMPLE = '1'
}

4.8 最终 fallback：开启 early input 后 delayed import main

const { startCapturingEarlyInput } = await import('../utils/earlyInput.js')
startCapturingEarlyInput()
const { main: cliMain } = await import('../main.js')
await cliMain()

full CLI 仅在前述快路径都未命中时才发生。

5) Guard / Decision Matrix（入口判决矩阵）

Guard 条件 行为 结果
version guard --version/-v/-V 直接输出版本并 return 零重型初始化
dump-prompt guard --dump-system-prompt 启 config + 模型解析 + 输出 prompt 不进入 Commander
bridge alias guard remote-control/rc/remote/sync/bridge auth+GB+policy gate 后转 bridgeMain 控制面专线
daemon worker guard --daemon-worker <kind> 直接 runDaemonWorker 轻量 worker 启动
daemon guard daemon config+sinks 后进 daemon main 长驻监督路径
bg session guard ps/logs/attach/kill/--bg/--background 按分支调用 bg handlers 后台会话管理专线
templates guard new/list/reply 进模板 job main，必要时 process.exit(0) TUI 残留句柄不阻塞退出
runners guard environment-runner/self-hosted-runner 直接 headless runner main 不加载交互 CLI
tmux-worktree guard --tmux + --worktree execIntoTmuxWorktree，按 handled/error 处理 可早退可显式失败
update rewrite guard --update/--upgrade 重写 argv 为 update 子命令 用户误用恢复
bare mode guard --bare 提前设置 CLAUDE_CODE_SIMPLE=1 影响后续模块求值/选项构建
fallback guard 全部分支未命中 earlyInput + delayed import main.js 进入 full CLI 主链

6) Failure / Recovery / Degradation

6.1 快路径失败局部化

入口代码采用“命中即 return”的单分支模型，避免一个快路径失败后继续走其它快路径造成语义串扰。

6.2 bridge 失败显式化

auth 缺失、版本不满足、policy 禁用都立即 exitWithError，不会隐式降级到普通 CLI。

6.3 tmux/worktree 失败可解释

execIntoTmuxWorktree 返回结构化错误字符串（Windows 不支持 / tmux 未安装），由入口统一终止并提示。

6.4 update 参数误用恢复

--update/--upgrade 统一 rewrite，避免用户落入未知参数路径。

6.5 full CLI 是“明确 fallback”

只有未命中任何快路径时才 import('../main.js')，确保慢路径行为可预测。

7) Invariants

  1. src/entrypoints/cli.tsx:main 必须保持“先分流、后 full import”的启动序。
  2. --version 分支必须保持零重模块加载语义。
  3. bridge 分支必须先通过 auth/policy gate，后进入 bridgeMain。
  4. --worktree --tmux 的平台/依赖检查必须在完整 CLI 前完成。
  5. --bare 环境位必须在 main.js 导入前写入。
  6. 未命中快路径时才允许 earlyInput + delayed import fallback。

8) Cross-module Contracts

  • 对 02：01 只决定是否进入 full CLI，不承担 Commander 初始化策略。
  • 对 05：01 只把控制权移交 bridgeMain，不定义 bridge 会话生命周期。
  • 对 worktree 子系统：01 只消费 execIntoTmuxWorktree 的 handled/error 协议，不侵入其内部状态。
  • 对输出系统：01 只做启动分流，不定义 print/help/stream-json 语义。

9) Engineering Constraints / Evolution Guidance

新增入口快路径时，必须同时验证：

  1. 是否真的需要在 entrypoint 层短路（而不是 Commander 子命令）；
  2. 是否需要 enableConfigs()/initSinks() 的前置能力；
  3. 失败是否应 hard-fail 还是 fallthrough 到 full CLI；
  4. 是否破坏已有 guard 的互斥性（尤其 args[0] 家族分支）；
  5. 是否需要 startup profiler checkpoint 保持可观测性。

最小回归集合：

  • --version；
  • bridge aliases（含 policy deny）；
  • daemon / --daemon-worker；
  • ps/logs/attach/kill/--bg；
  • --worktree --tmux（Windows/无 tmux/成功三态）；
  • --update/--upgrade rewrite；
  • --bare + full fallback。
