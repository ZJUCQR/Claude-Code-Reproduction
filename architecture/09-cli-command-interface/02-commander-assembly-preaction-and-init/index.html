Commander 装配、preAction 与初始化屏障（深潜审计版）

1) Scope 与 Evidence Boundary

本页只覆盖 full CLI 路径 中 src/main.tsx 的三件事：

  • run() 如何装配 Commander 主程序与顶层选项面；
  • program.hook('preAction', ...) 如何作为统一初始化屏障；
  • action 内部如何把 setup/commands/agents/环境应用编排成可控启动序。

证据范围：

  • src/main.tsx:main
  • src/main.tsx:run
  • src/main.tsx:runMigrations
  • src/main.tsx:getInputPrompt

不覆盖：

  • argv 顶层 fast-path（见 01）；
  • command registry/slash 路由（见 03）；
  • output/bridge 细节（见 04/05）。

2) Core Thesis

02 模块的本质不是“声明很多 .option()/.command()”，而是把 full CLI 的可执行性压缩为一个稳定顺序：

  1. preAction 先完成关键前置（MDM/keychain、init()、sinks、migrations）；
  2. action 再进行 setup 与命令面加载，并行化可并行项；
  3. 非关键远程/同步任务走 fail-open，不阻断主链。

一句话：Commander 是外壳，preAction+action 编排才是启动状态机。

3) Runtime State Ownership

状态类别 所有者 关键函数 职责
进程级启动防护态 main.tsx main 早期安全环境位、signal/warning 处理、argv 早改写
Commander 结构态 main.tsx run 构造 program、help 配置、顶层 options/subcommands
preAction 屏障态 main.tsx program.hook('preAction', ...) action 前关键初始化与幂等副作用注入
migration 态 main.tsx runMigrations 版本迁移 + 异步迁移容错
action 启动编排态 main.tsx 默认 .action(...) 主体 setup、commands/agents 并发加载、模式分流前置
输入拼接态 main.tsx getInputPrompt TTY/pipe 输入统一，超时告警但不中断

4) End-to-end Flow（full CLI 主链）

4.1 main() 先做进程级保护，再进入 run()

src/main.tsx:main 早期设置：

process.env.NoDefaultCurrentDirectoryInExePath = '1'
initializeWarningHandler()
process.on('SIGINT', () => {
  if (process.argv.includes('-p') || process.argv.includes('--print')) return
  process.exit(0)
})

之后进入 Commander 主链。

4.2 run() 构造 program 与 help 排序策略

function createSortedHelpConfig() {
  const getOptionSortKey = (opt: Option) =>
    opt.long?.replace(/^--/, '') ?? opt.short?.replace(/^-/, '') ?? ''
  return Object.assign(
    { sortSubcommands: true, sortOptions: true } as const,
    { compareOptions: (a: Option, b: Option) => getOptionSortKey(a).localeCompare(getOptionSortKey(b)) },
  )
}

const program = new CommanderCommand()
  .configureHelp(createSortedHelpConfig())
  .enablePositionalOptions()

4.3 preAction：关键阻断初始化统一前置

program.hook('preAction', async thisCommand => {
  await Promise.all([ensureMdmSettingsLoaded(), ensureKeychainPrefetchCompleted()])
  await init()

  if (!isEnvTruthy(process.env.CLAUDE_CODE_DISABLE_TERMINAL_TITLE)) {
    process.title = 'claude'
  }

  const { initSinks } = await import('./utils/sinks.js')
  initSinks()

  const pluginDir = thisCommand.getOptionValue('pluginDir')
  if (Array.isArray(pluginDir) && pluginDir.length > 0 && pluginDir.every(p => typeof p === 'string')) {
    setInlinePlugins(pluginDir)
    clearPluginCache('preAction: --plugin-dir inline plugins')
  }

  runMigrations()
  void loadRemoteManagedSettings()
  void loadPolicyLimits()

  if (feature('UPLOAD_USER_SETTINGS')) {
    void import('./services/settingsSync/index.js').then(m => m.uploadUserSettingsInBackground())
  }
})

该链条把“必须阻断”与“可异步 fail-open”显式分层。

4.4 action 启动编排：setup 与命令加载并发（受 worktree gate）

const preSetupCwd = getCwd()
if (process.env.CLAUDE_CODE_ENTRYPOINT !== 'local-agent') {
  initBuiltinPlugins()
  initBundledSkills()
}

const setupPromise = setup(preSetupCwd, ...)
const commandsPromise = worktreeEnabled ? null : getCommands(preSetupCwd)
const agentDefsPromise = worktreeEnabled ? null : getAgentDefinitionsWithOverrides(preSetupCwd)
commandsPromise?.catch(() => {})
agentDefsPromise?.catch(() => {})
await setupPromise

const currentCwd = worktreeEnabled ? getCwd() : preSetupCwd
const [commands, agentDefinitionsResult] = await Promise.all([
  commandsPromise ?? getCommands(currentCwd),
  agentDefsPromise ?? getAgentDefinitionsWithOverrides(currentCwd),
])

这里的关键不是并发本身，而是 worktree 可能 chdir，所以并发有条件。

4.5 非交互路径提前应用环境并做上下文预取

if (getIsNonInteractiveSession()) {
  applyConfigEnvironmentVariables()
  void getSystemContext()
  void getUserContext()
  void ensureModelStringsInitialized()
}

print/headless 路径以“先环境一致，再预取优化”为策略。

4.6 stdin 处理是“可见降级”而非静默阻塞

src/main.tsx:getInputPrompt：

if (!process.stdin.isTTY && !process.argv.includes('mcp')) {
  ...
  const timedOut = await peekForStdinData(process.stdin, 3000)
  if (timedOut) {
    process.stderr.write('Warning: no stdin data received in 3s, proceeding without it...\n')
  }
  return [prompt, data].filter(Boolean).join('\n')
}

5) Guard / Decision Matrix

Guard 条件 行为 结果
preAction gate 任意 command action 执行 强制先跑 preAction 初始化顺序一致
mdm/keychain guard preAction 开始 Promise.all 等待预热 降低后续设置读取阻塞
sink attach guard subcommands 不走 setup preAction 中 initSinks() 避免事件静默丢失
plugin-dir propagation guard 顶层 --plugin-dir 存在 setInlinePlugins + clearPluginCache 子命令也能看到 inline plugins
migration version guard 版本不一致 runMigrations() + 保存新版本 启动期配置演进一致
remote-settings fail-open guard 远程设置/策略加载 void load... 不阻断主执行
worktree parallel guard worktreeEnabled 禁用 pre-setup commands 并发 避免 chdir 前后 cwd 不一致
stdin timeout guard 非 TTY 且无数据 3s 告警后继续 可见降级而非卡死
non-interactive env guard --print 等非交互 先 applyConfigEnvironmentVariables() git/path/env 语义一致

6) Failure / Recovery / Degradation

6.1 关键初始化失败是 fail-stop

preAction 内 init()、MDM/keychain 等待是阻断型；失败不应继续 action，避免半初始化执行。

6.2 远程管理设置与设置同步是 fail-open

loadRemoteManagedSettings / loadPolicyLimits / settings sync 均异步触发，不阻塞主命令路径。

6.3 迁移失败局部化

runMigrations() 中 migrateChangelogFromConfig().catch(() => {}) 明确“失败下次重试”，不拖垮启动。

6.4 并发加载的 rejection 被显式消音再 join

commandsPromise?.catch(() => {}) 与 agentDefsPromise?.catch(() => {}) 先抑制瞬时 unhandled，再在后续 Promise.all 统一收敛。

6.5 stdin 慢生产者退化为 warning

3 秒未见数据时提示并继续，不把 CLI 锁死在隐式管道等待。

7) Invariants

  1. program.hook('preAction', ...) 必须保持为 action 前统一屏障。
  2. initSinks() 必须在 preAction 中对所有子命令可达。
  3. --plugin-dir 的传播必须在 preAction 统一注入，而不是仅默认 action 可见。
  4. runMigrations() 必须在启动链稳定执行，并维持版本门闩。
  5. worktreeEnabled 时不得复用 pre-setup cwd 的命令并发加载结果。
  6. 非交互模式必须在关键 git/system 操作前应用配置环境变量。

8) Cross-module Contracts

  • 对 01：01 决定“是否进入 full CLI”，02 负责“进入后如何初始化”。
  • 对 03：02 产出已初始化的命令与代理上下文，03 负责 registry/slash 投影。
  • 对 04：02 只负责模式前置（print/headless 预取），不定义输出协议细节。
  • 对 plugin/MCP 子系统：02 只做启动期注入与刷新时机，不接管其内部解析与执行语义。

9) Engineering Constraints / Evolution Guidance

扩展启动流程时优先检查：

  1. 新步骤应放 preAction（阻断）还是 action（可并发/可延后）；
  2. 是否会破坏 worktree-chdir 前后的 cwd 一致性；
  3. 是否会让 subcommands 与默认 action 产生初始化不一致；
  4. 是否应 fail-open（后台任务）或 fail-stop（核心初始化）；
  5. 是否需要 profileCheckpoint 保持可观测。

建议回归：

  • preAction 触发顺序（MDM/keychain -> init -> sinks -> migrations）；
  • --plugin-dir 在 plugin/mcp/auth/doctor 子命令中的可见性；
  • worktree 模式下 commands/agents 加载正确 cwd；
  • non-interactive 的 env 应用 + git/system 预取；
  • stdin 超时 warning 路径。
