风险闭环：Auth / Policy / Refusal / Telemetry（深潜审计版）

1) Scope 与 Evidence Boundary

本页只覆盖客户端可证实的“风险相关执行闭环”：认证失效处理、策略阻断、模型 refusal 显示、遥测上报与本地状态清理。

证据范围：

  • src/utils/auth.ts
  • src/services/api/withRetry.ts
  • src/services/api/errors.ts
  • src/services/api/sessionIngress.ts
  • src/services/mcp/auth.ts
  • src/services/mcp/client.ts
  • src/bridge/trustedDevice.ts
  • src/bridge/bridgeApi.ts
  • src/bridge/remoteBridgeCore.ts
  • src/services/policyLimits/index.ts
  • src/services/remoteManagedSettings/*
  • src/services/analytics/sink.ts
  • src/services/analytics/firstPartyEventLoggingExporter.ts

不覆盖：

  • 服务端封禁评分模型；
  • 上游 moderation 具体判定算法。

2) Core Thesis

从客户端源码可证实的不是“本地封号引擎”，而是分布式阻断与恢复闭环：

  1. 认证失败会触发刷新/重试/清理；
  2. 组织策略可阻断能力面；
  3. refusal 由上游裁决，客户端负责语义投影；
  4. 关键失败会进入 telemetry 与可追踪状态。

3) Runtime State Ownership

状态类别 所有者 关键函数 职责
OAuth 认证态 auth.ts + withRetry.ts handleOAuth401Error / withRetry 401/403 revoked 刷新与恢复
API 错误语义态 errors.ts getAssistantMessageFromError / getErrorMessageIfRefusal 将上游错误映射为用户可读终态
MCP 重授权态 mcp/auth.ts + mcp/client.ts revokeServerTokens / wrapFetchWithStepUpDetection invalid_grant / insufficient_scope / needs-auth
bridge 高敏认证态 trustedDevice.ts + bridgeApi.ts enrollTrustedDevice trusted device 与 bridge 401/403/410 分流
policy 阻断态 policyLimits/index.ts isPolicyAllowed / loadPolicyLimits 组织策略能力门禁
telemetry 状态 analytics/sink.ts + 1P exporter initializeAnalyticsSink 事件扇出、失败落盘与回放

4) End-to-end Flow

  1. 请求阶段命中 withRetry / withOAuth401Retry；
  2. 遇到 401/403 revoked 时执行 token 失效处理与重试；
  3. 若仍失败，errors.ts 生成结构化用户态错误；
  4. MCP/Bridge 走各自认证恢复链（step-up、trusted-device、transport rebuild）；
  5. policy/managed settings 在能力面上进一步 gate；
  6. 关键事件经 sink 扇出到 Datadog/1P，并在失败时本地持久化重放。

5) Guard / Decision Matrix

Guard 条件 行为 结果
oauth retry guard 401 或 revoked 403 清缓存 + 刷新 + 一次重试 减少瞬时失效
organization gate org 不允许 OAuth/功能 显式拒绝 能力面 fail-stop
mcp invalid_grant guard refresh token 失效 清本地 token + re-auth 防无效循环刷新
mcp step-up guard insufficient_scope 触发交互式权限提升 权限提升可解释
trusted-device guard bridge 高敏能力 设备凭据校验/注册 限制远程滥用
policy guard policy 不允许 屏蔽特定能力 企业治理生效
refusal mapping guard stop_reason=refusal Usage Policy 终态文案 审核结果可见
telemetry failover guard 发送失败 本地队列落盘与回放 可观测性连续

6) Failure / Recovery / Degradation

6.1 认证失效恢复

  • 能恢复：刷新 token 后继续；
  • 不能恢复：进入 authentication_failed/token_revoked 等终态。

6.2 MCP 重授权退化

invalid_grant 或 needs-auth 命中后短路连接，等待显式 re-auth，避免无意义重试风暴。

6.3 Bridge 恢复

SSE 401 后重建 transport；恢复窗口中的控制帧丢弃，防旧会话污染新链路。

6.4 上报退化

上报异常时本地 JSONL 队列持久化，后续回放；业务链不被 telemetry 阻塞。

7) Invariants

  1. 客户端不做独立封号判决，只消费上游裁决信号。
  2. 认证失败必须有显式恢复或显式终态。
  3. MCP/Bridge 高敏路径必须额外门控。
  4. policy gate 必须早于能力执行。
  5. refusal 必须映射为可解释用户终态。
  6. telemetry 失败不能阻断主执行链。

8) Cross-module Contracts

  • 对 05：本页解释 MCP auth 闭环，不替代 MCP 生命周期主文。
  • 对 07：refusal 是流式终态之一，展示逻辑由 streaming/output 投影承接。
  • 对 09：bridge/auth gate 属 CLI 管理面入口，具体风险语义在本页统一。
  • 对 01：风险处理结果必须消息化，不得破坏主状态机收敛。

9) Engineering Constraints / Evolution Guidance

新增风险控制逻辑时需先明确：

  1. 属于认证恢复、策略阻断还是内容拒绝投影；
  2. fail-open / fail-stop 语义是否与现有链一致；
  3. 是否会产生无限重试或缓存污染；
  4. 是否补齐 telemetry 事件与脱敏字段。

建议回归：

  • OAuth 401/revoked 403 路径；
  • MCP invalid_grant + insufficient_scope + needs-auth 缓存；
  • bridge trusted-device 与 401 恢复重建；
  • policy allow/deny 场景；
  • refusal 终态文案与上报链。
