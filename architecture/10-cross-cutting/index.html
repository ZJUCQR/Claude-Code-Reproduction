Cross-cutting 运行专题（入口审计页）

1) Scope 与 Evidence Boundary

本页是 docs/architecture/10-cross-cutting 入口页，只负责跨模块专题的边界、导航与证据锚点。

覆盖主题：

  • KAIROS 持久助手与 Auto-Dream/Proactive 调度链
  • BUDDY 伴侣系统的确定性生成与命令面投影
  • Auth / Policy / Refusal / Telemetry 风险闭环

证据范围（模块级）：

  • src/main.tsx
  • src/bootstrap/state.ts
  • src/services/autoDream/*
  • src/utils/cron*.ts
  • src/buddy/*
  • src/services/api/errors.ts
  • src/services/api/withRetry.ts
  • src/services/mcp/auth.ts
  • src/bridge/trustedDevice.ts
  • src/services/policyLimits/index.ts
  • src/services/analytics/*

2) Core Thesis

10 模块处理的是“跨模块但高耦合”的运行专题：它们不属于单一子系统，却会同时影响 CLI、memory、streaming、安全与可观测性。

3) Runtime State Ownership

状态 所有者 说明
assistant 持久化态 main.tsx + bootstrap/state.ts KAIROS 激活、全局态传播
dream/proactive 调度态 services/autoDream/* + utils/cron*.ts 后台整合与周期任务
buddy 伴侣态 buddy/* 确定性生成、渲染、命令入口
风险闭环态 api/mcp/bridge/policy/analytics 认证失效、策略阻断、拒绝与上报

4) End-to-end Flow（高层）

  1. KAIROS/BUDDY/风险信号分别在本模块收敛为专题视图；
  2. 每个专题明确“状态所有者 -> guard -> 失败恢复 -> 跨模块契约”；
  3. 通过反向链接回到 01/02/05/07/08/09 对应主链。

5) Guard / Decision Matrix（入口级）

Guard 条件 行为 结果
feature gate 功能未开启 跳过专题分支 主链不受影响
safety gate 信任/认证/策略不满足 fail-stop 或降级 安全边界稳定
consistency gate 多来源状态不一致 缓存失效/重建 避免漂移
telemetry gate 上报受限 降级路径记录 可观测性尽量保留

6) Failure / Recovery / Degradation

  • 专题逻辑失败应局部化，不击穿 query 主链；
  • 高敏能力（bridge/MCP/auth）失败应显式 fail-stop；
  • UI/提示层失败允许降级到最小可用状态。

7) Invariants

  1. 跨模块专题不替代原模块主文。
  2. 每个专题必须给出可追溯源码锚点。
  3. 专题扩展不能破坏 01-09 的边界契约。
  4. 失败语义必须显式（fail-open/fail-stop）。

8) Cross-module Contracts

  • 对 01：消费执行主链，不重写 query 状态机。
  • 对 02：复用记忆系统，不接管 memory 生命周期。
  • 对 05/07/09：提供专题解释，不替代协议与入口定义。

9) Engineering Constraints / Evolution Guidance

新增 cross-cutting 专题时，必须先证明：

  1. 主题跨越至少两个核心模块；
  2. 在原模块中拆分会造成重复或语义断裂；
  3. 可提供独立的 guard/invariants/contracts。
