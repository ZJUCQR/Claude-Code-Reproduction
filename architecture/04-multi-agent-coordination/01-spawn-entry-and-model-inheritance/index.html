多 Agent 协同：Spawn 入口与模型继承（深潜审计版）

1) Scope 与 Evidence Boundary

本页覆盖“teammate 创建入口”与“模型/参数继承语义”，证据范围：

  • src/tools/shared/spawnMultiAgent.ts
  • src/utils/swarm/spawnUtils.ts
  • src/utils/swarm/teamHelpers.ts

不覆盖：

  • backend 探测细节（见 02）；
  • permission mailbox 协议（见 03）；
  • worktree 生命周期（见 04）。

2) Core Thesis

spawn 层不是“转发创建请求”，而是将松散输入收敛成稳定执行契约：

  1. inherit 等别名在入口层归一；
  2. explicit/auto 执行意图不混淆；
  3. teammate 身份、命令参数、团队持久态同轮建立；
  4. 失败时提供可行动分支（回退或报错）。

3) Runtime State Ownership

状态类别 所有者 关键函数 说明
模型继承态 spawnMultiAgent.ts resolveTeammateModel 归一 inherit 与默认模型
CLI 继承态 spawnMultiAgent.ts buildInheritedCliFlags 继承 leader 关键执行参数
spawn 分流态 spawnMultiAgent.ts handleSpawn* / handleSpawn in-process / split pane / separate window
启动命令态 spawnUtils.ts getTeammateCommand / buildInheritedEnvVars 生成执行命令与环境继承
团队持久态 teamHelpers.ts readTeamFileAsync / writeTeamFileAsync teammate 元数据落盘

4) End-to-end Flow

  1. spawnTeammate 收到 SpawnTeammateConfig；
  2. resolveTeammateModel 把 inherit/undefined 收敛为具体模型；
  3. buildInheritedCliFlags 生成子进程继承参数；
  4. handleSpawn 判定走 in-process 或 pane backend；
  5. 执行成功后同步更新 team 状态（成员、backend、identity）；
  6. 返回可追踪 agent_id 与 spawn 元信息给上层。
// src/tools/shared/spawnMultiAgent.ts
export function resolveTeammateModel(inputModel: string | undefined, leaderModel: string | null): string {
  if (inputModel === 'inherit') {
    return leaderModel ?? getDefaultTeammateModel(leaderModel)
  }
  return inputModel ?? getDefaultTeammateModel(leaderModel)
}

5) Guard / Decision Matrix

Guard 条件 动作 结果
model alias guard inputModel='inherit' 替换为 leader/default 模型 防字面值误传
explicit mode guard 非 auto 且后端异常 直接抛错 保持用户显式意图
auto fallback guard auto 且后端失败 走 in-process 可用性优先
input completeness guard 缺 name/prompt/team 拒绝 spawn 防悬空 teammate
identity guard 名称冲突/非法 unique + sanitize 保证 agent_id 可映射
plan-mode permission guard planModeRequired 抑制危险权限继承 防越权启动

6) Failure / Recovery / Degradation

6.1 探测失败分支

  • explicit 模式：surface 错误并终止；
  • auto 模式：受控退化至 in-process。

6.2 启动失败分支

  • spawn 结果 success=false：终止注册并返回失败；
  • 防止写入半成品 team 状态。

6.3 持久态写入失败

  • team 文件写失败：拒绝“只在内存存在”的 teammate，避免恢复链断裂。

6.4 参数继承失败

  • 若继承链不完整，回落默认模型/参数，不阻断主流程。

7) Invariants

  1. 每个 teammate 必须有稳定 agent_id + team_name。
  2. inherit 必须在入口层被解析，不得向下游泄漏。
  3. explicit 模式不得静默 fallback。
  4. spawn 成功后，内存态与持久态必须同轮可见。
  5. plan-mode 限制优先于便利型参数继承。
  6. 同名 teammate 处理必须可重复、可确定（唯一化规则固定）。

8) Cross-module Contracts

  • 对 02（backend）：01 输出“明确模式与参数”，02 负责执行后端最终选择。
  • 对 03（permission）：01 只建立身份与启动上下文，权限审批仍由 leader 通道决定。
  • 对 04（worktree）：01 不定义隔离目录策略，只消费其结果。
  • 对 query/tool 主循环：01 仅负责协同入口，不改工具语义。

9) Engineering Constraints / Evolution Guidance

新增 spawn 参数或模式时必须验证：

  1. 是否破坏 resolveTeammateModel 的确定性；
  2. 是否引入 explicit/auto 语义漂移；
  3. 是否影响 team 文件恢复能力；
  4. 是否在失败路径保持“无半状态写入”。

建议回归：

  • inherit / 指定模型 / 空模型；
  • auto fallback 与 explicit 报错；
  • 名称冲突下 identity 稳定性；
  • 启动失败时 team 状态无脏写。
