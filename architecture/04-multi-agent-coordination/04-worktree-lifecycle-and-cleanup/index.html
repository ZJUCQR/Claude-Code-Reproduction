多 Agent 协同：Worktree 生命周期与清理（深潜审计版）

1) Scope 与 Evidence Boundary

本页覆盖“协同隔离目录生命周期”与“退出/超时清理收敛”，证据范围：

  • src/utils/worktree.ts
  • src/bridge/bridgeMain.ts
  • src/bridge/bridgePointer.ts
  • src/bridge/capacityWake.ts

不覆盖：

  • spawn 输入归一与后端探测（见 01/02）；
  • permission mailbox 协议（见 03）。

2) Core Thesis

worktree 机制的价值不止“隔离改动目录”，而是确保多 agent 执行在结束时可安全收敛：

  1. create/resume 路径可追踪；
  2. keep/cleanup 行为可控；
  3. stale 回收默认 fail-closed；
  4. bridge done/timeout 都能执行一致收尾。

3) Runtime State Ownership

状态类别 所有者 关键函数/字段 说明
会话 worktree 态 worktree.ts getCurrentWorktreeSession / restoreWorktreeSession 当前会话绑定上下文
创建/保留/清理态 worktree.ts createWorktreeForSession / keepWorktree / cleanupWorktree session 生命周期主路径
agent 临时 worktree 态 worktree.ts createAgentWorktree / removeAgentWorktree 子执行单元隔离目录
stale 回收态 worktree.ts cleanupStaleAgentWorktrees / hasWorktreeChanges 周期安全回收
退出收尾态 bridgeMain.ts runBridgeLoop / onSessionDone / onSessionTimeout 会话结束/超时终止
指针一致性态 bridgePointer.ts writeBridgePointer / clearBridgePointer 活跃会话指针管理
容量唤醒态 capacityWake.ts createCapacityWake 释放资源后唤醒调度

4) End-to-end Flow

  1. 需要隔离执行时，createWorktreeForSession 校验 slug 并创建/恢复会话 worktree；
  2. 子 agent 可通过 createAgentWorktree 创建临时目录；
  3. 运行期间根据状态可 keepWorktree（保留）或 cleanupWorktree（清理）；
  4. 周期性 cleanupStaleAgentWorktrees 对可安全删除的遗留目录做回收；
  5. bridge 在 onSessionDone 或 onSessionTimeout 触发统一收尾，含指针与资源释放。

5) Guard / Decision Matrix

Guard 条件 动作 结果
slug guard 非法 slug 拒绝创建 防路径注入
hook preference guard 配置 create/remove hook 优先 hook 支持 VCS 非 git 实现
dirty guard hasWorktreeChanges=true 禁止自动删 防误删未提交改动
unpushed guard 存在未推送提交 跳过 stale 删除 防丢失本地提交
ephemeral pattern guard 不匹配受控 slug 跳过清理 防误扫用户自命名目录
keep vs cleanup guard 用户选择 keep 仅解绑会话 保留现场
timeout guard 会话超时 走 onSessionTimeout 保证终止收尾
shutdown idempotency guard 重复结束信号 幂等短路 防重复删除/终止

6) Failure / Recovery / Degradation

6.1 创建失败

  • 非 git 且无 hook：返回明确配置错误；
  • 不进入半初始化 session 状态。

6.2 清理失败

  • 删除目录/分支失败：记录错误并保留现场；
  • 避免“删一半”的不可恢复状态。

6.3 stale 回收失败

  • 任一步 git 命令失败：跳过该条目（fail-closed）；
  • 清理任务继续处理其它条目。

6.4 bridge 收尾失败

  • onSessionDone/onSessionTimeout 中单项清理失败不应阻断其余收尾；
  • 指针清理失败需可观测，防后续误判活跃会话。

6.5 容量恢复退化

  • 即使部分清理失败，也应尽力唤醒容量调度，避免系统长期“假满载”。

7) Invariants

  1. worktree 创建前必须通过 slug 校验。
  2. session worktree 与 agent worktree 生命周期不得互相污染。
  3. 自动清理默认 fail-closed（有疑问就不删）。
  4. 删除前必须检查 dirty 与 unpushed 双条件。
  5. keep/cleanup 必须是显式分支，不得隐式覆盖。
  6. bridge done 与 timeout 都必须走可重复、可收敛的终止路径。
  7. 指针状态必须与实际会话生命周期一致。

8) Cross-module Contracts

  • 对 01/02：worktree 只负责目录隔离，不决定 spawn/backend 策略。
  • 对 03：会话清理必须与 team/task 清理协同，避免孤儿成员。
  • 对 bridge 调度层：退出时释放资源后应触发容量恢复信号。
  • 对 git/worktree 命令层：遵守同一安全删除约束，不绕过检查。

9) Engineering Constraints / Evolution Guidance

新增清理或隔离能力时必须验证：

  1. 是否破坏 keep/cleanup 显式语义；
  2. 是否绕过 dirty/unpushed 安全门；
  3. 是否在 timeout 路径仍可幂等执行；
  4. 是否能在 pointer/容量状态上完整收尾。

建议回归：

  • create/resume/keep/cleanup 全链；
  • dirty、unpushed、ephemeral pattern 组合；
  • stale 回收多条目部分失败；
  • bridge done/timeout 双分支与 pointer 清理一致性。
