流式处理（入口审计页）

1) Scope 与 Evidence Boundary

本页是 docs/architecture/07-streaming-processing 的入口页，只负责模块边界、阅读顺序与页面所有权，不承载 streaming 机制深潜。

证据边界覆盖：

  • src/services/api/claude.ts
  • src/utils/messages.ts
  • src/cli/structuredIO.ts
  • src/cli/transports/*.ts
  • src/services/tools/StreamingToolExecutor.ts
  • src/query.ts
  • src/screens/REPL.tsx
  • src/components/Messages.tsx

2) Core Thesis

07 模块是“实时语义投影层”：把模型流、控制请求、transport 重放与工具执行进度压缩成可关联、可恢复、可渲染的统一流。

目标不是“更快打印”，而是“更快时仍不乱语义”。

3) Runtime State Ownership

状态 所有者 说明
stream event 装配态 claude.ts + messages.ts delta 到最终消息状态
request correlation 态 structuredIO.ts pending request / duplicate suppression
transport 态 ccrClient.ts + HybridTransport.ts buffering / replay / reconnect
tool 背压态 StreamingToolExecutor.ts streamed tool queue 与错误传播
渲染投影态 REPL.tsx + Messages.tsx streamingText/thinking/toolUses UI 投影

4) End-to-end Flow（高层）

  1. 模型流被解析为 stream events。
  2. 事件被装配成消息状态并进入 StructuredIO/transport。
  3. transport 负责 flush、重连、重放与顺序保证。
  4. streamed tool use 进入 executor 并产出进度/结果。
  5. CLI/REPL/UI 将其投影为最终可见输出。

5) Guard / Decision Matrix（入口级）

Guard 条件 行为 结果
incomplete stream guard 无有效 assistant 输出 fallback 保持可用性
duplicate/orphan guard response 无法正常关联 忽略/清理 保持协议幂等
replay guard buffered stream_event 未 flush 先 flush 再写 保持顺序
tool concurrency guard exclusive vs concurrency-safe 串行/并行 背压稳定
refusal/stop guard refusal/max_output/context-window 进入可解释终态 防静默失败
render mode guard live/static/transcript 选择投影视图 UX 一致

6) Failure / Recovery / Degradation

  • stream 中断：按 fallback/abort/error 分支恢复或终止。
  • duplicate/late response：通过 correlation ledger 吸收。
  • transport 失败：按 replay/reconnect 路径恢复，失败则显式关闭。
  • tool sibling error：通过 synthetic terminal state 收敛。
  • UI 退化：即使 overlay/progress 缺失，也保留最终结果可观测。

7) Invariants

  1. stream 语义必须先装配再渲染。
  2. control 与 content 消息共享顺序保证。
  3. duplicate 响应不得重新进入业务处理。
  4. streamed tool 必须有终态。
  5. fallback/reconnect 不能制造重复语义。
  6. 输出模式变化不能改变事件语义。

8) Cross-module Contracts

  • 对 query/tool 主链：07 只做实时投影与恢复，不改业务语义。
  • 对 05/06：控制消息与 hook/MCP 结果共享关联与顺序约束。
  • 对 CLI/UI：显示模式可变，但语义必须一致。
  • 对 transport：delivery retry 不得破坏 semantic dedupe。

9) Engineering Constraints / Evolution Guidance

扩展 streaming 时必须验证：

  1. 新事件是否进入统一装配器；
  2. 新 request 类型是否具备关联/取消/去重语义；
  3. 新 transport 是否满足 flush/replay 顺序保证；
  4. 新 executor/UI 状态是否仍可稳定收敛。
