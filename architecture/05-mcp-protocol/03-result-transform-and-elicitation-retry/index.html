MCP 协议：结果转换与 Elicitation 重试（深潜审计版）

1) Scope 与 Evidence Boundary

本页覆盖“MCP 调用后半链路”：tool call、URL elicitation 协商重试、结果规范化、大输出处理。

证据范围：

  • src/services/mcp/client.ts
  • src/utils/mcpValidation.ts
  • src/utils/mcpOutputStorage.ts

不覆盖：

  • 连接建立与鉴权（见 01）；
  • discovery 映射（见 02）；
  • CLI/UI 管理与审批面（见 04）。

2) Core Thesis

03 页的目标是确保“调用结果可被主链安全消费”：

  1. URL 协商具备 accept/decline/cancel 一等分支；
  2. 重试有上界，避免协议级死循环；
  3. 异构返回必须先 transform 再 process；
  4. 大输出通过 truncate/persist 保护上下文预算。

3) Runtime State Ownership

状态类别 所有者 关键函数 说明
调用执行态 client.ts callMCPTool 执行 RPC 调用与错误类型收敛
URL 协商态 client.ts callMCPToolWithUrlElicitationRetry -32042 协商、用户动作、有限重试
结果转换态 client.ts transformMCPResult toolResult/structured/contentArray 归一
结果后处理态 client.ts processMCPResult 大输出策略分支与最终内容生成
预算判定态 mcpValidation.ts getMaxMcpOutputTokens / mcpContentNeedsTruncation / truncateMcpContentIfNeeded token/体积阈值判定
持久化态 mcpOutputStorage.ts getLargeOutputInstructions / persistBinaryContent / isBinaryContentType 超大与二进制内容外置

4) End-to-end Flow

  1. 调用入口执行 callMCPTool；
  2. 若抛 UrlElicitationRequired，进入 callMCPToolWithUrlElicitationRetry；
  3. accept 分支重试调用，decline/cancel 分支直接返回解释性内容；
  4. 调用成功后 transformMCPResult 统一结构；
  5. processMCPResult 根据预算执行直传/截断/落盘指引；
  6. 返回主链可消费结果。
// src/services/mcp/client.ts
export async function callMCPToolWithUrlElicitationRetry({...}): Promise<MCPToolCallResult> {
  const MAX_URL_ELICITATION_RETRIES = 3
  for (let attempt = 0; ; attempt++) {
    try {
      return await callToolFn({...})
    } catch (error) {
      if (!(error instanceof McpError) || error.code !== ErrorCode.UrlElicitationRequired) throw error
      if (attempt >= MAX_URL_ELICITATION_RETRIES) throw error
      ...
    }
  }
}

5) Guard / Decision Matrix

Guard 条件 动作 结果
elicitation trigger guard McpError + UrlElicitationRequired 进入 URL 协商流程 协议级交互闭环
retry bound guard attempt >= MAX_RETRIES 停止重试并失败 防无限循环
user-action guard action 非 accept 返回解释性内容 保留用户否决权
transform shape guard 非预期结果结构 抛 TelemetrySafeError 防脏结果上行
output budget guard 内容超阈值 truncate/persist 路径 保护上下文
binary guard 二进制 content-type persistBinaryContent 防 raw binary 入模
ide bypass guard IDE 特定路径 跳过部分大输出策略 保持 IDE 语义一致

6) Failure / Recovery / Degradation

6.1 协商失败链

  • URL 协商异常仅在 -32042 分支处理；
  • 非协商异常直接抛出，避免错误吞噬。

6.2 用户拒绝链

  • decline/cancel 不再重试；
  • 返回可解释文本，主链可继续。

6.3 结果结构异常链

  • transform 阶段抛 TelemetrySafeError；
  • 阻止不确定结构进入模型上下文。

6.4 大输出退化链

  • 超阈值时优先按策略截断或落盘；
  • 落盘失败可退化为截断提示，保持可解释输出。

6.5 二进制内容链

  • 二进制检测命中后持久化并返回引用；
  • 避免把不可读内容直接传给模型。

7) Invariants

  1. URL elicitation 必须有 accept/decline/cancel 三类终态。
  2. 重试必须有固定上界。
  3. 结果必须先 transform 再 process。
  4. 非法结果结构不得上送模型。
  5. 大输出治理必须优先保护上下文预算。
  6. 二进制内容不得以原始 payload 形式进入模型。

8) Cross-module Contracts

  • 对 01：03 假定连接守卫可用，不重复定义建连语义。
  • 对 02：03 消费 discovery 投影后的 tool metadata 与命名。
  • 对 04：03 的 elicitation 与输出策略需被 UI/CLI 正确展示与控制。
  • 对主链：03 输出统一结果协议，避免把 MCP 私有错误散布到上层。

9) Engineering Constraints / Evolution Guidance

新增返回类型或协商机制时必须验证：

  1. 是否可映射进 transformMCPResult 统一结构；
  2. 是否仍保留用户拒绝路径；
  3. 是否遵守重试上界；
  4. 是否在大输出与二进制分支保持预算安全。

建议回归：

  • UrlElicitationRequired 的 accept/decline/cancel；
  • retry-limit 命中；
  • transform 三种主结构（toolResult/structured/contentArray）；
  • truncate 与 persist-large-output 双分支；
  • 二进制输出持久化分支。
