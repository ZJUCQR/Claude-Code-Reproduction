Agent / HTTP / Prompt Hook 执行器（深潜审计版）

1) Scope 与 Evidence Boundary

本页覆盖“Hook 执行协议层”：command/prompt/agent/http/function/callback 的执行语义、输入输出协议、超时/取消/格式校验。

证据范围：

  • src/utils/hooks.ts
  • src/utils/hooks/execPromptHook.ts
  • src/utils/hooks/execAgentHook.ts
  • src/utils/hooks/execHttpHook.ts
  • src/utils/hooks/AsyncHookRegistry.ts

不覆盖：

  • 配置来源与 matcher 选择（见 01）；
  • permission/tool 决策桥接（见 03）；
  • session/file watcher/progress UX（见 04）。

2) Core Thesis

执行协议层的职责不是“多支持几种 hook 类型”，而是把多样执行方式统一成标准 HookResult：

  1. command/prompt/agent/http 都必须走统一聚合模型；
  2. sync/async/asyncRewake/forceSyncExecution 语义可解释；
  3. JSON/schema/exit code/allowlist/abort 失败分支必须收敛；
  4. Agent hook 必须内建反递归与强制终止约束。

3) Runtime State Ownership

状态类别 所有者 关键函数 说明
command 协议态 hooks.ts execCommandHook / parseHookOutput / processHookJSONOutput stdin/stdout/exit-code 协议
prompt 协议态 execPromptHook.ts execPromptHook / addArgumentsToPrompt LLM prompt + schema 输出
agent 协议态 execAgentHook.ts execAgentHook / createStructuredOutputTool / registerStructuredOutputEnforcement 多轮 agent + 强制结构化输出
http 协议态 execHttpHook.ts execHttpHook allowlist/proxy/SSRF/response 校验
异步调度态 AsyncHookRegistry.ts async hook 背景执行与完成事件 async / asyncRewake
统一分发态 hooks.ts executeHooksOutsideREPL 按 type 路由并回收统一结果

4) End-to-end Flow

  1. 上层 executeHooks 选中 hook 集合；
  2. executeHooksOutsideREPL 按 hook type 分发到具体 exec*；
  3. 各执行器运行协议特定逻辑（shell/stdout、prompt schema、agent turns、HTTP POST）；
  4. 输出经 parseHookOutput / schema 校验 / structured-output enforcement 收敛；
  5. 最终统一返回 success / blocking / non_blocking_error / cancelled 等 HookResult。
// src/utils/hooks/execAgentHook.ts
const MAX_AGENT_TURNS = 50
registerStructuredOutputEnforcement(toolUseContext.setAppState, hookAgentId)

5) Guard / Decision Matrix

Guard 条件 动作 结果
type dispatch guard command/prompt/agent/http/function/callback 路由对应执行器 协议隔离
sync mode guard sync vs async vs asyncRewake 立即执行或登记后台 执行节奏稳定
forceSyncExecution guard hook 要求强同步 阻止异步漂移 保持顺序语义
command exit guard exit code 0 / 2 / other success / blocking / error shell 结果可解释
JSON/schema guard stdout/response 非法 non_blocking_error 或 blocking 防脏输出上行
agent max-turns guard turnCount 超限 abort + cancelled 防递归失控
HTTP allowlist guard URL 不匹配 policy 直接失败 防任意出网
abort/timeout guard combined signal 触发 cancelled/局部结束 防长时间挂起

6) Failure / Recovery / Degradation

6.1 command hook 失败链

  • stdin 写入、stdout JSON 解析、schema 校验、exit code 非零均收敛为标准结果；
  • EPIPE、abort、bad JSON 不应抛穿主链。

6.2 prompt hook 失败链

  • 非 JSON/schema mismatch -> non_blocking_error；
  • ok=false -> blocking；
  • aborted -> cancelled。

6.3 agent hook 失败链

  • 未返回 structured output 或超轮次 -> cancelled；
  • 其它异常 -> non_blocking_error；
  • 成功时必须产出结构化响应。

6.4 http hook 失败链

  • allowlist 未命中 -> 立即失败；
  • 超时/abort/network/non-2xx -> 标准失败结果；
  • 不隐式重试，由上层事件语义决定是否再次触发。

7) Invariants

  1. 所有执行器都必须输出统一 HookResult。
  2. Hook 执行不得直接改写主消息流。
  3. timeout/abort 语义必须由中央入口统一约束。
  4. Agent hook 必须有强制终止与结构化输出约束。
  5. HTTP hook 必须经过 allowlist/SSRF/proxy 安全门。
  6. 非法 JSON/schema 不得被视作成功结果。

8) Cross-module Contracts

  • 对 01：02 只消费 matcher 结果，不定义来源优先级。
  • 对 03：02 只输出 HookResult，不决定这些结果如何参与权限裁决。
  • 对 04：02 可产生 progress/attachments，但不负责最终渲染策略。
  • 对主链：02 必须把多种协议差异压平，避免调用侧理解六套返回模型。

9) Engineering Constraints / Evolution Guidance

新增 hook 协议时必须验证：

  1. 是否接入统一 timeout/abort 机制；
  2. 是否输出统一 HookResult；
  3. 是否对非法输出做 schema/shape 校验；
  4. 是否具备与现有协议等价的失败降级语义。

建议回归：

  • command exit code 0/2/other；
  • prompt schema success/failure；
  • agent structured-output missing/max-turns；
  • HTTP allowlist/network/non-2xx；
  • async / asyncRewake / forceSyncExecution 分支。
