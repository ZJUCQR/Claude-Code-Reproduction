记忆系统：文件写入、Forked 执行与时效（深潜审计版）

1) Scope 与 Evidence Boundary

本页聚焦 memory 写侧安全边界与一致性语义，证据范围：

  • src/services/SessionMemory/sessionMemory.ts
  • src/services/extractMemories/extractMemories.ts
  • src/utils/forkedAgent.ts
  • src/memdir/memoryAge.ts
  • src/memdir/findRelevantMemories.ts

不覆盖：

  • 触发阈值细节（见 02）；
  • gate/观测总收敛（见 04）。

2) Core Thesis

写侧治理的核心不是“写进去”，而是“三件事同时成立”：

  1. 权限必须精确收敛（只写允许的 memory 路径）；
  2. 执行必须上下文隔离（forked agent 不污染主线程状态）；
  3. 时效必须显式化（旧记忆要带 stale 语义）。

这三条决定了 memory 系统是否会从“增强能力”变成“隐形风险源”。

3) Runtime State Ownership

状态类别 所有者 关键机制 说明
单文件写权限 sessionMemory.ts createMemoryFileCanUseTool(memoryPath) 仅允许 Edit 指定文件
目录级写权限 extractMemories.ts createAutoMemCanUseTool(memoryDir) 允许受限 read/write 工具集合
forked 执行隔离态 sessionMemory.ts + forkedAgent.ts createSubagentContext + overrides.readFileState 避免主上下文 read cache 污染
写入游标推进 extractMemories.ts lastMemoryMessageUuid 成功后推进，失败不推进
时效状态 memoryAge.ts mtimeMs -> memoryAgeDays/freshness 将陈旧风险转译为文本提示

4) End-to-end Flow

4.1 SessionMemory 单文件限权写入

// src/services/SessionMemory/sessionMemory.ts
export function createMemoryFileCanUseTool(memoryPath: string): CanUseToolFn {
  return async (tool: Tool, input: unknown) => {
    if (
      tool.name === FILE_EDIT_TOOL_NAME &&
      typeof input === 'object' &&
      input !== null &&
      'file_path' in input
    ) {
      const filePath = input.file_path
      if (typeof filePath === 'string' && filePath === memoryPath) {
        return { behavior: 'allow' as const, updatedInput: input }
      }
    }
    return {
      behavior: 'deny' as const,
      message: `only ${FILE_EDIT_TOOL_NAME} on ${memoryPath} is allowed`,
      decisionReason: { type: 'other' as const, reason: ... },
    }
  }
}

4.2 extractMemories 目录级受限执行

runExtraction() 通过 createAutoMemCanUseTool(memoryDir) 赋予 forked agent 受限工具能力；并在已检测到主会话直接写 memory 时 skip fork，避免重复提取。

4.3 trailing coalescing（写侧并发治理）

// src/services/extractMemories/extractMemories.ts
if (inProgress) {
  pendingContext = { context, appendSystemMessage }
  return
}

await runExtraction({ context, appendSystemMessage })

// finally
const trailing = pendingContext
pendingContext = undefined
if (trailing) {
  await runExtraction({ context: trailing.context, isTrailingRun: true })
}

4.4 时效输出

// src/memdir/memoryAge.ts
export function memoryFreshnessText(mtimeMs: number): string {
  const d = memoryAgeDays(mtimeMs)
  if (d <= 1) return ''
  return (
    `This memory is ${d} days old. ` +
    `Memories are point-in-time observations, not live state — ` +
    `claims about code behavior or file:line citations may be outdated. ` +
    `Verify against current code before asserting as fact.`
  )
}

5) Guard / Decision Matrix

Guard 条件 动作 结果
Session 文件写入 tool=Edit 且 file_path===memoryPath allow 单文件可写
Session 文件写入 非上述条件 deny fail-closed
extract direct-write 互斥 hasMemoryWritesSince(...) skip fork + 推进 cursor 避免重复提取
extract 重入 inProgress=true stash latest pending 合并多次触发
trailing 执行 finally 检测 pending 运行 trailing run 补齐新增区间
stale 提示 memoryAgeDays > 1 注入 freshness 文本 提醒复核当前代码
fresh 记忆 memoryAgeDays <= 1 无 stale 警告 降低噪音

6) Failure / Recovery / Degradation

6.1 权限拒绝链：拒绝优先于模糊写入

createMemoryFileCanUseTool deny 非目标路径，确保“要么合法写入，要么明确失败”。

6.2 forked 抽取失败链：best-effort

runExtraction catch 仅日志与埋点，不将失败上抛主循环。

6.3 重入恢复链：pending 覆盖旧值

进行中重入只保留最新 pendingContext；当前 run 结束后 trailing 补跑，避免 N 次触发导致 N 次并发写。

6.4 时效恢复链：文本层风险提示

旧记忆不会被自动删；通过 freshness note 把“需验证当前状态”前置给模型。

6.5 读缓存污染恢复

SessionMemory 写前使用 createSubagentContext 与独立 readFileState，防止主 context dedup/cache 误判。

7) Invariants

  1. SessionMemory 写权限必须是“单文件 Edit”最小集合。
  2. extractMemories 写权限必须受 memoryDir 约束。
  3. forked agent 不能污染主线程 read/write 缓存状态。
  4. inProgress 重入必须 coalesce，不能并发写同一 memory 区间。
  5. cursor 只在成功或显式 skip（direct write）后推进。
  6. trailing run 只能补新增区间，不能回放全历史。
  7. stale 记忆必须有显式风险文本，不得默默当实时事实。
  8. 写侧失败不能击穿主会话响应路径。

8) Cross-module Contracts

  • 对 01（tool 权限执行）：memory 写入策略通过统一 canUseTool 接口落地，不建旁路权限系统。
  • 对 02（session extraction）：02 决定“何时写”；本页定义“写时如何安全”。
  • 对 04（gates/observability）：本页产生拒绝、coalesce、error 事件信号，04 统一可观测解释。
  • 对 prompt 注入（01 子页）：写侧产生的 mtime 最终影响 freshness 提示。

9) Engineering Constraints / Evolution Guidance

新增写入工具或放宽权限前必须回答：

  1. 是否仍满足最小权限原则？
  2. 是否会破坏 direct-write 互斥逻辑？
  3. 是否会让 trailing run 不可预测（乱序/重复）？
  4. 是否保留 stale 提示链路？

建议回归：

  • 非目标路径写入（应拒绝）；
  • inProgress 期间多次触发（应 coalesce）；
  • direct-write 检测命中（应 skip fork）；
  • 旧记忆文件召回（应带 freshness 提示）；
  • forked extraction 异常（主链继续）。
