    记忆系统：加载与 Prompt 注入（深潜审计版）

    1) Scope 与 Evidence Boundary

    本页仅覆盖 memory 读侧注入链，证据范围：

    • src/memdir/memdir.ts
    • src/memdir/findRelevantMemories.ts
    • src/memdir/memoryAge.ts
    • src/constants/prompts.ts
    • src/QueryEngine.ts

    本页不覆盖：

    • SessionMemory 写侧抽取（见 02）；
    • extractMemories 后台整理（见 03）；
    • gate 与观测总收敛（见 04）。

    2) Core Thesis

    loadMemoryPrompt() 的核心职责不是“拼一段提示词”，而是：

    1. 按 feature/env/settings 做 可解释分流；
    2. 在注入前保障目录存在，避免模型先做无意义目录探测；
    3. 在禁用场景返回 null，保证主链可降级；
    4. 把“记忆可过期”语义注入消费侧，避免把记忆当实时真值。

    这是一条“注入可选、语义可控、失败可退化”的读路径。

    3) Runtime State Ownership

    状态类别 所有者 关键字段/函数 说明
    注入开关状态 memdir.ts isAutoMemoryEnabled() / TEAMMEM / KAIROS 决定注入分支
    注入文本结构 memdir.ts buildMemoryLines / buildMemoryPrompt 决定记忆类型学与保存规则
    相关记忆选择 findRelevantMemories.ts findRelevantMemories / sideQuery 从 memory headers 选最多 5 条
    时效提示状态 memoryAge.ts memoryAgeDays / memoryFreshnessText 记忆陈旧性显式化
    上游注入调用点 prompts.ts, QueryEngine.ts systemPromptSection('memory', ...) / loadMemoryPrompt() 接入 system prompt

    4) End-to-end Flow

    4.1 上游触发

    prompts.ts 与 QueryEngine.ts 在组装系统提示时调用 loadMemoryPrompt()，将返回值（string | null）作为 memory section。

    4.2 分流与目录保障

    // src/memdir/memdir.ts
export async function loadMemoryPrompt(): Promise<string | null> {
  const autoEnabled = isAutoMemoryEnabled()

  if (feature('KAIROS') && autoEnabled && getKairosActive()) {
    return buildAssistantDailyLogPrompt(skipIndex)
  }

  if (feature('TEAMMEM')) {
    if (teamMemPaths!.isTeamMemoryEnabled()) {
      await ensureMemoryDirExists(teamDir)
      return teamMemPrompts!.buildCombinedMemoryPrompt(...)
    }
  }

  if (autoEnabled) {
    await ensureMemoryDirExists(autoDir)
    return buildMemoryLines('auto memory', autoDir, ...).join('\n')
  }

  logEvent('tengu_memdir_disabled', ...)
  return null
}

    4.4 陈旧性提示

    memoryFreshnessText(mtimeMs) 将 “>1 天” 的记忆加上 stale 提醒，降低“旧事实冒充新事实”的风险。

    5) Guard / Decision Matrix

    Guard 条件 动作 结果
    KAIROS 优先分支 feature('KAIROS') && autoEnabled && getKairosActive() 走 daily-log prompt 与普通 MEMORY.md 语义互斥
    TEAMMEM 联合分支 feature('TEAMMEM') && isTeamMemoryEnabled() ensure team dir + combined prompt auto/team 联合注入
    auto memory 启用 autoEnabled ensure auto dir + buildMemoryLines 单目录注入
    全部禁用 非以上条件 记录 tengu_memdir_disabled 返回 null
    相关记忆选择失败 sideQuery 异常/abort 返回空数组 主链继续
    freshness 判定 memoryAgeDays <= 1 无提示 降低噪声
    freshness 判定 memoryAgeDays > 1 输出 stale 文本 提醒“需回读当前代码”

    6) Failure / Recovery / Degradation

    6.1 注入禁用/失败：返回 null 而非抛错

    loadMemoryPrompt() 在禁用路径返回 null，上游可安全拼装其它 prompt section，避免 memory 成单点故障。

    6.2 目录保障失败：仅影响 memory 能力，不劫持主链

    ensureMemoryDirExists 失败会有日志；系统仍可在“无 memory 注入”语义下继续。

    6.3 相关性选择失败：退化为空召回

    findRelevantMemories 在 sideQuery 异常时返回 []，这是 fail-open 策略：牺牲召回，不牺牲可用性。

    6.4 stale 风险恢复：文本级自纠偏

    memoryFreshnessText 以系统提示方式强调“记忆是时点观察”，避免模型把 file:line 旧引用当实时事实。

    7) Invariants

    1. 注入函数对上游契约必须保持 Promise<string | null>。
    2. KAIROS daily-log 与 TEAMMEM/MEMORY.md 索引语义不能混用。
    3. memory 注入禁用时不得抛穿主链异常。
    4. 相关记忆筛选失败必须退化为“空集合”而非中断。
    5. freshness 提示必须依赖文件时间戳而非模型猜测。
    6. 构建器（buildMemoryPrompt）只读，不在内部隐式 mkdir。
    7. memory 指令必须持续声明“历史记忆 ≠ 当前真值”。

    8) Cross-module Contracts

    • 对 01（query/tool 执行）：memory prompt 是可选输入片段，不改变工具事务语义。
    • 对 03（compact）：压缩可变消息体积，但不应破坏 memory 注入分支可用性。
    • 对 02/03 子页：本页只定义读侧注入契约，不定义写侧提取与落盘流程。
    • 对 UI/transport：memory section 是语义文本，不应被 transport 改写为强约束命令。

    9) Engineering Constraints / Evolution Guidance

    新增注入策略时优先检查：

    1. 是否引入了新的不可降级依赖（若是，需补 fallback）；
    2. 是否改变了 TEAMMEM/KAIROS 分支优先级；
    3. 是否保持 null 退化语义；
    4. 是否为 stale 记忆留了显式提示。

    建议回归：

    • auto disabled；
    • auto enabled；
    • TEAMMEM enabled；
    • KAIROS active；
    • sideQuery abort/failure；
    • stale 与 fresh 文件混合召回。
