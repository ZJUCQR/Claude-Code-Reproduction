    Skill 发现、加载与索引（深潜审计版）

    1) Scope 与 Evidence Boundary

    本页只覆盖 08 模块里“技能如何从文件系统与配置源进入统一命令抽象”这一层：

    • 目录发现与上行边界
    • Markdown/frontmatter 解析与字段归一
    • 技能命令对象构造
    • conditional/dynamic 技能激活
    • file watcher 触发的缓存失效与刷新

    证据边界（逐文件）：

    • src/skills/loadSkillsDir.ts
    • src/utils/frontmatterParser.ts
    • src/utils/markdownConfigLoader.ts
    • src/utils/skills/skillChangeDetector.ts
    • src/hooks/useSkillsChange.ts

    不覆盖：

    • SkillTool validate/permission/call（见 02）
    • slash 入口与 fork 执行（见 03）
    • bundled/plugin/MCP 来源 taxonomy（见 04）

    2) Core Thesis

    这一层的本质不是“扫目录+读 md”，而是把高度脏乱的输入面压平为下游可消费的稳定 command facts：

    1. 来源收敛：managed/user/project/additional/legacy/dynamic 必须被并轨；
    2. 语义收敛：frontmatter 必须被宽容解析，并映射到确定字段；
    3. 可见性收敛：paths 条件技能不直接暴露，而是先 dormant、后激活；
    4. 刷新收敛：变更检测只清该清的缓存，避免 stale command surface。

    如果这里失真，后面的 getCommands() / getSkillToolCommands() / slash / SkillTool 都会收到彼此不一致的技能事实源。

    3) Runtime State Ownership

    状态类别 所有者 关键函数 职责
    文件身份态 loadSkillsDir.ts getFileIdentity 物理文件去重（防 symlink/重叠目录重复暴露）
    frontmatter 解析态 frontmatterParser.ts parseFrontmatter, quoteProblematicValues YAML 容错解析，失败局部降级
    字段归一态 loadSkillsDir.ts parseSkillFrontmatterFields, parseSkillPaths frontmatter -> command 可执行字段
    command 构造态 loadSkillsDir.ts createSkillCommand 固化为 type:'prompt' 统一命令对象
    条件技能态 loadSkillsDir.ts conditionalSkills, activateConditionalSkillsForPaths 路径命中前不暴露
    动态技能态 loadSkillsDir.ts dynamicSkills, getDynamicSkills, addSkillDirectories 运行期增量发现与注入
    目录发现态 markdownConfigLoader.ts resolveStopBoundary, getProjectDirsUpToHome 向上扫描边界控制（git/worktree）
    刷新传播态 skillChangeDetector.ts, useSkillsChange.ts scheduleReload, useSkillsChange 文件变化 -> 清缓存 -> 通知 UI

    4) End-to-end Flow

    4.1 目录上行边界先被收敛

    resolveStopBoundary() 避免“误把 nested git repo 当最终边界”导致上层 .claude/skills 丢失：

    function resolveStopBoundary(cwd: string): string | null {
  const cwdGitRoot = findGitRoot(cwd)
  const sessionGitRoot = findGitRoot(getProjectRoot())
  ...
  if (cwdCanonical && normalizePathForComparison(cwdCanonical) === normalizePathForComparison(sessionGitRoot)) {
    return cwdGitRoot
  }
  ...
  if (nCwdGitRoot !== nSessionRoot && nCwdGitRoot.startsWith(nSessionRoot + sep)) {
    return sessionGitRoot
  }
  return cwdGitRoot
}

    getProjectDirsUpToHome() 在边界内逐级尝试 .claude/<subdir>，不可访问目录只跳过，不炸全链路：

    const claudeSubdir = join(current, '.claude', subdir)
try {
  statSync(claudeSubdir)
  dirs.push(claudeSubdir)
} catch (e: unknown) {
  if (!isFsInaccessible(e)) throw e
}

    4.2 frontmatter 先解析，再重试修复

    parseFrontmatter() 走“两次 parse + 局部降级”：

    const match = markdown.match(FRONTMATTER_REGEX)
if (!match) {
  return { frontmatter: {}, content: markdown }
}
...
try {
  const parsed = parseYaml(frontmatterText)
  ...
} catch {
  try {
    const quotedText = quoteProblematicValues(frontmatterText)
    const parsed = parseYaml(quotedText)
    ...
  } catch (retryError) {
    logForDebugging(`Failed to parse YAML frontmatter...`)
  }
}

    quoteProblematicValues() 专门修复常见 YAML 坑（如 glob/:/# 等字符导致的紧凑映射报错）：

    const match = line.match(/^([a-zA-Z_-]+):\s+(.+)$/)
...
if (YAML_SPECIAL_CHARS.test(value)) {
  const escaped = value.replace(/\\/g, '\\\\').replace(/"/g, '\\"')
  result.push(`${key}: "${escaped}"`)
}

    4.3 字段归一把 YAML 变成 runtime 语义

    parseSkillFrontmatterFields() 是整个 discovery 层的语义门：

    const validatedDescription = coerceDescriptionToString(frontmatter.description, resolvedName)
const description = validatedDescription ?? extractDescriptionFromMarkdown(markdownContent, descriptionFallbackLabel)

const userInvocable =
  frontmatter['user-invocable'] === undefined
    ? true
    : parseBooleanFrontmatter(frontmatter['user-invocable'])

const model =
  frontmatter.model === 'inherit'
    ? undefined
    : frontmatter.model
      ? parseUserSpecifiedModel(frontmatter.model as string)
      : undefined

const effortRaw = frontmatter['effort']
const effort = effortRaw !== undefined ? parseEffortValue(effortRaw) : undefined
if (effortRaw !== undefined && effort === undefined) {
  logForDebugging(`Skill ${resolvedName} has invalid effort ...`)
}

    这里的关键不是“取字段”，而是把以下默认语义写死：

    • user-invocable 缺省为 true；
    • model: inherit 视作“无覆盖”；
    • 非法 effort 仅字段失效，不让 skill 失效；
    • hooks 必须过 schema（parseHooksFromFrontmatter()）才进入后续运行时。

    4.4 paths 不是简单字符串，而是条件可见性协议

    parseSkillPaths() 会把 match-all/空模式收敛成 undefined，避免制造伪 conditional skill：

    const patterns = splitPathInFrontmatter(frontmatter.paths)
  .map(pattern => pattern.endsWith('/**') ? pattern.slice(0, -3) : pattern)
  .filter((p: string) => p.length > 0)

if (patterns.length === 0 || patterns.every((p: string) => p === '**')) {
  return undefined
}

    4.5 统一 command 对象在 discovery 阶段就被固化

    createSkillCommand() 直接把 skill 固化为 type:'prompt'：

    return {
  type: 'prompt',
  name: skillName,
  description,
  allowedTools,
  argNames: argumentNames.length > 0 ? argumentNames : undefined,
  model,
  disableModelInvocation,
  userInvocable,
  context: executionContext,
  agent,
  effort,
  paths,
  source,
  loadedFrom,
  hooks,
  skillRoot: baseDir,
  async getPromptForCommand(args, toolUseContext) { ... }
}

    并在 prompt 组装阶段执行关键替换与安全分叉：

    finalContent = substituteArguments(finalContent, args, true, argumentNames)
...
if (loadedFrom !== 'mcp') {
  finalContent = await executeShellCommandsInPrompt(finalContent, ...)
}

    即：MCP skill markdown 明确不执行 inline shell。

    4.6 conditional/dynamic 生命周期

    getSkillDirCommands() 把条件技能先放入 conditionalSkills：

    if (skill.type === 'prompt' && skill.paths && skill.paths.length > 0 && !activatedConditionalSkillNames.has(skill.name)) {
  newConditionalSkills.push(skill)
} else {
  unconditionalSkills.push(skill)
}
...
for (const skill of newConditionalSkills) {
  conditionalSkills.set(skill.name, skill)
}

    后续文件事件触发 activateConditionalSkillsForPaths()，才迁移到 dynamicSkills：

    if (skillIgnore.ignores(relativePath)) {
  dynamicSkills.set(name, skill)
  conditionalSkills.delete(name)
  activatedConditionalSkillNames.add(name)
  activated.push(name)
}

    4.7 watcher/reload 触发缓存失效

    skillChangeDetector.scheduleReload() 先跑配置变更 hooks，再统一清缓存并发信号：

    const results = await executeConfigChangeHooks('skills', paths[0]!)
if (hasBlockingResult(results)) {
  return
}
clearSkillCaches()
clearCommandsCache()
resetSentSkillNames()
skillsChanged.emit()

    useSkillsChange() 区分两类刷新：

    • 磁盘技能变化：clearCommandsCache()（全链）
    • GrowthBook 刷新：clearCommandMemoizationCaches()（memo-only）
    const handleChange = useCallback(async () => {
  clearCommandsCache()
  const commands = await getCommands(cwd)
  onCommandsChange(commands)
}, ...)

const handleGrowthBookRefresh = useCallback(async () => {
  clearCommandMemoizationCaches()
  const commands = await getCommands(cwd)
  onCommandsChange(commands)
}, ...)

    5) Guard / Decision Matrix

    5.1 Discovery & Parse Guards

    Guard 条件 动作 结果
    no-frontmatter guard FRONTMATTER_REGEX 不匹配 返回空 frontmatter 普通 markdown 仍可加载
    yaml-retry guard 首次 parse 失败 quoteProblematicValues 后重试 提升 frontmatter 容错
    invalid-hooks guard hooks schema 失败 parseHooksFromFrontmatter 返回 undefined skill 本体不受影响
    invalid-effort guard parseEffortValue 失败 日志+忽略该字段 fail-soft
    match-all-path guard paths 清洗后全 ** 视作 undefined 避免伪 conditional
    mcp-shell guard loadedFrom === 'mcp' 跳过 executeShellCommandsInPrompt 阻断远端 markdown 内联 shell

    5.2 Visibility & Reload Guards

    Guard 条件 动作 结果
    dedup guard 同一物理文件重复出现 getFileIdentity 去重 防重复技能
    conditional gate skill 有 paths 且未激活 仅入 conditionalSkills 不提前可见
    activation gate 路径命中 ignore 规则 迁移到 dynamicSkills 增量可见
    reload hook gate executeConfigChangeHooks 阻断 跳过清缓存 保留策略控制
    growthbook gate feature 刷新 只清 memo cache 避免不必要重扫

    6) Failure / Recovery / Degradation

    6.1 frontmatter 失败链（局部）

    • 无 frontmatter：直接空对象；
    • YAML 失败：自动 quote 重试；
    • 再失败：记录 warn，继续加载其它技能。

    这条链保证“坏一个 skill 文件”不拖垮命令总线。

    6.2 文件系统异常恢复

    目录不可访问时多处逻辑都是 fail-soft：

    • getProjectDirsUpToHome()：isFsInaccessible 仅跳过；
    • loadSkillsFromSkillsDir()：单目录/单文件读取失败仅跳过；
    • watcher 枚举路径时 stat 失败仅跳过该路径。

    6.3 变更风暴退化策略

    skillChangeDetector.ts 通过 debounce 收敛大量变更事件：

    const RELOAD_DEBOUNCE_MS = 300
...
pendingChangedPaths.add(changedPath)
if (reloadTimer) clearTimeout(reloadTimer)
reloadTimer = setTimeout(async () => { ... }, RELOAD_DEBOUNCE_MS)

    避免“每个文件变更都完整重载”导致事件风暴。

    6.4 动态技能与缓存失效的耦合处理

    onDynamicSkillsLoaded() 只清 memo，不清 dynamicSkills 容器本体，避免刚激活就被清掉：

    onDynamicSkillsLoaded(() => {
  clearCommandMemoizationCaches()
  skillsChanged.emit()
})

    7) Invariants

    1. Skill 在命令层必须是统一 type:'prompt' 抽象。
    2. 同一物理文件不能在命令面出现多个实例。
    3. frontmatter 失败必须局部化，不得中断全量加载。
    4. conditional skill 未激活前不得出现在 unconditional 可见集合。
    5. MCP 来源 skill markdown 不执行 inline shell。
    6. reload 必须经过 hook gate，且刷新语义可区分（full clear vs memo clear）。

    8) Cross-module Contracts

    • 对 02：01 只提供 command facts，不做 runtime permission。
    • 对 03：01 仅提供可执行 prompt command，不决定 slash/fork 入口行为。
    • 对 04：01 解释本地 discovery 主链，04 再解释 bundled/plugin/MCP 差异。
    • 对 src/commands.ts：01 的输出必须稳定支撑 getCommands()、getSkillToolCommands()、getSlashCommandToolSkills()。

    9) Engineering Constraints / Evolution Guidance

    1. 新增 frontmatter 字段时，必须在 parser 层定义“合法值 + 默认值 + 非法降级”；
    2. 新增技能来源时，先对齐去重与可见性生命周期，再接入命令系统；
    3. 不要把 GrowthBook 刷新与磁盘变化刷新混成单一路径；
    4. paths 规则应继续贴合 ignore/gitignore 语义，不应引入另一套 DSL；
    5. 变更检测层不要绕过 executeConfigChangeHooks() 直接热重载。
