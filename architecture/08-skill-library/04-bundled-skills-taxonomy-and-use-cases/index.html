Bundled Skills 分类、合流语义与使用场景（深潜审计版）

1) Scope 与 Evidence Boundary

本页只回答一个问题：bundled / plugin / MCP 这三类“非普通本地 skills 目录来源”如何并入统一 command 抽象，同时保留安全边界差异。

证据范围：

  • src/skills/bundledSkills.ts
  • src/utils/plugins/loadPluginCommands.ts
  • src/skills/mcpSkillBuilders.ts
  • src/commands.ts
  • src/skills/loadSkillsDir.ts（用于合流接口锚定）

不覆盖：

  • 本地 discovery/frontmatter 主链（见 01）
  • SkillTool runtime permission 判定（见 02）
  • slash 用户平面分发/fork 回注（见 03）

2) Core Thesis

04 的核心不是列“有哪些官方技能”，而是说明来源多样时仍保持这两个约束：

  1. 统一抽象：所有来源最终都得表现为同一种 Command 壳；
  2. 边界不抹平：来源不同，安全与运行语义必须继续分层。

即：

  • bundled skill 可以携带文件提取能力，但提取路径必须硬约束；
  • plugin skill 能做变量替换与 shell 执行，但它是 plugin 来源，不应伪装成本地 skill；
  • MCP 通过 builder 接缝借用本地构造器，但不代表它等价于本地磁盘来源。

3) Runtime State Ownership

状态类别 所有者 关键函数 职责
bundled 注册态 bundledSkills.ts registerBundledSkill, getBundledSkills 进程内注册表，供命令系统读取
bundled 文件提取态 bundledSkills.ts extractBundledSkillFiles, writeSkillFiles 惰性写盘并注入 base-dir
bundled 路径安全态 bundledSkills.ts resolveSkillFilePath, safeWriteFile 路径逃逸防护 + 原子安全写入
plugin 命令加载态 loadPluginCommands.ts getPluginCommands, createPluginCommand plugin markdown -> prompt command
plugin 技能加载态 loadPluginCommands.ts getPluginSkills, loadSkillsFromDirectory SKILL.md 目录语义加载
MCP 构造器注册态 mcpSkillBuilders.ts registerMCPSkillBuilders, getMCPSkillBuilders 打破循环依赖的“构造器桥”
合流态 commands.ts getSkills, getCommands bundled/plugin/skills/builtin 统一并轨

4) End-to-end Flow

4.1 Bundled：注册时只是声明，执行时才提取

registerBundledSkill() 不立即写盘，而是为 files 场景包一层惰性提取逻辑：

if (files && Object.keys(files).length > 0) {
  skillRoot = getBundledSkillExtractDir(definition.name)
  let extractionPromise: Promise<string | null> | undefined
  const inner = definition.getPromptForCommand
  getPromptForCommand = async (args, ctx) => {
    extractionPromise ??= extractBundledSkillFiles(definition.name, files)
    const extractedDir = await extractionPromise
    const blocks = await inner(args, ctx)
    if (extractedDir === null) return blocks
    return prependBaseDir(blocks, extractedDir)
  }
}

这里明确了 three-way 语义：

  1. 提取成功：返回带 base-dir 前缀的 prompt；
  2. 提取失败：skill 仍执行（return blocks）；
  3. 并发调用：共享同一个 extractionPromise，不重复写盘。

4.2 Bundled 文件写入的安全边界

核心防护在两层：

路径归一+逃逸阻断：

function resolveSkillFilePath(baseDir: string, relPath: string): string {
  const normalized = normalize(relPath)
  if (
    isAbsolute(normalized) ||
    normalized.split(pathSep).includes('..') ||
    normalized.split('/').includes('..')
  ) {
    throw new Error(`bundled skill file path escapes skill dir: ${relPath}`)
  }
  return join(baseDir, normalized)
}

写入标志与权限：

const SAFE_WRITE_FLAGS =
  process.platform === 'win32'
    ? 'wx'
    : fsConstants.O_WRONLY |
      fsConstants.O_CREAT |
      fsConstants.O_EXCL |
      O_NOFOLLOW

async function safeWriteFile(p: string, content: string): Promise<void> {
  const fh = await open(p, SAFE_WRITE_FLAGS, 0o600)
  try {
    await fh.writeFile(content, 'utf8')
  } finally {
    await fh.close()
  }
}

这套组合保证 bundled 引用文件能力是“受控开启”，不是任意落盘。

4.3 Plugin：命令加载与技能加载分支

getPluginCommands() 与 getPluginSkills() 是两条平行入口：

  • getPluginCommands()：读 commands path（普通 .md + metadata/inlined content）；
  • getPluginSkills()：读 skills path（SKILL.md 目录语义）。

loadSkillsFromDirectory() 支持“直接目录 skill”与“子目录 skill”两种形态：

const directSkillPath = join(skillsPath, 'SKILL.md')
...
if (directSkillContent !== null) {
  ... createPluginCommand(..., true, { isSkillMode: true })
  return skills
}
...
const skillFilePath = join(skillDirPath, 'SKILL.md')
... createPluginCommand(..., true, { isSkillMode: true })

而 createPluginCommand() 把 plugin frontmatter 收敛进统一 command 壳：

return {
  type: 'prompt',
  name: commandName,
  description,
  allowedTools,
  model,
  effort,
  disableModelInvocation,
  userInvocable,
  source: 'plugin' as const,
  loadedFrom: isSkill || config.isSkillMode ? 'plugin' : undefined,
  pluginInfo: { pluginManifest, repository: sourceName },
  ...
}

并在 prompt 生成阶段执行 plugin 变量替换：

finalContent = substitutePluginVariables(finalContent, { path: pluginPath, source: sourceName })
...
if (pluginManifest.userConfig) {
  finalContent = substituteUserConfigInContent(finalContent, loadPluginOptions(sourceName), pluginManifest.userConfig)
}

4.4 MCP：builder 桥接而非直接耦合

mcpSkillBuilders.ts 把 createSkillCommand 与 parseSkillFrontmatterFields 注册成“写一次、取一次”的桥，避免 mcpSkills.ts <-> loadSkillsDir.ts 形成循环依赖：

let builders: MCPSkillBuilders | null = null

export function registerMCPSkillBuilders(b: MCPSkillBuilders): void {
  builders = b
}

export function getMCPSkillBuilders(): MCPSkillBuilders {
  if (!builders) {
    throw new Error('MCP skill builders not registered — loadSkillsDir.ts has not been evaluated yet')
  }
  return builders
}

语义上：MCP skill 借的是“构造能力”，不是“把 mcp 变成本地目录”。

4.5 命令系统最终合流

commands.ts:getSkills() 把 skillDir/plugin/bundled/builtinPlugin 四路统一返回：

const [skillDirCommands, pluginSkills] = await Promise.all([...])
const bundledSkills = getBundledSkills()
const builtinPluginSkills = getBuiltinPluginSkillCommands()
return { skillDirCommands, pluginSkills, bundledSkills, builtinPluginSkills }

commands.ts:getCommands() 再拼接成完整 command surface：

return [
  ...bundledSkills,
  ...builtinPluginSkills,
  ...skillDirCommands,
  ...workflowCommands,
  ...pluginCommands,
  ...pluginSkills,
  ...COMMANDS(),
]

5) Guard / Decision Matrix

5.1 来源合流与安全边界

Guard 条件 动作 结果
bundled files guard skill 定义含 files 惰性提取 + base-dir prepend 文件能力按需开启
bundled extract failure guard extractBundledSkillFiles 报错 返回 null 并继续 skill 执行 degrade-not-crash
path traversal guard 绝对路径或 .. resolveSkillFilePath 抛错 阻断目录逃逸
safe write guard bundled 写盘 SAFE_WRITE_FLAGS + 0o600 原子写入 + 降低跟随风险
plugin duplicate guard plugin 内重复路径 isDuplicatePath 跳过 防重复加载
plugin mode guard isSkillMode loadedFrom:'plugin' + skill 目录变量替换 保留来源语义
mcp builders guard builders 未注册 getMCPSkillBuilders 抛显式错误 防静默半初始化
merge guard 各来源加载局部失败 getSkills 局部 catch 返回空集合 主命令系统继续可用

5.2 plugin/bare 模式边界

Guard 条件 动作 结果
bare mode guard isBareMode() && inlinePlugins.length===0 getPluginCommands/getPluginSkills 返回空 跳过市场插件自动加载
inline plugin override 指定 --plugin-dir 仍可加载 inline plugin 明确用户意图优先

6) Failure / Recovery / Degradation

6.1 Bundled 提取失败的降级语义

extractBundledSkillFiles() 失败不会中止 skill：

try {
  await writeSkillFiles(dir, files)
  return dir
} catch (e) {
  logForDebugging(`Failed to extract bundled skill ...`)
  return null
}

调用端收到 null 后直接 return blocks，即功能可用、文件参考能力降级。

6.2 Plugin 单路径失败局部化

getPluginCommands() 与 getPluginSkills() 都在插件维度/路径维度局部 catch，失败记录后继续其它插件：

try {
  const commands = await loadCommandsFromDirectory(...)
  pluginCommands.push(...commands)
} catch (error) {
  logForDebugging(`Failed to load commands ...`, { level: 'error' })
}

6.3 MCP builders 未注册的显式失败

getMCPSkillBuilders() 不会默认返回空 builder，而是抛错：

if (!builders) {
  throw new Error('MCP skill builders not registered ...')
}

避免“半初始化成功、后续行为漂移”的隐性故障。

7) Invariants

  1. bundled/plugin/MCP 最终都必须落到同一个 Command 抽象层。
  2. bundled 文件提取必须被路径与写入策略硬约束，不能出现目录逃逸。
  3. bundled 提取失败应降级而非致命。
  4. plugin skill 与 plugin command 必须保持来源可辨识（source/loadedFrom/pluginInfo）。
  5. MCP builder 依赖缺失必须显式失败，不得静默回退。
  6. 多来源合流失败必须局部化，不能拖垮 getCommands() 主链。

8) Cross-module Contracts

  • 对 01：04 不重写本地 discovery 主链，只补充非本地来源语义。
  • 对 02：04 提供“来源差异仍需权限差异”的前提，不直接做 permission 判决。
  • 对 03：04 提供统一 command 壳，03 再决定 slash/fork 用户入口行为。
  • 对命令系统：04 所有来源最终都要被 commands.ts:getSkills/getCommands 回收。

9) Engineering Constraints / Evolution Guidance

  1. 新增 bundled 文件能力时，必须沿用 resolveSkillFilePath + safeWriteFile 防线；
  2. plugin 新字段应继续在 createPluginCommand 统一归一，不要在执行阶段到处解析；
  3. MCP 侧扩展要通过 builder 契约接入，避免把 loadSkillsDir.ts 拉进循环依赖；
  4. 任何来源扩展都必须在 getSkills/getCommands 层验证是否会破坏顺序与去重；
  5. 保持 degrade-not-crash：来源级失败只能局部失效。
