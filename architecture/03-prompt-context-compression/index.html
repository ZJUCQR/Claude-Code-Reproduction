Prompt 与上下文压缩（入口审计页）

1) Scope 与 Evidence Boundary

本页是 docs/architecture/03-prompt-context-compression 的入口页，给出 03 模块职责边界、阅读顺序与页面所有权。

证据边界覆盖：

  • src/utils/systemPrompt.ts
  • src/constants/prompts.ts
  • src/services/compact/*.ts
  • src/query.ts
  • src/query/tokenBudget.ts

2) Core Thesis

03 模块是“上下文资源治理层”：在 token 受限下保持对话与工具执行语义可继续。

它解决的不是“少 token”，而是“压缩后仍可运行”。

3) Runtime State Ownership

状态 所有者 说明
Prompt 组装与优先级 systemPrompt.ts + prompts.ts 决定送模提示结构
自动压缩决策 autoCompact.ts 决定何时压缩
轻量压缩执行 microCompact.ts time-based/cached 路径
SM fallback 压缩 sessionMemoryCompact.ts session-memory compact
全量压缩与重建 compact.ts 生成 post-compact 消息集
压缩后清理 postCompactCleanup.ts 清理缓存和全局状态
回合恢复分支 query.ts withheld -> recover/surface

4) End-to-end Flow（高层）

  1. 组装 prompt（含动态边界）。
  2. 计算 token 状态与压缩判定。
  3. 尝试 micro/SM compact；必要时 full compact。
  4. 重建 post-compact 消息并做 cleanup。
  5. query 继续，失败走 recover/degrade 分支。

5) Guard / Decision Matrix（入口级）

Guard 条件 行为 结果
override prompt overrideSystemPrompt 直接短路 全覆盖
autocompact recursion guard querySource=session_memory/compact 禁止 auto 防循环
auto disabled env/settings 关闭 跳过 auto 手动路径保留
session-memory compact miss try 返回 null fallback legacy compact 可用性优先
连续失败上限 >= MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES 停止重试 防 API 风暴
API recoverable error withheld 413/media/max_output 恢复优先 recover 或 surface

6) Failure / Recovery / Degradation

  • 自动压缩失败：记录并回退，不阻断主循环。
  • SM compact 不命中：自动降级 legacy compact。
  • recoverable API 错误：先尝试恢复，失败再暴露。
  • post-cleanup 目标：把风险隔离在 compact 模块，不扩散到 query/tool 主链。

7) Invariants

  1. 压缩后消息拓扑必须可被 API 消费。
  2. 自动压缩不得递归进入自身路径。
  3. compact 后必须有清理阶段。
  4. recoverable 错误不能提前 surface。
  5. 主线程与子代理状态清理必须隔离。
  6. token budget 续轮必须有停止机制。

8) Cross-module Contracts

  • 与 01：03 不修改回合控制语义，只控制上下文体积与结构。
  • 与 02：03 可读取 session memory 作为 compact 输入，但失败必须可回退。
  • 与 06 stop hooks：错误恢复顺序优先于 hook 阶段，避免死循环。
  • 与 UI 层：collapse 是展示优化，不可改执行语义。

9) Engineering Constraints / Evolution Guidance

扩展 03 时必须：

  • 明确新增分支是“判定层”还是“执行层”；
  • 明确失败后的 recover/degrade；
  • 保持函数级锚点与跨页唯一归属，避免 README 与主文重复。
