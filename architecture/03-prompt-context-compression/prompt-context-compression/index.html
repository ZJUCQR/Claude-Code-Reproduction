Prompt 与上下文压缩（总览审计版）

1) Scope 与 Evidence Boundary

本页是 03 模块总览收敛页，聚焦以下执行平面：

  • src/utils/systemPrompt.ts
  • src/constants/prompts.ts
  • src/services/compact/autoCompact.ts
  • src/services/compact/microCompact.ts
  • src/services/compact/sessionMemoryCompact.ts
  • src/services/compact/compact.ts
  • src/services/compact/postCompactCleanup.ts
  • src/query.ts
  • src/query/tokenBudget.ts

本页目标不是复述 01~04 子页细节，而是统一回答：

  • 哪些状态在何处拥有；
  • 何时触发 compact、何时禁止；
  • 失败如何 recover/degrade；
  • 哪些不变量跨 compact/query/cleanup 成立。

2) Core Thesis

该模块核心不是“节省 token”，而是“在上下文缩减后维持可继续执行的语义拓扑”。

它是四段式体系：

  1. Prompt 组装（静态前缀 + 动态后缀）；
  2. 压缩判定（阈值/来源/gate）；
  3. 压缩执行（micro/session-memory/full）；
  4. 压缩后清理（缓存与运行态重置）。

工程价值：

  • 防止递归压缩与 API 风暴；
  • 在 recover 分支中优先“可继续”，而非“立即失败”；
  • 压缩后重建消息结构，保证下轮 tool/hook 仍可运行。

3) Runtime State Ownership

状态类别 所有者 关键字段/函数 说明
Prompt 生效优先级 systemPrompt.ts buildEffectiveSystemPrompt override/agent/custom/default/append 顺序
动态段缓存态 systemPromptSections + bootstrap state systemPromptSection / resolveSystemPromptSections / cache 控制动态 section 复用与失效
自动压缩判定态 autoCompact.ts threshold 族函数 + shouldAutoCompact 决定何时触发 compact
轻量压缩态 microCompact.ts pendingCacheEdits / cachedMC state 时间触发与缓存编辑路径
SM compact 态 sessionMemoryCompact.ts smCompactConfig / lastSummarizedMessageId 基于 session memory 的 fallback compact

清理态 postCompactCleanup.ts runPostCompactCleanup compact 后缓存/全局状态清扫
Query 恢复态 query.ts withheld/recovery transition 413/media/max_output 分支恢复
预算续轮态 query/tokenBudget.ts BudgetTracker + checkTokenBudget token target 达成/续轮/提前停止

4) End-to-end Flow（跨层时序）

  1. getSystemPrompt 生成 prompt sections，并在动态边界后插入 runtime section。
  2. query 回合内做 token warning/blocking 评估，并调用 autoCompactIfNeeded。
  3. auto compact 优先尝试 trySessionMemoryCompaction，不命中则 fallback compactConversation。
  4. buildPostCompactMessages 产出 boundary + summary + attachments + hooks。
  5. runPostCompactCleanup 清理模块级缓存与压缩态。
  6. query 继续；若遇 recoverable API error（withheld 413/media/max output），按恢复链重试或 surface。

关键链路片段：

// src/services/compact/autoCompact.ts
const sessionMemoryResult = await trySessionMemoryCompaction(...)
if (sessionMemoryResult) {
  setLastSummarizedMessageId(undefined)
  runPostCompactCleanup(querySource)
  markPostCompaction()
  return { wasCompacted: true, compactionResult: sessionMemoryResult }
}

const compactionResult = await compactConversation(...)
setLastSummarizedMessageId(undefined)
runPostCompactCleanup(querySource)

5) Guard / Decision Matrix

层级 Guard 动作 终态
Prompt 组装 overrideSystemPrompt 直接短路返回 替换全部默认链
自动压缩禁区 querySource in {session_memory, compact} shouldAutoCompact=false 防递归
自动压缩总开关 DISABLE_COMPACT / DISABLE_AUTO_COMPACT / settings 关闭 auto path 手动 compact 仍可用（视开关）
reactive-only 模式 tengu_cobalt_raccoon 禁止 proactive autocompact 留给 reactive recover
context collapse 模式 isContextCollapseEnabled() 禁止 proactive autocompact 避免双系统竞争
连续失败熔断 consecutiveFailures >= 3 停止重试 阻断 API 风暴
microcompact 时间触发 gap 超阈值 + main-thread source 清理旧 tool_result content 降低冷缓存重写成本
cached microcompact feature+model+main-thread 生成 cache_edits 不改本地消息体
query recover withheld 413/media/max_output 先 recover，再决定 surface 同轮恢复或结束
stop hook 保护 lastMessage 为 API error 跳过 stop hooks 防 death spiral

6) Failure / Recovery / Degradation

6.1 auto compact 失败链

  • SM compact 不可用 -> null -> fallback legacy compact；
  • legacy compact 抛错 -> 计数 +1；
  • 连续失败达到上限 -> 熔断停止自动重试。

6.2 query withheld 恢复链

query.ts 对 recoverable 错误先 withheld，再尝试恢复；恢复成功则 continue，失败才 surface 并终止，避免过早暴露可恢复错误。

6.3 microcompact 降级链

  • time-based trigger 不命中 -> 尝试 cached path；
  • cached path不可用 -> no-op 返回原消息；
  • 不影响主执行语义。

6.4 post-compact 清理降级

cleanup 是“最佳努力 + 必要核心重置”；即使某些外围清理失败，主 query 仍需继续，避免把压缩后处理变成单点故障。

6.5 token budget 续轮链

checkTokenBudget 在未达到目标且未出现 diminishing returns 时自动续轮；达到停止条件时结构化结束，防止无穷“继续”。

7) Invariants

  1. 压缩后消息必须满足 API 拓扑约束（tool_use/tool_result 等）。
  2. 自动压缩不得对 session_memory 与 compact 源递归触发。
  3. recoverable API 错误必须先尝试恢复，再决定 surface。
  4. compact 后必须执行状态清理，避免跨轮污染。
  5. main-thread 与 subagent 的清理边界必须隔离。
  6. compact 失败不能无限重试（必须有 circuit breaker）。
  7. token budget 续轮必须有停止条件，防止空转。
  8. Prompt 动态边界位置必须稳定，避免缓存策略失真。

8) Cross-module Contracts

  • 对 01（query/tool）：03 只管理上下文体积与结构，不改变工具事务语义。
  • 对 02（memory）：03 可使用 session memory 做 compact fallback，但不能依赖其必定成功。
  • 对 stop hooks：遇 API error 场景可跳过 stop hooks，避免“错误-阻断-重试”螺旋。
  • 对 UI/transport：collapse 属于展示优化，不可回写执行语义。

9) Engineering Constraints / Evolution Guidance

修改 03 模块先问三件事：

  1. 会不会引入新的递归压缩入口？
  2. 会不会破坏 post-compact 的可继续执行拓扑？
  3. 会不会让 recoverable 错误过早 surface？

若任一答案是“可能”，必须补：

  • 明确 guard 顺序；
  • 明确 failure -> recover/degrade 分支；
  • 明确 telemetry 或 transition reason。

建议回归：

  • session_memory / compact 来源不触发 auto；
  • SM compact 成功与 fallback legacy 两路径；
  • 连续失败熔断生效；
  • withheld 413/media/max-output 恢复与 surface；
  • post-compact cleanup 在 main-thread/subagent 差异路径。
