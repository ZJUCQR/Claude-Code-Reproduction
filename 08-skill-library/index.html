    技能库（入口审计页）

    1)范围与证据边界

    本页是 docs/08-skill-library 入口页，只负责模块边界、阅读路径、关键锚点，不承载实现细节。

    覆盖边界（模块级）：

    • discovery/loading/indexing
    • command surface 投影
    • SkillTool runtime/permission
    • slash/fork user-plane execution
    • bundled/plugin/MCP merge semantics
    • reload/change propagation

    对应源码簇：

    • src/skills/loadSkillsDir.ts
    • src/utils/frontmatterParser.ts
    • src/utils/markdownConfigLoader.ts
    • src/commands.ts
    • src/tools/SkillTool/SkillTool.ts
    • src/utils/processUserInput/processSlashCommand.tsx
    • src/utils/forkedAgent.ts
    • src/skills/bundledSkills.ts
    • src/utils/plugins/loadPluginCommands.ts
    • src/skills/mcpSkillBuilders.ts
    • src/utils/skills/skillChangeDetector.ts
    • src/hooks/useSkillsChange.ts

    2)核心论点

    08 模块是“多来源技能能力总线”：

    • 上游把异构技能来源压平为统一命令抽象；
    • 下游在不同执行平面（UI/slash/model）按策略恢复差异；
    • 整体目标是单一事实源、可解释权限、可恢复执行。

    3)运行时状态所有权

    状态 所有者 说明
    发现/索引态 loadSkillsDir.ts 技能发现、frontmatter 字段归一、conditional/dynamic 激活
    命令面态 commands.ts getCommands + skill/slash/model 投影过滤
    模型执行态 SkillTool.ts validate/permission/call（inline/fork/remote）
    用户执行态 processSlashCommand.tsx slash 解析、分发、fork/background 回注
    来源合流态 bundled/plugin/MCP loaders 多来源并轨与来源边界保留
    刷新传播态 watcher + hook 变更触发缓存清理与 UI 刷新

    4)端到端流程（高层）

    1. skills 被扫描并解析 frontmatter；
    2. 归一为 Command 抽象并进入 command registry；
    3. 在 getSkillToolCommands / getSlashCommandToolSkills 做 surface 分层；
    4. SkillTool 或 slash 入口触发执行；
    5. 按 inline/fork/remote 路径运行并回传结果；
    6. file watcher/GrowthBook 刷新触发缓存更新。

    5)守卫与决策矩阵（入口级）

    Guard 条件 行为 结果
    parse guard YAML/frontmatter 异常 重试+局部降级 单技能失败不扩散
    dedup guard 同物理文件重复 去重 防重复命令曝光
    surface guard consumer 不同 过滤可见命令 UI/slash/model 一致分层
    permission guard SkillTool 调用 deny-first 判决链 执行前止损
    execution guard context/source 不同 inline/fork/remote 分叉 运行语义清晰
    reload guard 文件变更或 flag 刷新 清缓存+重取命令 避免 stale commands

    6)失败、恢复与降级

    • malformed frontmatter：降级单 skill；
    • 单来源加载失败：其它来源继续；
    • 权限拒绝：可解释 deny/ask；
    • fork/background 失败：结果可回注、可追踪；
    • bundled 提取失败：仅失去文件参考能力，不阻断 skill 主体。

    7)不变量

    1. 统一 command 抽象是唯一对外接口。
    2. slash 与 SkillTool 必须共享命令事实源。
    3. deny 必须优先于 allow。
    4. conditional skills 未激活前不得暴露。
    5. 来源差异不能在抽象化中被抹平。
    6. cache/reload 失败必须局部化。

    8)跨模块契约

    • 对 05：可接 MCP skills，不接管 MCP 连接生命周期。
    • 对 06：可注册 hooks，不接管 hook 执行框架。
    • 对 09：输出统一命令集，不自建第二命令系统。
    • 对 01/07：提供技能执行结果，不改 query/stream 主链状态机。

    9)工程约束与演进指引

    扩展 08 时优先检查：

    1. 新来源是否先对齐 command 抽象；
    2. 新字段是否破坏 deny-first 或 surface 分层；
    3. 是否补齐缓存失效与刷新路径；
    4. 是否在文档中补全 path:function 级证据锚点。

    1)范围与证据边界

    本页是 08 模块总览页，覆盖 skill 系统的完整主链与跨页契约：

    • 发现与加载（discovery/indexing）

    2)核心论点

    08 模块本质是“可扩展命令能力总线”：

    • 先把异构来源（local/plugin/bundled/MCP/remote canonical）压平到统一 Command 抽象；
    • 再在运行时按 consumer（UI/slash/model）与执行语义（inline/fork/remote）恢复差异；
    • 并通过 deny-first、hook gate、source-specific policy 保持可控边界。

    一句话：统一抽象，不统一安全假设。

    3)运行时状态所有权

    状态类别 所有者 关键函数 职责
    discovery/loading 态 loadSkillsDir.ts getSkillDirCommands 多来源扫描、去重、conditional 划分
    frontmatter/schema 态 frontmatterParser.ts + loadSkillsDir.ts parseFrontmatter, parseSkillFrontmatterFields YAML 容错与字段归一
    command surface 态 commands.ts getCommands, getSkillToolCommands, getSlashCommandToolSkills 不同入口可见命令面
    model runtime 态 SkillTool.ts validateInput, checkPermissions, call 模型调用校验、授权、执行分叉
    user runtime 态 processSlashCommand.tsx processSlashCommand, getMessagesForSlashCommand slash 入口解析与分发
    fork execution 态 forkedAgent.ts + processSlashCommand.tsx prepareForkedCommandContext, executeForkedSlashCommand 子代理隔离执行与结果回收
    merge taxonomy 态 bundledSkills.ts / loadPluginCommands.ts / mcpSkillBuilders.ts 各自注册与桥接函数 多来源并轨且保留边界
    reload propagation 态 skillChangeDetector.ts, useSkillsChange.ts scheduleReload, useSkillsChange 变更触发缓存失效与 UI 刷新

    4)端到端流程

    1. 发现阶段：getProjectDirsUpToHome + getSkillDirCommands 收集技能源；
    2. 解析阶段：parseFrontmatter（含重试）+ parseSkillFrontmatterFields 归一字段；
    3. 构造阶段：createSkillCommand 产出统一 prompt command；
    4. 合流阶段：getSkills/getCommands 把 local/plugin/bundled 等并轨；
    5. 投影阶段：getSkillToolCommands 与 getSlashCommandToolSkills 各自过滤；
    6. 执行阶段（模型）：SkillTool validateInput -> checkPermissions -> call；
    7. 执行阶段（用户）：slash processSlashCommand -> getMessagesForSlashCommand；
    8. fork 路径：prepareForkedCommandContext + runAgent + extractResultText；
    9. 刷新阶段：skillChangeDetector / useSkillsChange 清缓存并重取 commands。

    关键代码锚点（示例）：

    // SkillTool: deny-first
for (const [ruleContent, rule] of denyRules.entries()) {
  if (ruleMatches(ruleContent)) {
    return { behavior: 'deny', ... }
  }
}

// slash: fork context
if (command.context === 'fork') {
  return await executeForkedSlashCommand(...)
}

    5)守卫与决策矩阵

    Guard 条件 动作 结果
    parse guard frontmatter YAML 异常 quote 重试 -> 局部降级 单文件失败不扩散
    dedup guard 同物理文件重复发现 getFileIdentity 去重 防重复命令
    conditional guard 命中 paths 条件 初始进 conditionalSkills 延迟暴露
    surface guard consumer 不同 getSkillToolCommands / getSlashCommandToolSkills 分层过滤 UI/slash/model 视图稳定
    permission guard SkillTool 调用 deny-first + allow + safe + ask 授权序稳定
    execution guard context/来源不同 inline/fork/remote 分叉 语义明确
    source policy guard loadedFrom==='mcp' 等 施加来源特定约束（如禁 shell） 边界不抹平
    reload guard 文件变化/GB 刷新 全清或 memo 清缓存 避免 stale surface

    6)失败、恢复与降级

    • frontmatter 失败：重试后降级，不中断全量 discovery；
    • 单来源失败：getSkills 局部 catch 返回空集合，其他来源继续；
    • permission 拒绝：在执行前止损并给出可解释终态；
    • fork/background 失败：结果/错误回注，不静默丢失；
    • bundled 提取失败：skill 主体继续执行，仅失去 base-dir 文件能力；
    • watcher 风暴：debounce 收敛并批处理 reload。

    7)不变量

    1. 08 对外只提供统一 command 抽象。
    2. slash 与 SkillTool 共享命令事实源与 prompt 展开核心。
    3. deny 必须先于任何 allow 分支。
    4. conditional skill 未激活前不得进入常驻可见集合。
    5. 来源差异必须在安全语义层保留，不得被“统一抽象”抹平。
    6. cache/reload 失败必须局部化，不能拖垮主命令系统。

    8)跨模块契约

    • 对 05（MCP）：08 只接入 MCP skill 抽象，不拥有 MCP 连接生命周期。
    • 对 06（Hooks）：08 可注册 skill hooks，但 hook 执行框架与策略引擎不归 08。
    • 对 09（CLI）：08 提供统一命令事实，不再自建第二套命令系统。
    • 对 01/07（主查询/流处理）：08 输出 prompt/fork 执行结果，不改主状态机。

    9)工程约束与演进指引

    1. 扩展来源时先做 command 抽象对齐，再做执行接线；
    2. 新 frontmatter/command 属性默认进入保守路径（如 ask），不要默认 auto-allow；
    3. 维持 SkillTool 与 slash 的共享处理函数，避免双轨漂移；
    4. reload 逻辑维持分层（全缓存清理 vs memo 清理），不要粗暴合并；
    5. 所有关键结论必须可回溯到 file:function 级证据。
