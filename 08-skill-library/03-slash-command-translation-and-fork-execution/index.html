    转译与 执行（深潜审计版）

    2)核心论点

    slash 不是另一套技能执行框架，而是 skill 命令系统的用户平面入口。核心约束：

    1. slash 与 SkillTool 必须命中同一 command facts；
    2. prompt command 依据 context 做 inline/fork 分叉；
    3. unknown/malformed 输入必须保留用户恢复路径；
    4. background fork 必须可回注、可观测、可失败呈现。

    3)运行时状态所有权

    状态类别 所有者 关键函数 职责
    slash 解析态 processSlashCommand.tsx processSlashCommand, looksLikeCommand /cmd args 解析、未知命令恢复
    命令分发态 processSlashCommand.tsx getMessagesForSlashCommand local/local-jsx/prompt 三分派
    prompt 展开态 processSlashCommand.tsx processPromptSlashCommand, getMessagesForPromptSlashCommand 统一 prompt command 消息生成
    fork 执行态 processSlashCommand.tsx executeForkedSlashCommand 前台/后台 fork 子代理执行
    fork 上下文准备态 forkedAgent.ts prepareForkedCommandContext prompt 组装、allowedTools 注入、agent 选择
    结果回收态 forkedAgent.ts extractResultText 子代理文本结果抽取
    参数替换态 argumentSubstitution.ts parseArgumentNames, substituteArguments $ARGUMENTS/$0/$name 语义
    hook 注册态 registerSkillHooks.ts registerSkillHooks skill frontmatter hooks 挂载到 session

    4)端到端流程

    4.1 输入先解析，再决定是否“真命令”

    processSlashCommand() 首先尝试 parse；parse 失败直接返回可恢复消息：

    const parsed = parseSlashCommand(inputString)
if (!parsed) {
  const errorMessage = 'Commands are in the form `/command [args]`'
  return { ... shouldQuery: false, resultText: errorMessage }
}

    若命令名不存在，进入“unknown command vs 非命令输入”分叉：

    if (!hasCommand(commandName, context.options.commands)) {
  let isFilePath = false
  try {
    await getFsImplementation().stat(`/${commandName}`)
    isFilePath = true
  } catch {}

  if (looksLikeCommand(commandName) && !isFilePath) {
    const unknownMessage = `Unknown skill: ${commandName}`
    return {
      ...,
      ...(parsedArgs ? [createSystemMessage(`Args from unknown skill: ${parsedArgs}`, 'warning')] : []),
      shouldQuery: false,
      resultText: unknownMessage,
    }
  }

  return { messages: [...], shouldQuery: true }
}

    这条链的关键是：未知 skill 时保留 args（便于用户重试），而不是简单吞掉输入。

    4.2 () 做真正分发

    先做 userInvocable gate：

    if (command.userInvocable === false) {
  return {
    messages: [... "This skill can only be invoked by Claude ..."],
    shouldQuery: false,
    command,
  }
}

    然后按 command.type 分发：

    switch (command.type) {
  case 'local-jsx': ...
  case 'local': ...
  case 'prompt': {
    if (command.context === 'fork') {
      return await executeForkedSlashCommand(...)
    }
    return await getMessagesForPromptSlashCommand(...)
  }
}

    4.3 统一走 ``

    processPromptSlashCommand() 只做类型收敛，然后委派：

    const command = findCommand(commandName, commands)
if (!command) throw new MalformedCommandError(`Unknown command: ${commandName}`)
if (command.type !== 'prompt') throw new Error(...)
return getMessagesForPromptSlashCommand(command, args, context, [], imageContentBlocks)

    核心路径里做了三件事：

    1) 调 command.getPromptForCommand(args, context) 拿结果； 2) 如有 hooks 且策略允许，调用 registerSkillHooks(...)； 3) 生成 metadata/meta user message/attachment permissions。

    const result = await command.getPromptForCommand(args, context)
...
if (command.hooks && hooksAllowedForThisSkill) {
  registerSkillHooks(context.setAppState, sessionId, command.hooks, command.name, ...)
}
...
const additionalAllowedTools = parseToolListFromCLI(command.allowedTools ?? [])
const messages = [
  createUserMessage({ content: metadata, uuid }),
  createUserMessage({ content: mainMessageContent, isMeta: true }),
  ...attachmentMessages,
  createAttachmentMessage({ type: 'command_permissions', allowedTools: additionalAllowedTools, model: command.model }),
]

    4.4：前台与后台两种执行模式

    executeForkedSlashCommand() 起手调用共享 helper：

    const { skillContent, modifiedGetAppState, baseAgent, promptMessages } =
  await prepareForkedCommandContext(command, args, context)

    前台（同步）

    默认路径会收集消息、渲染进度、抽取结果并返回 local-command-stdout：

    for await (const message of runAgent({ ... isAsync: false, ... })) {
  agentMessages.push(message)
  ... updateProgress()
}
...
let resultText = extractResultText(agentMessages, 'Command completed')
return {
  messages: [
    createUserMessage({ content: prepareUserContent({ inputString: `/${getCommandName(command)} ${args}`.trim(), precedingInputBlocks }) }),
    createUserMessage({ content: `<local-command-stdout>\n${resultText}\n</local-command-stdout>` }),
  ],
  shouldQuery: false,
  command,
  resultText,
}

    后台（）

    在 KAIROS + kairosEnabled 下走 fire-and-forget，并将结果 re-enqueue：

    if (feature('KAIROS') && (await context.getAppState()).kairosEnabled) {
  ...
  const enqueueResult = (value: string): void => enqueuePendingNotification({
    value,
    mode: 'prompt',
    priority: 'later',
    isMeta: true,
    skipSlashCommands: true,
    workload: spawnTimeWorkload,
  })
  void (async () => {
    ...
    const resultText = extractResultText(agentMessages, 'Command completed')
    enqueueResult(`<scheduled-task-result command="/${commandName}">\n${resultText}\n</scheduled-task-result>`)
  })().catch(err => {
    enqueueResult(`<scheduled-task-result command="/${commandName}" status="failed">\n${...}\n</scheduled-task-result>`)
  })

  return { messages: [], shouldQuery: false, command }
}

    4.5 竞态防护

    后台 fork 启动前会等待 pending MCP clients 收敛，避免 task 在 MCP 工具快照不完整时起跑：

    const deadline = Date.now() + MCP_SETTLE_TIMEOUT_MS
while (Date.now() < deadline) {
  const s = context.getAppState()
  if (!s.mcp.clients.some(c => c.type === 'pending')) break
  await sleep(MCP_SETTLE_POLL_MS)
}
const freshTools = context.options.refreshTools?.() ?? context.options.tools

    4.6 参数替换逻辑（底层语义）

    argumentSubstitution.ts 支持四类替换：

    content = content.replace(/\$ARGUMENTS\[(\d+)\]/g, ...)
content = content.replace(/\$(\d+)(?!\w)/g, ...)
content = content.replaceAll('$ARGUMENTS', args)
...
content = content.replace(new RegExp(`\\$${name}(?![\\[\\w])`, 'g'), parsedArgs[i] ?? '')

    这让 slash 与 skill prompt 的参数模型一致。

    4.7 注册语义

    registerSkillHooks() 会把 hooks 作为 session hooks 注册；once: true 的钩子在首次成功后自动移除：

    const onHookSuccess = hook.once
  ? () => {
      removeSessionHook(setAppState, sessionId, eventName, hook)
    }
  : undefined

addSessionHook(setAppState, sessionId, eventName, matcher.matcher || '', hook, onHookSuccess, skillRoot)

    5)守卫与决策矩阵

    5.1 输入与分发

    Guard 条件 动作 结果
    malformed slash guard parseSlashCommand 失败 返回格式提示 用户可恢复输入
    unknown command guard hasCommand miss + looksLikeCommand 返回 Unknown skill 并保留 args warning 降低重输成本
    path-vs-command guard 可能是文件路径 stat('/'+commandName) 探测 避免误伤普通输入
    userInvocable guard userInvocable===false 返回仅 Claude 可调用提示 用户入口与模型入口分层
    type dispatch guard local/local-jsx/prompt 按类型分支 统一入口，多执行语义

    5.2

    Guard 条件 动作 结果
    prompt type guard 非 prompt 命令进入 processPrompt 抛错 防错误复用
    fork context guard command.context==='fork' executeForkedSlashCommand 子代理隔离执行
    assistant bg guard KAIROS && kairosEnabled fire-and-forget + enqueue result 不阻塞主线程
    mcp settle guard pending MCP clients poll 等待并 refreshTools 减少工具快照竞态
    abort guard AbortError 返回 interruption message 终态可解释
    fork failure guard 后台异常 enqueue failed scheduled-task-result 失败可观测
    hooks policy guard hooks 限制策略不允许 不注册 hooks 不绕策略边界

    6)失败、恢复与降级

    6.1/恢复

    • malformed slash：立即提示命令格式；
    • unknown skill：明确错误 + 保留 args（warning message）；
    • 非 slash 输入：回退普通 prompt 流程。

    6.2/错误处理

    getMessagesForSlashCommand() 对 prompt 分支异常做显式兜底：

    • AbortError -> interruption 消息；
    • 其他异常 -> <local-command-stderr>。

    6.3 后台 失败可回注

    后台执行异常不会静默：

    enqueueResult(`<scheduled-task-result command="/${commandName}" status="failed">...`)

    这保证用户后续仍能在主队列看到失败结果。

    6.4 无效/受限时降级

    注册路径受策略 gate，hooks 不可用时 skill 主体仍继续执行。

    7)不变量

    1. slash 与 SkillTool 必须共享 command facts，不得各自维护 prompt 展开逻辑。
    2. context:'fork' 命令不得被当 inline prompt 直接注入。
    3. 背景 fork 必须通过队列回注结果（成功或失败）。
    4. unknown/malformed 输入必须保留用户恢复路径。
    5. hooks 注册必须受策略 gate 约束。
    6. 参数替换语义（$ARGUMENTS/$0/$name）必须稳定一致。

    8)跨模块契约

    • 对 01：03 消费 discovery 产出的 command，不参与目录扫描与 frontmatter 解析。
    • 对 02：03 是用户平面入口；02 是模型平面 runtime 壳。两者复用 prompt 展开能力。
    • 对 04：03 使用 merged-source commands，但不负责来源 taxonomy。
    • 对 06：03 可以注册 hooks，但 hook 执行框架与生命周期不由本模块拥有。

    9)工程约束与演进指引

    1. 新增 slash 类型分支时，优先复用现有 getMessagesForPromptSlashCommand / prepareForkedCommandContext；
    2. 不要移除 unknown command 的 args 保留路径；
    3. 背景 fork 若扩展为更多触发源，必须保持结果回注语义不变；
    4. MCP settle 等待逻辑如调整，需验证 startup 并发任务下的工具完整性；
    5. hooks gate 与 skill 执行应继续解耦（hooks 失败不拖垮 skill 主体）。
