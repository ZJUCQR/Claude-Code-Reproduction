    AgentLoop 与 Tool：入口与启动装配（深潜审计版）

    1) Scope 与 Evidence Boundary

    本页关注“进入 query loop 之前”的硬前置条件，证据范围：

    • src/entrypoints/cli.tsx（入口 fast-path 与 run/preAction 接缝）
    • src/setup.ts（cwd/hook/worktree/session-memory/sinks 初始化）
    • src/main.tsx（命令执行前初始化栅栏）
    • src/bootstrap/state.ts（运行时全局状态容器）

    不覆盖：

    • CLI 命令树语义（09 模块）；
    • query loop 内部状态机（02 页）；
    • 工具权限与执行事务（04 页）。

    2) Core Thesis

    启动链的核心价值不是“尽快进入交互”，而是建立可执行且一致的运行前提：

    1. cwd 与 projectRoot 必须先定；
    2. hooks 快照必须绑定最终 cwd；
    3. worktree 切换后必须重建与 cwd 相关缓存；
    4. setup 失败必须硬终止，不能带半初始化状态进入 query。

    这是一条“先正确、再快速”的策略：fast-path 仅限无副作用场景；其余路径必须经过完整栅栏。

    3) Runtime State Ownership

    3.1 cli.tsx 入口持有 fast-path 裁剪权

    main() 可在不加载完整运行时的前提下处理特定参数（例如版本号）；这避免无意义初始化与副作用。

    3.2 main.tsx preAction 持有命令执行前栅栏

    program.hook('preAction', ...) 负责在真正 command action 前完成初始化、环境同步与必要检查。

    3.3 setup.ts 持有启动状态落盘权

    setup(...) 负责： - setCwd(cwd) - hooks 快照捕获与更新 - file changed watcher - worktree 切换 - session memory 初始化 - sinks 初始化

    3.4 bootstrap/state.ts 持有全局运行态

    包括 session、cwd、projectRoot、token budget 等，后续 query/tool 链路依赖这些状态。

    4) End-to-end Flow

    4.1 入口分流（fast-path vs full-path）

    // src/entrypoints/cli.tsx
async function main(): Promise<void> {
  const args = process.argv.slice(2)
  if (args.length === 1 && (args[0] === '--version' || args[0] === '-v' || args[0] === '-V')) {
    console.log(`${SNAPSHOT_VERSION} (Claude Code)`)
    return
  }
}

    语义：--version 类请求不进入完整 setup 链。

    4.2 preAction 初始化栅栏

    main.tsx 中 program.hook('preAction', ...) 承担执行前同步： - MDM / settings / migrations / remote settings - sinks 关联 - plugin dir 处理

    这一步确保 command action 启动时运行环境一致。

    4.3 setup 主链

    来自 setup.ts 的关键动作：

    export async function setup(...): Promise<void> {
  setCwd(cwd)
  ...
  initializeFileChangedWatcher(cwd)
  ...
  initSessionMemory()
  ...
  initSinks()
}

    关键语义： - 先定 cwd，再做依赖 cwd 的初始化； - session memory 与 sinks 在 setup 收尾阶段接入，确保 query 前可用。

    4.4 worktree 分支

    if (worktreeEnabled) {
  worktreeSession = await createWorktreeForSession(...)
  process.chdir(worktreeSession.worktreePath)
  setCwd(worktreeSession.worktreePath)
  setProjectRoot(getCwd())
  updateHooksConfigSnapshot()
}

    语义：worktree 切换后不仅切 cwd，还必须刷新 hooks 快照，避免旧路径污染。

    5) Guard / Decision Matrix

    Guard 条件 动作 结果
    fast-path version 仅版本参数 直接输出版本并 return 跳过 setup
    worktree requested --worktree 开启 创建 worktree 并切 cwd 新会话根目录生效
    worktree create fail 创建异常 输出错误并 process.exit(1) 防止半初始化继续
    non-git + no hook 无法创建 worktree 硬失败 不进入 query
    plugin prefetch gated skipPluginPrefetch 跳过预取 降低启动副作用
    sinks not ready 未初始化 sink preAction/setup 补齐 保证日志/事件收敛

    6) Failure / Recovery / Degradation

    6.1 worktree 创建失败：硬终止优先于降级运行

    启动期最危险的是“半切换状态”继续执行。源码策略是失败即退出，不尝试模糊降级。

    6.2 cwd 依赖动作顺序错位风险

    若先初始化 hooks 再切 cwd，会导致 hooks 读取到旧目录配置。当前顺序通过 setCwd + 快照更新规避。

    6.3 预取任务降级

    插件/hooks 预取多为异步 fire-and-forget；失败不会阻塞主链。策略是“性能优化可退化，执行正确性不可退化”。

    6.4 sinks 初始化作为收尾屏障

    initSinks() 放在 setup 尾部，确保前置状态稳定后再接入日志与分析 sink，减少早期噪声/竞态。

    7) Invariants

    1. setCwd() 必须先于依赖 cwd 的初始化动作。
    2. worktree 切换后必须重设 projectRoot 与 hooks 快照。
    3. preAction 必须先于 command action。
    4. setup 未完成不得进入 query loop。
    5. 启动失败必须可见且可终止，禁止 silent fallback 到未定义状态。
    6. 预取任务可失败但不得破坏主执行路径。
    7. session/sinks 初始化必须在首轮 query 前完成。

    8) Cross-module Contracts

    • 对 09 CLI：入口层提供参数归一与命令选择，不重复执行平面逻辑。
    • 对 01 query：setup 输出稳定运行上下文，query 不再处理启动期基础校验。
    • 对 06 hooks：hooks 配置快照由 setup 维护，执行期仅消费。

    9) Engineering Constraints / Evolution Guidance

    新增启动参数或启动步骤时必须评估：

    1. 是否影响最终 cwd/projectRoot；
    2. 是否需要在 preAction 栅栏内执行；
    3. 是否会影响 hooks/sinks 初始化顺序；
    4. 失败后是硬终止还是可降级。

    建议启动改动回归用例： - 纯 fast-path（--version） - 默认 full-path - --worktree 成功 - --worktree 失败 - preAction + setup 并行路径下的 cwd 一致性
