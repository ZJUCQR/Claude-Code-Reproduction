    代理循环与工具：单工具执行、权限与错误封装（深潜审计版）

    核心论点

    toolExecution.ts 的价值不在“把 tool.call 跑通”，而在把工具调用转译成可审计协议事务：

    1) 输入结构必须可验证； 2) 权限决策必须可解释； 3) 执行失败必须可消息化； 4) hook 可干预但不能破坏 tool_use_id 对偶关系。

    核心入口证据：

    export async function* runToolUse(
  toolUse: ToolUseBlock,
  assistantMessage: AssistantMessage,
  canUseTool: CanUseToolFn,
  toolUseContext: ToolUseContext,
): AsyncGenerator<MessageUpdateLazy, void> {
  const toolName = toolUse.name
  let tool = findToolByName(toolUseContext.options.tools, toolName)
  ...
}

    运行时状态所有权

    ``：工具识别与外围分支

    职责： - 在可用工具集中解析工具； - fallback 到 base tools 的 alias 兼容路径； - unknown tool / 预中断分支直接消息化返回。

    ``：统一输出通道

    职责： - 把 progress 事件与最终结果合并为同一 AsyncIterable； - 避免上层再拼接两路流。

    核心片段：

    const stream = new Stream<MessageUpdateLazy>()
checkPermissionsAndCallTool(..., progress => {
  stream.enqueue({
    message: createProgressMessage({
      toolUseID: progress.toolUseID,
      parentToolUseID: toolUseID,
      data: progress.data,
    }),
  })
})
  .then(results => {
    for (const result of results) {
      stream.enqueue(result)
    }
  })
  .catch(error => {
    stream.error(error)
  })
  .finally(() => {
    stream.done()
  })

    ``：事务主控

    职责： - schema 与语义校验； - pre/post hooks； - 权限决策归一； - tool.call 执行与结果封装； - 失败路径 + failure hooks。

    端到端流程（单工具事务）

    1. 工具发现与 alias 回退。
    2. schema 校验（safeParse）。
    3. validateInput 语义校验。
    4. 预启动 bash classifier（并行化权限判断）。
    5. 执行 PreToolUse hooks（可改输入、可 stop）。
    6. 解析最终权限决策。
    7. 权限拒绝：构造 error tool_result 并返回。
    8. 权限允许：执行 tool.call。
    9. map result block -> 存储处理 -> 构造 user message。
    10. 执行 PostToolUse hooks。
    11. 成功返回结果列表。
    12. 失败 catch：执行 PostToolUseFailure hooks 并返回错误结果。

    守卫与决策矩阵

    Guard 条件 动作 输出语义
    unknown tool tool 与 alias 都未命中 直接返回错误 <tool_use_error>No such tool
    pre-abort abortController.signal.aborted 返回 cancel result tool_result is_error=true
    schema fail safeParse 失败 返回 InputValidationError error tool_result
    validate fail validateInput.result=false 返回业务错误 error tool_result
    prehook stop hook 发 stop 立即返回 stop result error tool_result
    permission deny behavior !== allow 返回拒绝语义+可选内容块 error tool_result (+attachments)
    call throw tool.call 抛错 失败 hooks + 错误封装 error tool_result
    posthook prevent shouldPreventContinuation 附加 stopped_continuation attachment + result

    不变量

    1. 每次 runToolUse 最终都必须返回可消费消息（成功或错误）。
    2. tool_use_id 必须贯穿到最终 tool_result。
    3. 权限拒绝必须走协议内消息，不能抛穿 query loop。
    4. hook 改写输入不得破坏 tool.call 参数一致性。
    5. toolDecisions 必须在 finally 清理，避免跨调用污染。
    6. failure hooks 即使失败也不能让主错误消息丢失。
    7. alias 只用于兼容，不得覆盖主工具语义。
    8. 输入校验失败必须在调用前终止，禁止带病执行。

    跨模块契约

    • 上游（query/orchestration/executor）只依赖 MessageUpdateLazy 协议。
    • 下游工具必须遵循 Tool 合约：inputSchema、call、mapToolResultToToolResultBlockParam。
    • 权限系统通过 resolveHookPermissionDecision 汇总 hook 与 canUseTool 决策，工具层不自建分裂权限路径。

    工程约束与演进指引

    新增工具或新权限策略时必须验证：

    1. schema 与 validateInput 覆盖边界输入；
    2. deny 路径可完整生成 tool_result；
    3. failure hooks 不会吞掉主错误；
    4. contentBlocks/imagePasteIds 在 allow/deny 都可稳定序列化；
    5. telemetry 不泄漏敏感输入（详情日志需显式开关）。

    推荐新增工具自测最小清单：

    • unknown tool 名称
    • schema 错误输入
    • validateInput 拒绝
    • permission deny
    • call throw
    • call success + post hook
    • user interrupt during execution
