    代理循环与工具 执行管线（入口审计页）

    1)范围与证据边界

    本页是 docs/01-agentloop-tool 的入口页，只负责模块边界、阅读顺序与页面所有权，不承载子机制深潜。

    证据边界覆盖：

    • src/query.ts
    • src/services/tools/toolOrchestration.ts
    • src/services/tools/toolExecution.ts
    • src/services/tools/StreamingToolExecutor.ts
    • src/query/stopHooks.ts

    不覆盖：

    • CLI argv 解析与命令注册（见 09）
    • MCP transport 生命周期（见 05）
    • 流协议投影与 UI 通道细节（见 07）

    2)核心论点

    01 模块是 Claude Code 执行平面的核心闭环：模型流 -> tool_use -> 工具执行 -> tool_result 回灌 -> stop hooks 收尾 -> 下一轮状态推进。

    它的价值不是“把工具跑起来”，而是把并发、权限、fallback、中断、hook 注入等高不确定运行时约束成可审计、可恢复、可追踪的状态机。

    3)运行时状态所有权

    状态 所有者 说明
    回合状态 src/query.ts State.messages、transition、恢复/终止分支
    工具调度状态 toolOrchestration.ts 批次拆分、context 回放、并发边界
    单工具事务状态 toolExecution.ts 输入校验、权限决策、调用与错误封装
    流式执行状态 StreamingToolExecutor.ts queued/executing/completed、级联取消与 drain
    收尾治理状态 stopHooks.ts blockingErrors、preventContinuation、summary/attachment

    4)端到端流程（高层）

    1. queryLoop 构建本轮上下文并做前置预算/压缩判断。
    2. 模型流式输出 assistant 与 tool_use。
    3. 工具走批次调度或流式执行器路径。
    4. 所有结果统一收敛为 tool_result 消息。
    5. 无 follow-up 工具时执行 handleStopHooks。
    6. 写入 next state 继续，或返回 terminal 结束。

    5)守卫与决策矩阵（入口级）

    Guard 条件 行为 结果
    blocking limit token 到硬阈值 直接错误返回 blocking_limit
    streaming fallback 流式路径失败/切换 tombstone + discard + retry 同轮恢复
    recoverable error 413/media/max output withheld 后恢复 continue 或 surface
    permission deny 工具不被允许 生成 error tool_result 消息化拒绝
    stop hook blocking blockingErrors/preventContinuation 终止或回灌错误续轮 显式裁决
    user interrupt abort signal 合成中断结果并停止当前轮 可解释终态

    6)失败、恢复与降级

    • recoverable API 错误：先 withheld，再 collapse/recompact/recover，最后才 surface。
    • tool 执行失败：统一转为 tool_result is_error=true，不抛穿主循环。
    • streaming fallback：丢弃旧流结果并重建 executor。
    • stop hook 异常：降级为 warning，不劫持主链终止。

    7)不变量

    1. tool_use 必须最终配对 tool_result。
    2. 并发只改变时机，不改变语义顺序。
    3. 可恢复错误不能提前暴露。
    4. 阻断决策必须结构化输出。
    5. fallback 后旧流消息必须 tombstone/discard。
    6. 任何 continue 分支都必须写入完整 next state。

    8)跨模块契约

    • 对 09：01 只接收归一消息输入，不回头解析 argv。
    • 对 07：01 输出语义事件，transport 不应改写语义。
    • 对 06：hook 可影响分支，但不能破坏消息拓扑。
    • 对 03：压缩可改变消息体积，不得破坏 tool 对偶语义。

    9)工程约束与演进指引

    修改 01 模块时必须优先检查：

    1. 会不会产生“无结果 tool_use”；
    2. 会不会让恢复分支失去可审计 reason；
    3. 会不会让 hook/fallback 在错误时击穿主链。

    若任一答案是“可能”，就必须补充：状态字段、消息化输出，以及终止/继续条件。

    深度审计正文

    1)范围与证据边界

    本篇是 01 模块的总览收敛页，聚焦执行平面五个核心文件：

    • src/query.ts
    • src/services/tools/toolOrchestration.ts
    • src/services/tools/toolExecution.ts
    • src/services/tools/StreamingToolExecutor.ts
    • src/query/stopHooks.ts

    本页目标不是重复 01~05 子页细节，而是建立统一语义地图：

    • 哪些状态在何处拥有；
    • 哪些失败在何处分流；
    • 哪些不变量跨文件成立；
    • 哪些契约不可被子模块破坏。

    2)核心论点

    AgentLoop 是一个“可恢复回合自动机 + 工具事务执行层 + 回合末治理层”的三段组合体。其核心价值：

    • 把复杂失败路径收敛到 Message 语义；
    • 把并发调度收敛到可审计顺序；
    • 把治理动作收敛到结构化阻断结果。

    换句话说：它不是“回答生成器”，而是“运行时语义稳定器”。

    3)运行时状态所有权（跨文件总表）

    状态类别 所有者 关键字段 说明
    回合状态 src/query.ts State.messages, transition, turnCount 决定继续/终止与恢复路径
    工具调度状态 toolOrchestration.ts currentContext, batch partition 决定并发批次与 context 回放
    单工具事务状态 toolExecution.ts processedInput, permissionDecision 决定校验、权限、调用与封装
    流式执行状态 StreamingToolExecutor.ts tools[], hasErrored, discarded 决定流式并发、级联取消与收尾
    回合治理状态 stopHooks.ts blockingErrors, preventContinuation 决定回合末阻断与继续

    4)端到端流程（跨层时序）

    1. queryLoop 构建本轮上下文，执行 compact/预算等前置。
    2. callModel 流式输出 assistant，收集 tool_use。
    3. 工具执行路径二选一：
    4. 流式执行器（StreamingToolExecutor）
    5. 批次调度器（runTools）
    6. 所有工具结果归一为 user/tool_result 消息。
    7. 无 follow-up 时执行 handleStopHooks。
    8. 根据阻断结果决定：continue（写 next State）或 return Terminal。

    5)守卫与决策矩阵（全链总览）

    层级 Guard 动作 终态
    Query 前置 blocking limit 直接错误返回 blocking_limit
    Query 流式 streaming fallback tombstone + discard + retry 同轮恢复
    Query 恢复 413/media withheld collapse/recompact 恢复 continue 或 surface
    Query 恢复 max output tokens escalate / recovery message continue 或 surface
    调度层 非安全并发 切串行批 保序执行
    工具层 deny/invalid/error 消息化 error tool_result 回灌模型
    stop hooks prevent/blocking 终止或回灌错误续轮 明确裁决

    6)失败、恢复与降级（全链）

    6.1 恢复链

    • withheld 错误先隐藏；
    • collapse drain 优先；
    • reactive compact 次级；
    • 都失败才 surface 错误并停止。

    6.2 工具失败链

    • 输入错误、权限拒绝、调用异常都统一为 tool_result is_error=true；
    • 失败后仍可触发 failure hooks；
    • 不抛穿主循环。

    6.3 流式失败链

    • fallback 时丢弃旧流结果并重建 executor；
    • abort 时 drain remaining results，补齐缺失对偶消息。

    6.4 失败链

    • hook 自身异常降级为 warning，不劫持主链终止。

    7)不变量（跨文件强约束）

    1. tool_use 与 tool_result 必须最终配对。
    2. 并发执行可改变时机，不可改变语义顺序。
    3. 可恢复错误不可提前暴露给上层消费者。
    4. 阻断决策必须结构化输出，禁止静默吞掉。
    5. fallback 后旧流消息必须 tombstone/discard。
    6. 任何 continue 必须写入完整 next state。
    7. 失败路径不能绕过消息化封装直接抛异常到上层。

    8)跨模块契约

    • 对 CLI（09）：只接收归一消息输入，不回头解析 argv。
    • 对 Streaming（07）：输出语义事件，transport 不应改写语义。
    • 对 Hooks（06）：hook 可以影响分支，但不能破坏消息拓扑。
    • 对 Compact（03）：压缩可改变消息体积，不得破坏 tool 对偶语义。

    9)工程约束与演进指引

    当你修改 01 模块时，优先问三个问题：

    1. 这个改动会不会产生“无结果 tool_use”？
    2. 这个改动会不会让恢复分支失去可审计 reason？
    3. 这个改动会不会让 hook 或 fallback 在错误时击穿主链？

    若任一答案是“可能”，必须补： - 明确状态字段； - 明确消息化输出； - 明确终止/继续条件。
