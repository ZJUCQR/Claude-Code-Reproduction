    AgentLoop 与 Tool 执行管线（入口审计页）

    1) Scope 与 Evidence Boundary

    本页是 docs/architecture/01-agentloop-tool 的入口页，只负责模块边界、阅读顺序与页面所有权，不承载子机制深潜。

    证据边界覆盖：

    • src/query.ts
    • src/services/tools/toolOrchestration.ts
    • src/services/tools/toolExecution.ts
    • src/services/tools/StreamingToolExecutor.ts
    • src/query/stopHooks.ts

    不覆盖：

    • CLI argv 解析与命令注册（见 09）
    • MCP transport 生命周期（见 05）
    • 流协议投影与 UI 通道细节（见 07）

    2) Core Thesis

    01 模块是 Claude Code 执行平面的核心闭环：模型流 -> tool_use -> 工具执行 -> tool_result 回灌 -> stop hooks 收尾 -> 下一轮状态推进。

    它的价值不是“把工具跑起来”，而是把并发、权限、fallback、中断、hook 注入等高不确定运行时约束成可审计、可恢复、可追踪的状态机。

    3) Runtime State Ownership

    状态 所有者 说明
    回合状态 src/query.ts State.messages、transition、恢复/终止分支
    工具调度状态 toolOrchestration.ts 批次拆分、context 回放、并发边界
    单工具事务状态 toolExecution.ts 输入校验、权限决策、调用与错误封装
    流式执行状态 StreamingToolExecutor.ts queued/executing/completed、级联取消与 drain
    收尾治理状态 stopHooks.ts blockingErrors、preventContinuation、summary/attachment

    4) End-to-end Flow（高层）

    1. queryLoop 构建本轮上下文并做前置预算/压缩判断。
    2. 模型流式输出 assistant 与 tool_use。
    3. 工具走批次调度或流式执行器路径。
    4. 所有结果统一收敛为 tool_result 消息。
    5. 无 follow-up 工具时执行 handleStopHooks。
    6. 写入 next state 继续，或返回 terminal 结束。

    5) Guard / Decision Matrix（入口级）

    Guard 条件 行为 结果
    blocking limit token 到硬阈值 直接错误返回 blocking_limit
    streaming fallback 流式路径失败/切换 tombstone + discard + retry 同轮恢复
    recoverable error 413/media/max output withheld 后恢复 continue 或 surface
    permission deny 工具不被允许 生成 error tool_result 消息化拒绝
    stop hook blocking blockingErrors/preventContinuation 终止或回灌错误续轮 显式裁决
    user interrupt abort signal 合成中断结果并停止当前轮 可解释终态

    6) Failure / Recovery / Degradation

    • recoverable API 错误：先 withheld，再 collapse/recompact/recover，最后才 surface。
    • tool 执行失败：统一转为 tool_result is_error=true，不抛穿主循环。
    • streaming fallback：丢弃旧流结果并重建 executor。
    • stop hook 异常：降级为 warning，不劫持主链终止。

    7) Invariants

    1. tool_use 必须最终配对 tool_result。
    2. 并发只改变时机，不改变语义顺序。
    3. 可恢复错误不能提前暴露。
    4. 阻断决策必须结构化输出。
    5. fallback 后旧流消息必须 tombstone/discard。
    6. 任何 continue 分支都必须写入完整 next state。

    8) Cross-module Contracts

    • 对 09：01 只接收归一消息输入，不回头解析 argv。
    • 对 07：01 输出语义事件，transport 不应改写语义。
    • 对 06：hook 可影响分支，但不能破坏消息拓扑。
    • 对 03：压缩可改变消息体积，不得破坏 tool 对偶语义。

    9) Engineering Constraints / Evolution Guidance

    修改 01 模块时必须优先检查：

    1. 会不会产生“无结果 tool_use”；
    2. 会不会让恢复分支失去可审计 reason；
    3. 会不会让 hook/fallback 在错误时击穿主链。

    若任一答案是“可能”，就必须补充：状态字段、消息化输出，以及终止/继续条件。
