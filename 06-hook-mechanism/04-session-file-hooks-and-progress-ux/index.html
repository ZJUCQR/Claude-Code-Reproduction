    与进度反馈（深潜审计版）

    1)范围与证据边界

    本页覆盖“生命周期 hooks”与“文件观察/进度 UX”：SessionStart、Setup、Stop、SubagentStop、FileChanged、CwdChanged、watcher 动态路径更新、progress/transcript/deferred messages。

    证据范围：

    • src/utils/sessionStart.ts
    • src/query/stopHooks.ts
    • src/utils/hooks.ts
    • src/utils/hooks/sessionHooks.ts
    • src/utils/hooks/fileChangedWatcher.ts
    • src/utils/hooks/hookEvents.ts
    • src/utils/collapseHookSummaries.ts
    • src/hooks/useDeferredHookMessages.ts

    不覆盖：

    • 配置快照与 matcher 选择（见 01）；
    • command/prompt/agent/http 执行协议（见 02）；
    • permission merge 与安全护栏（见 03）。

    2)核心论点

    生命周期与 UX 层的价值不是“多几个系统消息”，而是让 hook 对会话的长期影响可收敛、可观测：

    1. SessionStart/Setup/Stop/SubagentStop 等事件有稳定时序；
    2. watcher 通过 watchPaths 回流形成动态观察闭环；
    3. progress/deferred/summary 把执行状态转成用户可理解输出；
    4. 任何局部失败都不能打断主会话或主监听循环。

    3)运行时状态所有权

    状态类别 所有者 关键函数 说明
    SessionStart/Setup 态 sessionStart.ts processSessionStartHooks / processSetupHooks 启动/恢复/清理时的 hooks
    Stop/SubagentStop 态 stopHooks.ts + hooks.ts handleStopHooks / executeStopHooks / executeSubagentStopHooks 回合结束与子代理停止收尾
    session hook 注入态 sessionHooks.ts session/function hooks 的生命周期 会话期动态注入
    watcher 态 fileChangedWatcher.ts initializeFileChangedWatcher / updateWatchPaths / onCwdChangedForHooks 文件变化监听与路径更新
    progress 事件态 hookEvents.ts emitHookStarted / emitHookProgress / emitHookResponse 执行进度事件总线
    渲染收敛态 collapseHookSummaries.ts + useDeferredHookMessages.ts summary collapse / deferred session messages 降噪与时序注入

    4)端到端流程

    1. 启动/恢复/clear/compact 时 processSessionStartHooks / processSetupHooks 执行；
    2. 生命周期 hook 可返回 additionalContext、initialUserMessage、watchPaths；
    3. initializeFileChangedWatcher 建立 watcher，文件变化触发 executeFileChangedHooks；
    4. watchPaths 回流 updateWatchPaths，形成动态观察闭环；
    5. 回合结束时 handleStopHooks 协调 Stop/SubagentStop 与 summary；
    6. emitHookStarted/Progress/Response 与 deferred messages/collapse summaries 驱动 UI 呈现。
    // src/utils/hooks/fileChangedWatcher.ts
function handleFileEvent(path: string, event: 'change' | 'add' | 'unlink'): void {
  void executeFileChangedHooks(path, event)
    .then(({ watchPaths }) => {
      if (watchPaths.length > 0) updateWatchPaths(watchPaths)
    })
}

    5)守卫与决策矩阵

    Guard 条件 动作 结果
    session source guard startup/resume/clear/compact 传入不同 SessionStart source 启动语义可解释
    stop scope guard main session vs subagent Stop / SubagentStop 分流 收尾顺序稳定
    watchPaths change guard 新旧 paths 相同 不重启 watcher 降低抖动
    watcher error guard hook/watcher 异常 notify + 保持主循环 防监听死亡
    transcript/live guard transcript mode 压缩运行中噪音 UX 稳定
    deferred message guard session-start messages 未注入 useDeferredHookMessages 延后插入 保持首轮时序
    summary collapse guard 同类并行 summaries collapseHookSummaries 聚合 降噪

    6)失败、恢复与降级

    6.1/失败

    • 局部错误转为系统消息/attachment；
    • 不阻断启动与恢复主链。

    6.2/失败

    • handleStopHooks 输出 summary/告警；
    • 不让回合收尾卡死。

    6.3 执行失败

    • handleFileEvent 捕获错误后通知用户；
    • watcher 持续存活，后续事件仍可触发。

    6.4 恢复

    • 某次 hook 返回异常不会永久破坏路径集；
    • 后续成功返回可重新更新 watcher。

    6.5 退化

    • transcript mode 下压缩运行中状态；
    • 即使进度事件缺失，也保留最终结果 attachment/summary。

    7)不变量

    1. session hook 只能影响当前 sessionId。
    2. SessionStart/Setup/Stop/SubagentStop 必须保持稳定时序。
    3. 文件观察路径是静态 matcher 与动态 watchPaths 的并集。
    4. watcher 失败不应杀死主监听循环。
    5. progress 与 resolved 计数必须可对应。
    6. deferred messages 必须在首轮请求前后保持可解释注入顺序。

    8)跨模块契约

    • 对 01：04 消费已注册/已匹配的生命周期 hooks，不重写来源优先级。
    • 对 02：04 只消费统一 HookResult 与 system messages，不关心具体执行协议。
    • 对 03：deny/retry/additionalContext 等结果需要被本页的 UX 层正确呈现。
    • 对 query/session 层：04 扩展生命周期，但不得破坏主会话收敛与 watcher 稳定性。

    9)工程约束与演进指引

    新增 lifecycle hook 或 UX 反馈机制时必须验证：

    1. 是否保持 main/subagent/session/file 事件边界清晰；
    2. 是否会导致 watcher 重启抖动；
    3. 是否在 transcript/live 模式下都可解释；
    4. 是否在失败时仍保留主会话与主监听循环可用。

    建议回归：

    • SessionStart startup/resume/clear/compact；
    • Stop vs SubagentStop；
    • watchPaths changed/unchanged；
    • watcher 执行异常后继续监听；
    • deferred hook messages 与 collapseHookSummaries。
