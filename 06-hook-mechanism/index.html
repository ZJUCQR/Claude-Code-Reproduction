    Hook 机制（入口审计页）

    1) Scope 与 Evidence Boundary

    本页是 docs/architecture/06-hook-mechanism 的入口页，只负责模块边界、阅读顺序与页面所有权，不承载子机制深潜。

    2) Core Thesis

    06 模块是“策略注入执行面”：把配置、匹配、执行、权限桥接、生命周期 hooks 与进度展示收敛成统一可审计协议。

    目标不是“hook 越多越灵活”，而是“hook 足够强大且仍可约束、可恢复、可观测”。

    3) Runtime State Ownership

    状态 所有者 说明
    配置快照态 hooksConfigSnapshot.ts 多来源 hook 配置与 policy gating
    匹配/排序态 hooksSettings.ts event/matcher/source priority 选择
    会话注入态 sessionHooks.ts session/function hooks 的动态注册
    执行协议态 hooks.ts + exec*Hook.ts command/prompt/agent/http 等执行模型
    权限桥接态 toolHooks.ts + toolExecution.ts hook 决策与规则层/交互层合成
    生命周期/UX 态 sessionStart.ts/stopHooks.ts/watcher/hooks UI SessionStart/Stop/FileChanged 与进度反馈

    4) End-to-end Flow（高层）

    1. 归一 hook 配置与 session 注入。
    2. 根据事件与 matcher 选出命中集合。
    3. 通过统一执行管道分发到具体 hook 协议。
    4. 聚合结果并回流到 tool permission、session lifecycle 或 UI。
    5. 通过 progress/summary/deferred messages 向用户展示执行状态。

    5) Guard / Decision Matrix（入口级）

    Guard 条件 行为 结果
    disable-all guard policy 或 settings 禁用 hooks 直接跳过 hooks 全局失效
    managed-only guard 仅允许 managed hooks 屏蔽其它来源 收紧执行面
    trust gate 未信任上下文 跳过/阻止执行 防危险命令落地
    matcher guard 无命中 hooks 快速 no-op 降低热路径成本
    permission merge guard hook allow 与规则 deny/ask 冲突 规则层优先 防越权
    lifecycle guard main vs subagent vs file/watcher 进入不同事件入口 生命周期语义稳定

    6) Failure / Recovery / Degradation

    • hook 配置变更：刷新 snapshot，避免 stale 配置长期生效。
    • 执行器异常：聚合为标准错误语义，默认局部降级。
    • 权限冲突：hook 决策进入统一 merge 点，由规则层收敛。
    • watcher/hook UX 异常：通知用户但不打断主循环。
    • session hooks：结束时清理，避免跨会话泄漏。

    7) Invariants

    1. hook 只能通过标准执行管道影响系统。
    2. hook allow 不能绕过显式 deny/ask。
    3. trust gate 必须对所有 hook 类型统一生效。
    4. session hooks 必须可清除。
    5. 文件观察失败不应杀死主监听循环。
    6. progress 与最终结果必须可观测、可解释。

    8) Cross-module Contracts

    • 对 tool 执行层：06 只通过 pre/post/permission 接口施加影响。
    • 对权限系统：06 提供建议与上下文，不替代最终裁决。
    • 对 query/session 层：生命周期 hooks 不得阻断主会话收敛。
    • 对 UI：消息与进度展示必须共享统一结果语义。

    9) Engineering Constraints / Evolution Guidance

    扩展 06 模块时必须验证：

    1. 新 hook 类型是否接入统一守卫与超时/abort 机制；
    2. 新 hook 事件是否接入统一聚合结果模型；
    3. 是否破坏 permission merge 顺序；
    4. 是否在 transcript/live 模式下仍可观测。
