    记忆系统：抽取链路（深潜审计版）

    2)核心论点

    SessionMemory 的本质是“阈值驱动 + 串行执行 + 最小写权限”的增量提取事务：

    1. 只在主 REPL 线程触发；
    2. 只在 token/tool-call/turn-break 条件达成时触发；
    3. 通过 forked agent 写入单文件 memory；
    4. 抽取失败不阻断主链；
    5. 抽取状态有 stale/timeout 收敛。

    3)运行时状态所有权

    状态类别 所有者 关键字段/函数 说明
    抽取阈值配置 sessionMemoryUtils.ts sessionMemoryConfig init/update/tool-call 三阈值
    初始化状态 sessionMemoryUtils.ts sessionMemoryInitialized 是否达到初始 token 门槛
    抽取游标 sessionMemory.ts / utils lastMemoryMessageUuid / lastSummarizedMessageId 增量区间定义
    抽取生命周期 sessionMemoryUtils.ts extractionStartedAt + mark start/complete 等待与超时判断
    抽取执行器 sessionMemory.ts extractSessionMemory = sequential(...) 串行化防重入
    写权限边界 sessionMemory.ts createMemoryFileCanUseTool(memoryPath) 仅允许 Edit 目标文件

    4)端到端流程

    4.1 触发入口

    initSessionMemory() 在 auto-compact 启用时注册 post-sampling hook：registerPostSamplingHook(extractSessionMemory)。

    4.2 阈值决策

    // src/services/SessionMemory/sessionMemory.ts
export function shouldExtractMemory(messages: Message[]): boolean {
  const currentTokenCount = tokenCountWithEstimation(messages)
  if (!isSessionMemoryInitialized()) {
    if (!hasMetInitializationThreshold(currentTokenCount)) return false
    markSessionMemoryInitialized()
  }

  const hasMetTokenThreshold = hasMetUpdateThreshold(currentTokenCount)
  const toolCallsSinceLastUpdate = countToolCallsSince(messages, lastMemoryMessageUuid)
  const hasMetToolCallThreshold =
    toolCallsSinceLastUpdate >= getToolCallsBetweenUpdates()
  const hasToolCallsInLastTurn = hasToolCallsInLastAssistantTurn(messages)

  const shouldExtract =
    (hasMetTokenThreshold && hasMetToolCallThreshold) ||
    (hasMetTokenThreshold && !hasToolCallsInLastTurn)
  ...
}

    4.3 抽取事务执行

    // src/services/SessionMemory/sessionMemory.ts
const extractSessionMemory = sequential(async function (context) {
  if (querySource !== 'repl_main_thread') return
  if (!isSessionMemoryGateEnabled()) return
  if (!shouldExtractMemory(messages)) return

  markExtractionStarted()
  const setupContext = createSubagentContext(toolUseContext)
  const { memoryPath, currentMemory } = await setupSessionMemoryFile(setupContext)
  const userPrompt = await buildSessionMemoryUpdatePrompt(currentMemory, memoryPath)

  await runForkedAgent({
    promptMessages: [createUserMessage({ content: userPrompt })],
    canUseTool: createMemoryFileCanUseTool(memoryPath),
    querySource: 'session_memory',
    overrides: { readFileState: setupContext.readFileState },
  })

  recordExtractionTokenCount(tokenCountWithEstimation(messages))
  updateLastSummarizedMessageIdIfSafe(messages)
  markExtractionCompleted()
})

    4.4 等待收敛（供 等路径调用）

    waitForSessionMemoryExtraction() 轮询 extractionStartedAt，遇 stale 或 timeout 即停止等待。

    5)守卫与决策矩阵

    Guard 条件 动作 结果
    主线程守卫 querySource !== 'repl_main_thread' return 子 agent 不参与 session 抽取
    gate 守卫 !isSessionMemoryGateEnabled() return + (可选一次性埋点) 功能关闭退化
    初始化阈值 未达 minimumMessageTokensToInit return 不进入抽取
    更新阈值 未达 minimumTokensBetweenUpdate return 限频
    工具调用阈值 达到 toolCallsBetweenUpdates 且 token 达标 触发抽取 进入 fork
    turn-break 分支 token 达标且最后一轮无 tool_use 触发抽取 在自然断点抽取
    等待 stale extraction age > 60s 停止等待 防无限阻塞
    等待 timeout wait > 15s 停止等待 防主链卡死
    写权限守卫 非 Edit(memoryPath) deny fail-closed

    6)失败、恢复与降级

    6.1 抽取失败：主链继续

    抽取是后台增强能力，失败不会终止主会话；manual 路径返回错误结构而非抛穿。

    6.2 文件初始化失败：仅 视为可恢复

    setupSessionMemoryFile 在创建文件时仅吞 EEXIST；其它 FS 错误继续上抛给调用方，避免静默数据损坏。

    6.3 缓存去重副作用恢复

    抽取前显式 toolUseContext.readFileState.delete(memoryPath)，避免 FileReadTool 返回 file_unchanged 伪增量。

    6.4 等待链路降级

    waitForSessionMemoryExtraction 超时/stale 即放行，确保 compact/query 继续。

    6.5 生命周期清理

    manual 路径 finally 强制 markExtractionCompleted()；防止异常后 extraction 状态悬挂。

    7)不变量

    1. extractSessionMemory 必须串行执行（sequential）。
    2. 只有主线程可触发 session extraction。
    3. token 增量阈值是硬门槛，不可被 tool-call 阈值单独绕过。
    4. 触发成功后才推进相关 cursor/统计状态。
    5. 写权限必须限制为目标 memory 文件的 Edit。
    6. extraction started/completed 必须成对收敛。
    7. compact 等待路径不得无限阻塞。
    8. lastSummarizedMessageId 更新必须避免落在未闭合 tool_use 之后。

    8)跨模块契约

    • 对 01（query/stopHooks）：session memory 是 post-sampling 增强，不改主循环终止裁决。
    • 对 03（compact）：compact 可等待 session extraction，但不能被其永久阻塞。
    • 对 Tool 执行层：forked agent 仍走统一工具权限判定，不能旁路写文件。
    • 对 03 子页（extractMemories）：session 与长期提取共享“best-effort + 权限收敛”哲学，但状态机独立。

    9)工程约束与演进指引

    调整阈值或触发条件时必须同步验证：

    1. 与 autocompact token 口径一致；
    2. 高频 tool_use 场景下不会触发抽取风暴；
    3. manual/auto 路径都能保证 markExtractionCompleted() 收敛；
    4. compact 等待仍具 stale/timeout 上限。

    建议回归：

    • 未达初始化阈值；
    • 达 token 不达 tool-call；
    • 达 token 且最后回合无 tool_use；
    • subagent 触发（应跳过）；
    • extraction 超时/stale；
    • manual extraction 成功/失败。
