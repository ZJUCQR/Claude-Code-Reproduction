    记忆系统（入口审计页）

    2)核心论点

    记忆系统不是“让模型知道更多”的泛化功能，而是“让长期事实在可控权限与可审计失败语义下进入提示系统”的治理层。

    其核心约束：

    • 读侧可降级：memory 注入失败不能卡死主流程；
    • 写侧必须限权：子 agent 只允许写目标 memory 文件；
    • 生命周期可收敛：in-progress、stale、timeout、coalesce 必须闭环；
    • 陈旧性可见：历史事实必须与当前仓库真值分离。

    3)运行时状态所有权

    状态 所有者 关键语义
    memory prompt 注入策略 memdir.ts auto/team/kairos 分流与目录保障
    session 抽取阈值与游标 sessionMemory.ts token/tool-call/turn-break 触发 + cursor 推进
    抽取等待状态 sessionMemoryUtils.ts stale/timeout 双阈值防阻塞
    长期抽取并发控制 extractMemories.ts inProgress + pendingContext + trailing run
    compact 联动状态 autoCompact.ts session-memory compact 优先 + legacy fallback

    4)端到端流程（高层）

    1. Prompt 构建阶段：loadMemoryPrompt() 按 gate 决定是否注入 memory 指令。
    2. 回合后抽取阶段：extractSessionMemory 按阈值触发 forked agent，受最小权限约束写入 session memory。
    3. stop 后台整理阶段：executeExtractMemories 做主题级合并写入，重入时 coalesce。
    4. 压缩联动阶段：autoCompactIfNeeded 先尝试 session-memory compaction，失败再回落 legacy compaction。

    5)守卫与决策矩阵（入口级）

    Guard 条件 行为 结果
    auto memory disabled setting/env/gate 关闭 loadMemoryPrompt -> null 无注入继续运行
    non-main thread querySource !== repl_main_thread 不跑 session extraction 降噪 + 防重入
    threshold 未达 token 或 tool-call 不满足 跳过抽取 等待下一轮
    extraction in progress inProgress=true stash pendingContext trailing 补跑
    非目标文件写入 canUseTool 判定拒绝 deny fail-closed
    session compact miss 试验分支失败/不命中 fallback legacy compact 可用性优先

    6)失败、恢复与降级

    • 目录/注入失败：退化为无 memory 提示，不影响主对话。
    • 抽取悬挂风险：waitForSessionMemoryExtraction 用 stale + timeout 防无限等待。
    • 后台抽取异常：extractMemories 记录错误与埋点，不中断主链。
    • 并发重入：coalesced + trailing run 防抽取风暴。
    • 权限违规尝试：写入路径 fail-closed，阻断越权修改。

    7)不变量

    1. memory 注入失败不能阻断 query 主链。
    2. session extraction 只允许主线程执行。
    3. 抽取触发必须满足阈值与 turn 语义，不得无门槛频发。
    4. 子 agent memory 写入权限必须精确到文件路径。
    5. 抽取状态必须可收敛（started/completed/stale/timeout）。
    6. coalesced 重入只能保留最新 pendingContext。
    7. compact 后需清理相关 cursor，避免悬挂消息引用。
    8. 记忆事实默认可能过期，执行动作前需以当前代码/系统复核。

    8)跨模块契约

    • 与 01（AgentLoop/Tool）：memory 抽取依赖统一工具事务，但不得改变主 loop 终止语义。
    • 与 03（压缩）：memory 与 compact 协同而非替代；任一路径失败必须可回退。
    • 与 06（hooks）：stop 阶段触发的 memory 增强属于 best-effort，不是硬阻断。
    • 与 CLI/Prompt 组装：memory 文本是系统提示拼装片段，不能私自抬升为“绝对真值源”。

    9)工程约束与演进指引

    扩展 02 模块时应遵守：

    • 新 gate 必须定义默认值与关闭语义（fail-open 还是 fail-closed）；
    • 新写入路径必须有最小权限 canUseTool 约束；
    • 新抽取策略必须明确 cursor 推进时机（成功/失败/跳过）；
    • 新 telemetry 必须能区分“未触发”“触发失败”“触发成功”。

    建议先读总览再进子页，避免局部最优破坏全链不变量。

    深度审计正文

    2)核心论点

    Memory 子系统本质是“受门控的事实提炼与注入层”，不是“上下文越多越好”的缓存层。它由三段组成：

    1. Prompt 注入层（memdir）：决定“是否把 memory 机制暴露给模型”；
    2. Session 增量层（SessionMemory）：按阈值与时机抽取短周期会话事实；
    3. 长期整理层（extractMemories）：在 stop 后台合并事实并写入主题文件。

    核心工程价值：

    • 把“记忆失败”从主对话执行面剥离；
    • 把“记忆写入权限”收敛为最小文件级授权；
    • 把“过期风险”显式化为 freshness 提示，而非隐式假设。

    3)运行时状态所有权（跨文件总表）

    状态类别 所有者 关键字段/机制 说明
    注入开关状态 memdir.ts isAutoMemoryEnabled() / TEAMMEM / KAIROS 分支 决定是否返回 memory prompt
    Session 抽取游标 sessionMemory.ts + sessionMemoryUtils.ts lastMemoryMessageUuid、lastSummarizedMessageId、tokensAtLastExtraction 决定“从哪开始抽”与“何时再抽”
    Session 抽取生命周期 sessionMemoryUtils.ts extractionStartedAt + wait timeout/stale 阈值 防止主链无限等待后台抽取
    长期抽取并发态 extractMemories.ts inProgress、pendingContext、inFlightExtractions 决定 coalesce/trailing run 行为
    自动压缩联动态 autoCompact.ts trySessionMemoryCompaction 分支 + reset summarized id 先尝试 session-memory compact，再 fallback legacy compact

    4)端到端流程（跨层时序）

    4.1 读侧：注入链

    // src/memdir/memdir.ts
export async function loadMemoryPrompt(): Promise<string | null> {
  const autoEnabled = isAutoMemoryEnabled()

  if (feature('KAIROS') && autoEnabled && getKairosActive()) {
    return buildAssistantDailyLogPrompt(skipIndex)
  }

  if (feature('TEAMMEM')) {
    if (teamMemPaths!.isTeamMemoryEnabled()) {
      await ensureMemoryDirExists(teamDir)
      return teamMemPrompts!.buildCombinedMemoryPrompt(...)
    }
  }

  if (autoEnabled) {
    await ensureMemoryDirExists(autoDir)
    return buildMemoryLines('auto memory', autoDir, ...).join('\n')
  }

  logEvent('tengu_memdir_disabled', ...)
  return null
}

    语义：注入逻辑是“多门控分流 + 目录保障 + 可降级 return null”。

    4.2 写侧：增量抽取链

    // src/services/SessionMemory/sessionMemory.ts
const extractSessionMemory = sequential(async function (context) {
  if (querySource !== 'repl_main_thread') return
  if (!isSessionMemoryGateEnabled()) return
  if (!shouldExtractMemory(messages)) return

  markExtractionStarted()
  const setupContext = createSubagentContext(toolUseContext)
  const { memoryPath, currentMemory } = await setupSessionMemoryFile(setupContext)
  const userPrompt = await buildSessionMemoryUpdatePrompt(currentMemory, memoryPath)

  await runForkedAgent({
    promptMessages: [createUserMessage({ content: userPrompt })],
    canUseTool: createMemoryFileCanUseTool(memoryPath),
    querySource: 'session_memory',
    forkLabel: 'session_memory',
    overrides: { readFileState: setupContext.readFileState },
  })

  recordExtractionTokenCount(tokenCountWithEstimation(messages))
  updateLastSummarizedMessageIdIfSafe(messages)
  markExtractionCompleted()
})

    语义：主线程守卫、阈值守卫、受限写权限、成功后推进游标。

    4.3 回合末：长期 背景整理链

    // src/services/extractMemories/extractMemories.ts
if (inProgress) {
  pendingContext = { context, appendSystemMessage }
  return
}

await runExtraction({ context, appendSystemMessage })

// finally
const trailing = pendingContext
pendingContext = undefined
if (trailing) {
  await runExtraction({ context: trailing.context, isTrailingRun: true })
}

    语义：重入时仅保留最新上下文；当前轮结束后补跑 trailing，避免并发风暴。

    5)守卫与决策矩阵（全链）

    层级 Guard 动作 终态
    注入层 auto memory disabled loadMemoryPrompt -> null 无 memory 注入但主链继续
    注入层 TEAMMEM enabled + cohort hit ensure dir + combined prompt auto+team 策略注入
    Session 抽取 querySource !== repl_main_thread 直接 return 子线程不抽取
    Session 抽取 gate disabled 直接 return（可打点） 静默降级
    Session 抽取 shouldExtractMemory=false 不触发 fork 等待下一阈值点
    Session 权限 非 Edit(memoryPath) deny fail-closed
    长期抽取 inProgress=true stash 为 pendingContext coalesced
    长期抽取 direct write detected skip fork + 推进 cursor 避免重复抽取
    compact 联动 session memory compaction 成功 reset summarized id + cleanup 跳过 legacy compact
    compact 联动 session memory compaction 失败 fallback compactConversation 旧路径继续

    6)失败、恢复与降级（全链）

    6.1 注入失败链：目录不可达/关闭场景

    loadMemoryPrompt 在禁用时直接 null，并记录 tengu_memdir_disabled；不会阻断 query 主链。

    6.2 抽取等待链：+ 双保险

    waitForSessionMemoryExtraction() 不是无限阻塞：

    • 抽取年龄 > stale 阈值（60s）则不再等待；
    • 总等待 > timeout（15s）则继续主流程。

    这保证“后台抽取异常不挟持前台交互”。

    6.3 抽取失败链：/生命周期收敛

    manuallyExtractSessionMemory 在 finally 中 markExtractionCompleted()；自动路径成功末尾也会 completed，避免“永远 in-progress 幻象”。

    6.4 长期抽取失败链：-，不上抛主链

    runExtraction catch 仅日志与埋点（tengu_extract_memories_error），不中断 stop 后续逻辑。

    6.5 写权限失败链：

    createMemoryFileCanUseTool 明确只允许 Edit 目标 memory 文件；其它工具或其它路径一律 deny，防止子 agent 越界。

    7)不变量（跨文件强约束）

    1. memory 功能禁用时必须退化为“无注入”，不得报错阻断 query。
    2. Session 抽取仅允许主 REPL 线程触发，子 agent 不得并入该路径。
    3. 抽取触发必须同时尊重 token/tool-call/turn-break 语义阈值。
    4. memory 写入权限必须收敛到目标文件级（Edit(memoryPath)）。
    5. lastMemoryMessageUuid 只能在成功或显式 skip（direct write）后推进。
    6. in-progress 抽取重入必须 coalesce，不能并发重复 fork。
    7. trailing run 只能消费“新追加区间”，不能重扫全量历史。
    8. session memory/compact 联动后需重置 summarized cursor，防止悬挂 UUID。
    9. 记忆内容是“历史上下文提示”，不是当前代码真值；用户行动前需回读源码确认。

    8)跨模块契约

    • 对 query.ts：memory 是附属能力，失败不击穿主回合状态机。
    • 对 compact（03）：autoCompactIfNeeded 可先走 session-memory compact，但必须保持可回退至 legacy compact。
    • 对 hooks（06/01）：extractMemories 常在 stop 阶段触发，但返回语义必须是“可丢失增强”，不是“硬阻断治理”。
    • 对 Tool 执行层（01-04）：memory fork 子 agent 依赖统一权限与工具事务语义，不自建旁路执行协议。

    9)工程约束与演进指引

    修改 02 模块时优先自检三问：

    1. 这个改动会不会让“记忆失败”影响主对话可用性？
    2. 这个改动会不会放宽 memory 子 agent 文件权限边界？
    3. 这个改动会不会导致 cursor 推进与真实写入不一致？

    若任一答案是“可能”，至少补：

    • 明确 gate 与 fallback 分支顺序；
    • 明确成功/失败时 cursor 与 in-progress 的生命周期；
    • 明确 telemetry 事件以支持线上失稳定位。

    建议回归场景：

    • auto memory disabled + 正常对话；
    • session extraction 命中阈值与未命中阈值；
    • 抽取中重入触发 coalesced + trailing；
    • 目录可读不可写/写权限拒绝；
    • session memory compaction 成功与 fallback legacy compact。
