    记忆系统：、失败模式与可观测性（深潜审计版）

    1)范围与证据边界

    本页聚焦 02 模块全链门控与观测，不展开算法细节。证据范围：

    • src/memdir/memdir.ts
    • src/services/SessionMemory/sessionMemory.ts
    • src/services/SessionMemory/sessionMemoryUtils.ts
    • src/services/extractMemories/extractMemories.ts
    • src/query/stopHooks.ts
    • src/cli/print.ts

    不覆盖：

    • prompt 注入文本模板细节（01）；
    • session 阈值决策与执行细节（02）；
    • 写权限与 freshness 细节（03）。

    2)核心论点

    02 模块稳定性的关键不是“错误少”，而是：

    1. 门控顺序可解释（为什么没触发）；
    2. 失败语义可降级（触发失败不拖垮主链）；
    3. 后台任务可收敛（结束前有 drain 机制）；
    4. 事件可观测（能区分 disabled / skipped / failed / succeeded）。

    3)运行时状态所有权

    状态类别 所有者 关键字段/函数 说明
    注入 gate 状态 memdir.ts isAutoMemoryEnabled + feature flags 控制读侧注入
    Session gate 状态 sessionMemory.ts isSessionMemoryGateEnabled + once-log flag 控制 session 抽取启停
    extract gate 状态 extractMemories.ts tengu_passport_quail + isAutoMemoryEnabled + remote mode 控制长期抽取启停
    抽取在途状态 extractMemories.ts inFlightExtractions, inProgress, pendingContext 控制 coalesce/drain
    停止阶段触发点 stopHooks.ts executeExtractMemories(...) fire-and-forget 回合末异步触发
    结束收敛点 print.ts drainPendingExtraction() 响应后、进程收尾前排空

    4)端到端流程

    4.1 触发后台抽取

    // src/query/stopHooks.ts
if (
  feature('EXTRACT_MEMORIES') &&
  !toolUseContext.agentId &&
  isExtractModeActive()
) {
  void extractMemoriesModule!.executeExtractMemories(
    stopHookContext,
    toolUseContext.appendSystemMessage,
  )
}

    语义：只在主线程、extract mode 打开时 fire-and-forget 触发。

    4.2 多重门控

    // src/services/extractMemories/extractMemories.ts
if (context.toolUseContext.agentId) return
if (!getFeatureValue_CACHED_MAY_BE_STALE('tengu_passport_quail', false)) return
if (!isAutoMemoryEnabled()) return
if (getIsRemoteMode()) return

if (inProgress) {
  pendingContext = { context, appendSystemMessage }
  return
}

await runExtraction({ context, appendSystemMessage })

    语义：门控顺序清晰，重入时 coalesce。

    4.3 响应后 收敛

    print.ts 在响应 flush 后调用 drainPendingExtraction()，给 in-flight 抽取一个 soft timeout 收尾窗口。

    5)守卫与决策矩阵

    层级 Guard 动作 结果
    注入层 !isAutoMemoryEnabled() 返回 null 无 memory 注入
    Session 抽取层 gate 关闭 return + 单次埋点 静默跳过
    extract 入口层 subagent/remote/flag off return 不启动后台抽取
    extract 并发层 inProgress=true pendingContext=latest coalesced
    extract 执行层 runExtraction 抛错 记录 error event 主链继续
    stop hooks 层 hook 自身异常 warning system message 不 preventContinuation
    结束收敛层 in-flight 未结束 drain + timeout 降低进程退出丢任务概率

    6)失败、恢复与降级

    6.1-失败链（可解释跳过）

    Session 与 extract 都有 gate-disabled 事件（并带 once-log 防刷屏），可区分“没触发”与“触发失败”。

    6.2 执行失败链（-）

    extract 失败只记录 tengu_extract_memories_error，不影响 query stop 决策。

    6.3 异常链（治理降级）

    handleStopHooks catch 后发 warning 并返回 { preventContinuation: false }，避免治理路径击穿主链。

    6.4 收尾恢复链（）

    drainPendingExtraction(timeout) 在输出后收敛后台任务，减少“响应完成后进程快速退出导致抽取中断”概率。

    6.5 重入恢复链（）

    在 in-progress 期间只保留最新上下文，当前 run 完成后 trailing 补跑，防止重复提取风暴。

    7)不变量

    1. memory 系统失效不能导致 query 主链失效。
    2. gate 判定必须先于 forked 抽取调用。
    3. in-progress 抽取重入必须 coalesced，不能并发 N 路重复执行。
    4. stopHooks 对 extractMemories 仅 fire-and-forget，不等待其完成再决定 continuation。
    5. 任何 stop hook 异常都应降级为 warning，不得静默吞错或硬终止。
    6. 结束阶段必须有 drain 机制处理在途抽取。
    7. telemetry 需区分 disabled / coalesced / error / success，避免黑盒化。
    8. 子 agent 不得触发主会话 memory 提炼流程。

    8)跨模块契约

    • 对 01（query/stopHooks）：memory 提炼必须服从 stopHooks 的“不可劫持主链”契约。
    • 对 03（compact）：compact 可利用 session memory，但不依赖 extractMemories 完成才可推进。
    • 对 CLI 输出层（print）：memory 后台任务必须在退出前有机会 drain。
    • 对 observability：事件命名与字段需可追踪门控序列与失败阶段。

    9)工程约束与演进指引

    新增 gate 或埋点时，至少保证：

    1. 事件语义一一对应（disabled/coalesced/error/success）；
    2. once-log 场景不会丢失关键首次信号；
    3. fire-and-forget 路径有对应 drain 保障；
    4. 异常处理不会改变 stopHook 的 preventContinuation 逻辑。

    建议回归：

    • gate 全关；
    • gate 开启但 remote mode；
    • inProgress 下多次 stop 连续触发；
    • runExtraction 抛错；
    • stopHooks 抛错；
    • print 收尾 drain 超时。
